## 해본 것

세션을 쪼갠 순서 그대로.

| 칸 | 내용 | 새 개념 |
|---|---|---|
| **1-A** | React 0줄. 주소창에 API URL을 직접 쳐서 응답을 본다 | 요청 = URL 하나 |

## 막힌 자리 (다음 세션 난이도의 근거)

홍이 말한 것: *"버튼을 작성하는 것까지는 좋았고, `useState`를 찾아보는 과정과 `fetch` 사용이 어려웠다."*

실제로 시간을 잡아먹은 건 개념이 아니라 **주변부**였다.

1. **`button`이 HTML인지 React인지** — 어디서 찾아야 하는지 몰라 헤맴 (→ 소문자/대문자 규칙, Elements 탭 확인법으로 정리)
2. **`return`을 `<>` 안에 넣어 화면이 빔** — 에러가 안 나서 단서가 없었다
3. **`setState`라는 이름을 호출** — `useState`가 돌려주는 두 이름을 내가 짓는다는 걸 몰랐다
4. **`${ }`와 `{ }`를 섞음** — JSX 중괄호와 템플릿 리터럴을 같은 것으로 봄
5. **`process.env`** — Vite는 `import.meta.env`
6. **파라미터 이름 누락** — `?a=값=값=값`. 질의문자열 구조를 몰랐다

**2·3·4·6은 React 문제가 아니라 JS/웹 기초 문제다.**

## 규칙 변경 — 링크는 에이전트가 준다 (2026-09-08 홍 제안)

기존 사다리 규칙은 *"에이전트는 로드맵과 찾는 법만"*이었는데, 이번 세션에서 **그게 난이도를 엉뚱한 데서 올렸다.** 배울 것은 `useState`·`fetch`인데 시간을 쓴 건 "어느 문서를 봐야 하나"였다.

→ **새 개념이 나오면 정확한 문서 페이지 링크를 에이전트가 먼저 붙인다.** 「찾는 법」은 홍이 이미 찾을 줄 아는 것에만 남긴다. 코드를 홍이 전부 타이핑하는 원칙은 그대로다.

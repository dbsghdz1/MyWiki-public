## 왜 헷갈리는가 (가설)

**세 축이 겹쳐 보이기 때문**으로 보인다. 실제로는 독립적인 축인데 대화에서 섞여 나왔다.

| 축 | 갈림 |
|---|---|
| JS 타입 | `number` / `bigint` |
| 값의 성격 | 정수 / 소수 |
| 쓰임 | 돈을 깎는다 / 화면에 그린다 |

특히 **"소수인데 `bigint`"**(코인 수량을 10⁸ 곱해 정수로)가 낯선 지점으로 보인다. 소수를 다루는 방법이 "`number`로 그냥 쓴다"와 "단위를 쪼개 정수로 만든다" 둘인데, 후자를 처음 만났다.

## 할 실험 (예측 → 실행 → 대조)

각각 **먼저 답을 적고** 돌린다. 예측이 틀린 자리가 헷갈리는 자리다.

```js
BigInt(0.5)              // ?
BigInt("0.5")            // ?
1n + 1                   // ?
1n < 2                   // ?
0.1 + 0.2 === 0.3        // ?
7n / 2n                  // ?
Number.MAX_SAFE_INTEGER + 2   // ?
(0.001 * 1e8)            // ?  ← 수량 스케일링이 number로도 되나
```

마지막 줄이 이 세션의 핵심 질문이다 — **왜 굳이 정수로 스케일링하는가**를 확인한다.

# 고차함수와 배열 메서드

함수를 인자로 받거나 돌려주는 함수가 고차함수다. 짧은 코드가 읽기 쉬운 건 짧아서가 아니라 **부품이 적어서**다.

## 핵심 정리

**고차함수는 함수를 인자로 받거나 함수를 돌려주는 함수다.**

```js
[1,2,3].map(x => x * 2)   // map은 고차함수 — 함수를 받는다
"1.5".split('.')          // 문자열을 받는다 → 그냥 메서드
"5".padEnd(8, '0')        // 숫자·문자열을 받는다 → 그냥 메서드
```

`map`·`filter`·`reduce`·`sort`·`forEach`가 고차함수고, `split`·`padEnd`·`slice`는 아니다. 구분이 중요한 이유는 **가독성 문제의 성격이 다르기 때문**이다 — 고차함수는 콜백을 읽어야 하지만 일반 메서드는 읽을 콜백이 없다.

**판단 기준: 무엇을(what) 말하는가, 어떻게(how)를 늘어놓는가.**

```js
// how — 절차를 나열한다. 맞는지 알려면 머릿속으로 실행해야 한다
while (count < scale) { s += '0'; count += 1; }

// what — 의도가 이름에 있다
s.padEnd(scale, '0')
```

짧아서 좋은 게 아니라 **부품이 적어서** 좋다. 위 `while` 버전에는 실제로 버그가 둘 있었다(무한 루프 — `count`를 안 늘림 / `count` 시작값을 0으로 둬서 이미 들어온 소수부 자릿수를 무시). `padEnd`에는 그 버그가 들어갈 자리가 없다.

**반대로 체인이 길어지면 읽기 나빠진다.**

```js
data.filter(x => x.a).map(x => x.b).reduce((s, x) => s + x.c, 0)
```

세 단계를 한 줄에 밀어넣으면 각 단계가 무엇을 만드는지 안 보인다. 중간에 이름을 붙여 끊는 게 낫다. `reduce`에 복잡한 누적기가 들어갈 때도 `for` 루프가 더 명확할 수 있다 — **억지로 함수형으로 쓰는 것이 손해인 경우가 있다.**

**남는 함정**: 짧은 코드는 그 어휘를 아는 사람에게만 읽기 쉽다. 다만 `split`·`padEnd`·`map` 정도는 JS에서 모두가 아는 어휘라 익혀두는 쪽이 이득이다.

### 2026-11-27 — 내 자산 화면에서 `map`, `join`, `find` (다시 볼 것)

- 맥락: [MyCryptoDiary](../../../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/MyCryptoDiary/README.md) 내 자산 화면 5-1단계. DB의 보유 줄(`holdings`)마다 업비트 현재가를 붙이는 코드에서 세 번 막혔다. 홍이 「나중에 다시 볼게」로 기록을 요청했다.
- 막힌 지점과 원인:
  1. `holdings.map((holding) => { holding.market; })`: 화살표 뒤에 중괄호를 쓰면 `return`을 직접 써야 값이 나간다. 결과가 `[undefined, undefined]`가 되고 `join(',')`은 `','`가 된다. ESLint `no-unused-expressions` 경고가 이것을 가리켰다. 고치는 법: `return holding.market` 또는 중괄호 없이 `(holding) => holding.market`.
  2. `prices[0].trade_price`: 업비트 응답 배열은 보낸 순서를 보장하지 않으니 위치로 짝을 맞추면 모든 줄에 첫 가격이 찍힌다.
  3. `prices.find((price) => price.market === holdingMarket)`를 `map` 바깥에 두고 이어 붙인 글자 `'KRW-BTC,KRW-ETH'`와 비교했다. 코인이 둘 이상이면 항상 `undefined`. 홍 요청으로 에이전트가 고쳤다.
- 최종 모양: `holdings.map((holding) => { const ticker = prices.find((price) => price.market === holding.market); ... ticker?.trade_price })`
- 다시 볼 때 읽는 법:
  - `find(함수)`: 원소를 앞에서부터 함수에 넣어 보고 `true`가 나온 **첫 원소**를 준다. 없으면 `undefined`.
  - `(price) => price.market === holding.market`: 넘기는 함수. 중괄호가 없으니 오른쪽 비교 결과가 그대로 돌려진다. Swift의 `prices.first { price in price.market == holding.market }`와 같다.
  - 짝을 맞추는 열쇠는 두 배열에 공통으로 있는 칸(`market`)이다. 「지금 이 줄」(`holding`)은 바깥 `map`이 준 것이라 `find`가 `map` 안에 있어야 쓸 수 있다.
  - `find`의 결과는 `undefined`일 수 있어 `TS18048`이 나고 `?.`로 푼다.
- 근거: `src/_pages/portfolio/ui/PortfolioPage.tsx`

### 2026-11-28 — `rows`로 모으고 `reduce`로 더하기 (홍이 손으로 다시 만든 것)

- 맥락: [MyCryptoDiary](../../../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/MyCryptoDiary/README.md) 내 자산 화면. 처음엔 줄마다 계산을 JSX의 `map` 안에서 하고 바로 그렸다. 요약 카드의 「총 평가금액」을 만들려다 막혔다.
- 막힌 이유: `map`에 넘긴 함수 안에서 만든 `evaluationAmount`는 그 함수 안에서만 산다. 코인이 셋이면 세 번 따로 만들어지고 줄을 그린 뒤 사라진다. 홍이 `<div>{evaluationAmount}</div>`를 `map` 위에 넣어 빨간 줄로 직접 확인했다.
- 바꾼 순서: `return` 위에서 `rows = holdings.map(→ 계산한 값 객체).filter(→ null 빼기)`로 먼저 모으고, 합계는 `rows.reduce((sum, row) => sum + row.evaluationAmount, 0n)`, JSX는 `rows.map`으로 그리기만 한다.
- 함께 배운 것:
  - `return`하지 않은 JSX는 버려진다. `map` 안에서 `return` 앞에 쓴 `<div>`는 화면에 안 나온다.
  - JSX 글자 안의 백틱과 `${}`는 그냥 글자다. 값을 쓰려면 `{ }`를 연다.
  - `reduce` 시작값은 `0n`. `0`이면 `bigint`와 섞여 에러.
  - 함수의 인자 이름은 함수 안의 이름이다. 전체 수익률을 위해 홍이 `calculateReturnRate`에 인자를 늘렸다가 호출 6곳이 깨졌고, 함수는 그대로 두고 `{ pnl: totalPnl, buyAmount: totalBuyAmount }`로 부르면 된다는 걸 확인했다.
  - `?.`는 빨간 줄을 없애지 않고 뒤로 미룬다. `account?.cashKrw + …`에서 `TS18048`. 위에서 `if (!account)`로 거르면 풀린다.

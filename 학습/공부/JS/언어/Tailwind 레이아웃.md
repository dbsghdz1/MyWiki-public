# Tailwind 레이아웃

`flex`는 부모에 붙여 자식을 나란히 놓게 하고, `flex-1`은 자식에 붙여 남는 자리를 차지하게 한다. 부모가 `flex`가 아니면 `flex-1`, `mt-auto`, `items-center`, `gap-*`은 아무 일도 하지 않는다.

## 핵심 정리

- **숫자는 4를 곱한 px다.** `w-58`은 232px, `h-16`은 64px, `p-6`은 24px이다. 시안의 수치를 4로 나누면 클래스 숫자가 나온다
- **`flex`와 `flex-1`은 붙는 곳이 다르다.** `flex`는 부모가 「내 자식을 한 줄로 놓는다」, `flex-1`은 자식이 「남는 자리는 내가 갖는다」
- **`flex-col`이면 방향이 세로로 바뀐다.** 이때 `flex-1`이 차지하는 남는 자리는 폭이 아니라 높이다
- **본문만 스크롤시키려면 두 가지가 필요하다.** 바깥 박스의 높이를 화면 높이로 정하고(`h-screen`), 스크롤될 박스에 `overflow-y-auto`를 붙인다. 높이가 정해지지 않으면 넘칠 일이 없어서 스크롤이 생기지 않고 화면 전체가 길어진다
- **부모 높이와 자식이 그 높이를 채우는지는 따로 정해진다.** 교차축 기본값이 늘리기(`stretch`)라 자식이 꽉 찬다. `items-*`는 부모가 자식 전체에, `self-*`는 자식 하나가 자기에게 건다
- **`h-screen`은 화면 높이, `h-full`은 부모 높이다.** 틀 안의 화면은 `h-full`로 부모가 준 만큼만 쓴다
- **`mt-auto`는 남는 세로 공간을 전부 위쪽 여백으로 쓴다.** 세로 `flex` 안에서 마지막 박스를 맨 아래로 보낼 때 쓴다
- 여백은 `px`가 좌우, `py`가 위아래, `p`가 네 방향이다. 경계선은 `border-r`처럼 방향을 정하고 색은 토큰 클래스(`border-line-soft`)로 따로 준다

화면 틀의 구조는 이렇다.

```
div  flex h-screen                    가로로 둘을 놓고 높이는 화면만큼
├ aside  w-58 flex flex-col           폭 232, 안은 세로로
│   └ 맨 아래 박스  mt-auto
└ div  flex-1 flex flex-col           남는 폭 전부, 안은 세로로
    ├ header  h-16                    높이 64
    └ main  flex-1 overflow-y-auto    남는 높이 전부, 여기만 스크롤
```

## 기록

### 2026-11-18: `w-58`은 58px가 아니고, `flex`와 `flex-1`은 무엇이 다른가
- 궁금했던 것: [MyCryptoDiary](../../../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/MyCryptoDiary/README.md)의 공통 화면 틀을 시안(메뉴 칸 232, 상단 바 64)대로 치다가 「`w-58`은 뭐지, 58px는 아닌 거지? `flex`랑 `flex-1` 차이는 뭐야」라고 물었다
- 예측: `w-58`이 58px는 아닐 것이라고 봤다. 맞았다. `flex`와 `flex-1`은 구분하지 못했다
- 파고든 길: 박스 두 개를 옆으로 놓는 것부터 시작해 아홉 단계로 하나씩 붙이며 화면을 봤다
- 알게 된 것:
  - Tailwind 숫자는 4를 곱한 px다
  - `flex`는 부모에, `flex-1`은 자식에 붙는다. 부모에 `flex`가 없으면 `flex-1`은 먹지 않는다
  - 오른쪽 박스 안을 `flex-col`로 바꾸면 `flex-1`이 차지하는 것이 남는 높이가 된다. 그래서 상단 바 아래 본문이 화면 끝까지 내려간다
- 근거: MyCryptoDiary `76207da`(뼈대), `b5aac92`(안쪽 여백), `src/widgets/app-shell/ui/AppShell.tsx`

### 2026-11-18: 본문이 길어지면 왜 메뉴까지 같이 스크롤되나
- 궁금했던 것: 본문에 긴 내용을 넣으면 화면 전체가 길어져 메뉴 칸과 상단 바도 같이 밀려 올라갔다
- 알게 된 것:
  - 바깥이 `h-screen`으로 높이가 정해져 있어도, 본문 박스에 `overflow-y-auto`가 없으면 내용이 박스 밖으로 넘쳐 나가고 페이지 전체가 스크롤된다
  - `overflow-y-auto`는 「넘치면 이 박스 안에서 스크롤해라」다. 스크롤을 누가 책임지는지를 박스 하나에 정해 주는 것이다
- 근거: MyCryptoDiary `42acc62`, 스크롤 동작은 화면에서 직접 확인

### 2026-11-18: 클래스를 붙였는데 화면이 그대로일 때, Tailwind 문제가 아니었다
- 궁금했던 것: `h-screen`을 붙였는데 「아무 변화가 없네」, 새로고침해도 그대로였다
- 파고든 길: 서버가 주는 CSS에는 `h-screen` 규칙이 있었고 브라우저에 적용된 스타일에는 없었다. 둘이 다르다는 데서 원인이 브라우저 쪽이라는 것이 갈렸다
- 알게 된 것:
  - 예전에 `localhost:3000`에서 띄웠던 다른 프로젝트(trip-live)가 서비스 워커를 등록해 두었고, 그것이 옛 CSS를 대신 돌려주고 있었다
  - 서비스 워커는 주소(출처)에 붙는다. `localhost:3000`을 쓰는 프로젝트는 전부 같은 출처라 서로의 서비스 워커를 물려받는다
  - 코드가 맞는데 화면만 다르면 「서버가 준 것」과 「브라우저가 가진 것」을 따로 본다
- 근거: 서비스 워커 등록 해제 뒤 바깥 박스 높이가 24에서 900으로 바뀜
- 새로 생긴 궁금증: 서비스 워커가 요청을 가로채는 방식은 따로 본 적이 없다

### 2026-11-21: 세 칸이 모두 꽉 차는 건 부모가 높아서일까
- 궁금했던 것: [MyCryptoDiary](../../../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/MyCryptoDiary/README.md) 거래소를 목록, 가격과 차트, 주문 폼 세 칸으로 나누며 주문 폼만 내용 높이로 줄여야 했다. 「세 칸이 꽉 찬 이유는 부모가 h-screen이라서 아니야?」라고 물었다
- 예측: 부모 높이 때문이라고 봤다. 반만 맞았다
- 파고든 길: 바깥 박스에 `items-start`를 붙이는 실험을 했다. 처음에는 세 자식에 붙여서 아무것도 줄지 않았고, 바깥 박스로 옮기자 세 칸이 모두 글자 높이로 줄었다
- 알게 된 것:
  - 부모가 얼마나 높은지(`h-full`)와 자식이 그 높이를 채우는지(교차축 정렬, 기본값 `stretch`)는 따로 정해진다. 부모가 높아도 정렬이 늘리기가 아니면 자식은 내용만큼이다
  - `items-*`는 붙인 박스의 안쪽(자식들)에 영향을 준다. 자식 하나만 바꾸려면 그 자식에 `self-*`를 붙인다. 주문 폼 칸에 `self-start`
  - `AppShell`의 `main` 안에서 `h-screen`을 쓰면 상단 바 64px와 위아래 여백 48px만큼 넘쳐 스크롤이 생긴다. `h-full`은 부모의 여백 안쪽 높이를 기준으로 한다
  - `flex-1`은 주축을 따른다. 바깥(가로)에서는 가운데 칸이 남는 폭을, 가운데 칸(`flex-col`) 안에서는 차트 카드가 남는 높이를 가져간다
  - 칸 사이 간격은 각 칸의 margin이 아니라 부모의 `gap-4`가 맡는다
  - 모르는 클래스는 오류 없이 무시된다. `glas` 오타로 카드 하나만 배경이 빠졌다
- 근거: MyCryptoDiary `33549f1`, `src/_pages/exchange/ui/ExchangePage.tsx`

# 뮤테이션과 낙관적 업데이트

읽기가 [[학습/공부/JS/서버 상태와 TanStack Query|서버 상태와 TanStack Query]]라면, 이 노트는 **쓰기**다 — 서버를 바꾸는 요청에서 화면을 언제 바꿀 것인가.

## 학습 계획

**미션:** 서버에 쓰는 요청에서 **화면을 먼저 바꾸고 실패하면 되돌리는** 처리를 직접 판단해 넣을 수 있다.
할 수 있게 되는 것 — ① [[프로젝트/개인/약국맵/README|약국맵]] 제보 버튼에서 낙관적 업데이트를 **없이/있이** 둘 다 만들고 체감 차이를 말한다 ② **캐시를 건드리는 방식과 안 건드리는 방식** 중 하나를 고르고 그 이유를 댄다 ③ `cancelQueries`를 **빼면 무슨 일이 나는지** 재현 결과로 설명한다. 범위 밖 — 동시 mutation(TkDodo의 `isMutating`), 오프라인 큐.

- [ ] **Mutations** — `useMutation`의 상태 4개와 `mutate`, 부수효과 콜백이 언제 불리는지. 완료 기준: 버튼 하나를 `useMutation`으로 붙이고 상태를 화면에 드러낸다
- [ ] **Optimistic Updates — 두 방식** — `variables`로 UI만 그리는 것과 `onMutate`로 캐시를 고치는 것. 완료 기준: 내 제보 버튼이 어느 쪽이어야 하는지 이유와 함께 고른다
- [ ] **롤백과 `cancelQueries`** — 스냅샷을 어디에 두고 어떻게 되돌리는지, 취소가 없으면 무엇이 덮이는지. 완료 기준: 깜빡임을 **재현**하고 원인을 말한다
- [ ] 사다리 8 — 제보 버튼에 실제로 적용 ([[프로젝트/개인/약국맵/학습 로드맵|야생학습]] 프론트 사다리 8번)

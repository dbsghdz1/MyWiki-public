# 데이터베이스

관계형 DB가 안에서 어떻게 동작하는가 — 인덱스(B+Tree), 트랜잭션과 격리 수준, 실행 계획, 정규화. 소마 백엔드(Spring Boot + RDB)의 쿼리·스키마 결정을 근거 있게 하는 것이 목표. 백엔드 경험을 풀스택으로 넓히는 전략(계획 우선순위)과 직결.

## 핵심 정리

강의 1획독(10-06) 뒤에 B+Tree 인덱스가 빠른 이유·인덱스가 안 타는 경우, 격리 수준 4단계와 이상 현상, 실행 계획 읽는 법을 채운다. 지금 있는 것은 프로젝트에서 먼저 부딪힌 넷이다.

- **「값이 없음」을 제약하려면 없음을 값으로 만들어야 한다.** MySQL UNIQUE는 NULL을 서로 다른 값으로 본다 → [[학습/공부/CS/데이터베이스/제약 조건|제약 조건]]
- **코드에만 있는 규칙은 CHECK로 DB에 내린다.** 값을 늘릴 때 마이그레이션이 필요해지는 것이 노리는 바다.
- **PK는 식별, FK는 존재 검사.** 「하나만」을 보장하는 것은 FK가 아니라 PK다 → [[학습/공부/CS/데이터베이스/키와 스키마 설계|키와 스키마 설계]]
- **동시성 판정은 코드가 아니라 DB에 맡긴다.** `INSERT ... ON CONFLICT DO NOTHING → SELECT`.

# 제약 조건 — UNIQUE와 CHECK

**「값이 없음」을 제약의 대상으로 삼으려면 없음을 값으로 만들어야 하고, 코드에만 있는 규칙은 CHECK로 DB에 내린다.** (2026-09-16 [[학습/공부/CS/데이터베이스/데이터베이스|데이터베이스]]에서 분리)

## 핵심 정리

- **MySQL의 UNIQUE는 NULL 중복을 막지 못한다.** `NULL = NULL`이 참이 아닌 것의 연장이다. 우회는 **생성 컬럼**(`IFNULL(col,'*') STORED`)에 UNIQUE를 거는 것 — `STORED`여야 인덱스가 걸린다.
- **CHECK는 INSERT·UPDATE·REPLACE·LOAD DATA에서 평가**되고, `NOT ENFORCED`면 있어도 강제되지 않는다. 데이터가 있는 테이블에도 나중에 걸 수 있고, ALTER가 성공했다는 것 자체가 기존 데이터 검증이다.
- **대가는 값을 늘릴 때 마이그레이션이 필요해지는 것** — 부작용이 아니라 노리는 바다. 「코드(enum)와 DB가 같이 바뀌어야 한다」를 스키마로 못박는 것.

## 기록

### 2026-08-16 — MySQL의 UNIQUE는 NULL 중복을 막지 못한다

- 맥락: 보험찾개냥 SSH-310 룰 테이블. `document_rule`에 보험사별 룰과 **폴백 룰**(모르는 보험사용)을 같은 테이블에 두면서, 폴백은 `insurance_company_code`를 NULL로 뒀다.
- 배운 것:
  - `UNIQUE(insurance_company_code, claim_type)`를 걸어도 **폴백 행은 몇 개든 들어간다.** MySQL의 UNIQUE 인덱스는 NULL을 서로 다른 값으로 취급하기 때문이다 — SQL에서 `NULL = NULL`이 참이 아닌 것의 연장이다.
  - 우회는 **생성 컬럼(generated column)에 UNIQUE를 거는 것**이다. `company_key VARCHAR(30) AS (IFNULL(insurance_company_code,'*')) STORED`처럼 NULL을 실제 값으로 치환한 컬럼을 만들고 거기에 제약을 건다. `STORED`여야 인덱스를 걸 수 있다.
  - 즉 **"값이 없음"을 제약의 대상으로 삼으려면 없음을 값으로 만들어야 한다.**
- 근거: `Server/src/main/resources/db/migration/V2__create_document_rule.sql`, 커밋 `8957a3e`. `DocumentRuleSeedTest`가 중복 INSERT에 `DuplicateKeyException`이 나는지로 확인한다.

### 2026-08-18 — CHECK 제약으로 "코드에만 있는 규칙"을 DB에 내리기

- 맥락: 같은 프로젝트 SSH-293. `claim_type`·`provided_by`·`requirement`가 애플리케이션에선 enum인데 DB에선 그냥 `VARCHAR`였다. 운영자가 SQL로 오타 섞인 값을 넣으면 조회가 터지는 구조였다.
- 배운 것:
  - MySQL은 `CHECK` 제약을 **INSERT·UPDATE·REPLACE·LOAD DATA에서 평가**하고 FALSE면 에러를 낸다. `NOT ENFORCED`로 만들어 두는 것도 가능하니, 있다고 다 강제되는 건 아니다.
  - `ALTER TABLE ... ADD CONSTRAINT ck_x CHECK (col IN ('A','B'))` 형태로 **이미 데이터가 있는 테이블에도 나중에 걸 수 있다.** 기존 행이 위반하면 ALTER가 실패하므로, 성공했다는 것 자체가 기존 데이터 검증이 된다.
  - 대가는 **값을 늘릴 때 마이그레이션이 필요해진다**는 것이다. 이건 부작용이 아니라 노리는 바다 — "코드(enum)와 DB가 같이 바뀌어야 한다"를 스키마로 못박는 것.
  - 방어를 **읽을 때가 아니라 쓸 때** 두는 판단은 [[학습/공부/백엔드/JPA와 Spring Data|JPA와 Spring Data]]에 적었다.
- 근거: `V3__add_document_rule_enum_check.sql`, 커밋 `0cdeacf`. 로컬·CI 양쪽에서 기존 43룰·276항목에 걸리는 행 없이 적용됐다.

# TCP 연결의 상태

`netstat`이 보여주는 건 **지금 어떤 상태냐**이고, `tcpdump`가 보여주는 건 **무엇이 오갔나**다. 둘을 같은 것으로 보면 계속 꼬인다.

## 핵심 정리

- **`netstat`의 줄 수와 3-way handshake는 아무 상관이 없다.** 숫자 3이 겹친 우연이다. 핸드셰이크는 **연결을 맺는 찰나에 패킷 3개**가 오가고 끝나서 `ESTABLISHED`가 되므로, `netstat`에는 이미 안 보인다.
- **`tcpdump`의 `.`은 ACK 비트**다. `[S]`=SYN · `[S.]`=SYN+ACK · `[.]`=ACK · `[F.]`=FIN+ACK · `[R.]`=RST+ACK.
- **맺을 때 3번, 끊을 때 4번인 이유**: 맺을 때는 서버가 "알겠다(ACK)"와 "나도 열자(SYN)"를 `[S.]` **한 방에 합칠 수 있다.** 끊을 때는 "알겠다(ACK)"를 먼저 보내야 하는데 **서버가 아직 보낼 데이터가 남아 있을 수 있어서** 자기 `FIN`을 같이 못 붙인다. 그래서 따로 나간다.
- **`[S]`에 `[R.]`(RST)이 돌아오면 그 포트에 아무도 없다는 뜻**이다 = `Connection refused`. 핸드셰이크가 시작도 못 한 것이다.
- **`localhost`는 IPv6(`::1`)를 먼저 시도하고 실패하면 IPv4로 재시도**한다 — 그래서 실패 시 `[S]`/`[R.]` 쌍이 **두 번** 찍힌다.

## 기록

### 2026-09-17 — netstat 3줄이 3-way handshake인가?

- 궁금했던 것: [[학습/공부/CS/네트워크/학습 계획|N2]](49~52강) 세션. `nc -l 9999`로 연결을 만들고 `netstat`을 보니 줄이 3개라 **그게 3-way handshake인가** 싶었다. 앞 질문은 [[학습/공부/CS/네트워크/포트와 localhost|포트와 localhost]].
- 예측: netstat 3줄 = 3-way handshake. **틀렸다.**
- 파고든 길: `sudo tcpdump -i lo0 -n 'tcp port 9999'`를 켜두고 연결을 끊었다 다시 붙였다.
- 알게 된 것:
  - **3줄은 상태(LISTEN + 양 끝 ESTABLISHED)**이고 핸드셰이크는 **순간에 오가는 패킷**이다. 층이 다르다.
  - 실제로 잡힌 건 **4-way(종료)**였다 — `[F.]` → `[.]` → `[F.]` → `[.]`. **끊을 때 4번인 이유가 여기 눈으로 보인다.**
  - 그다음 붙을 때는 `[S]`에 **`[R.]`이 돌아왔다** — 서버(`nc -l`)를 이미 꺼둔 상태였다. RST는 "그 포트에 아무도 없다".
  - 그 실패가 **IPv6(`::1`) → IPv4(`127.0.0.1`) 순서로 두 번** 찍혔다.
- 근거: 실측 로그
  ```
  127.0.0.1.49608 > 127.0.0.1.9999: Flags [F.]   ← 4-way 시작
  127.0.0.1.9999  > 127.0.0.1.49608: Flags [.]
  127.0.0.1.9999  > 127.0.0.1.49608: Flags [F.]
  127.0.0.1.49608 > 127.0.0.1.9999: Flags [.]
  ::1.49623       > ::1.9999:        Flags [S]   ← IPv6 먼저
  ::1.9999        > ::1.49623:       Flags [R.]  ← 거부
  127.0.0.1.49624 > 127.0.0.1.9999:  Flags [S]   ← IPv4 재시도
  127.0.0.1.9999  > 127.0.0.1.49624: Flags [R.]
  ```
- 새로 생긴 궁금증: 정상 종료 뒤 `TIME_WAIT`은 왜 한동안 남아 있나? (50강 범위, 아직 실측 못 함)

## 막힌 것

- `TIME_WAIT`이 남는 이유와 지속 시간 — 이날은 서버를 먼저 꺼서 관측하지 못했다.

# OSI 7계층

네트워크 통신을 7개 계층으로 나눈 참조 모델. 실제 인터넷은 TCP/IP 4~5계층으로 돌아가지만, "이 문제가 어느 계층 문제인가"를 말하는 공용 언어로 쓰인다. [[학습/공부/CS/네트워크|네트워크]]의 출발점.

## 핵심 정리

### OSI 7계층 ↔ TCP/IP 4계층 대응표 (2026-08-21, 네트워크 강의 44강)

| OSI | TCP/IP 4계층 | 역할 | 대표 프로토콜 | PDU |
|---|---|---|---|---|
| 7 애플리케이션 | 애플리케이션 | 앱이 네트워크와 통신하게 해주는 프로토콜 집합 | HTTP, SMTP, FTP, SSH | 메시지 |
| 6 프레젠테이션 | 〃 | 데이터 인코딩/디코딩, 암호화 | — | 메시지 |
| 5 세션 | 〃 | 통신 세션 관리 | — | 메시지 |
| 4 전송 | 전송 | 데이터를 쪼개고 오류 없이 순서대로 전달 | TCP, UDP | 세그먼트(TCP) / 데이터그램(UDP) |
| 3 네트워크 | **인터넷** | 노드→노드로 패킷화해 목적지까지 전달, 주소·라우팅 | IP, ICMP, ARP | 패킷 |
| 2 데이터링크 | 링크 | MAC 주소 기반 인접 전달 + 오류 검출 | Ethernet | 프레임 (헤더 + FCS 트레일러) |
| 1 물리 | 〃 | 전기·광 신호로 실제 전송 | — | 비트 |

- **두 모델의 차이는 딱 세 가지다.** ① OSI가 애플리케이션 계층을 셋(애플리케이션·프레젠테이션·세션)으로 쪼갠다 ② OSI가 링크 계층을 데이터링크·물리로 쪼갠다 ③ TCP/IP의 "인터넷 계층"을 OSI는 "네트워크 계층"이라 부른다. 나머지는 같은 것을 다르게 자른 것뿐이다.
- **표의 세로 순서 = 캡슐화 순서다.** 내려갈수록 헤더가 하나씩 더 붙고(메시지→세그먼트→패킷→프레임→비트), 수신 측에서는 역순으로 벗겨진다. **트레일러가 붙는 건 데이터링크 계층뿐**(FCS).
- **PDU 이름을 정확히 부르는 실익**: "프레임 문제"라고 말하는 순간 MAC 주소와 FCS를, "패킷 문제"라고 말하는 순간 IP 헤더를 열어보게 된다. 전부 "패킷"이라 부르면 이 지시가 사라진다.
### 왜 모델이 두 개인가 (역사)

- **TCP/IP는 실물이 먼저였다** — 1970년대에 개발돼 1983년 ARPANET이 전면 전환했다. **OSI는 1984년 ISO 7498(= ITU-T X.200)로 나온 국제 표준안**이다. 표준 경쟁에서 단순하고 이미 동작하던 TCP/IP가 이겼고, **OSI는 "말하기 위한 언어"로만 남았다.** 실제 코드에 OSI 5계층 같은 건 없다 — "3계층 문제 같은데요"가 통하는 것이 OSI의 유일한 실용성이다.
- **프레젠테이션(6)·세션(5)은 TCP/IP에 대응 계층이 없는 빈 칸이다.** 인코딩/암호화는 UTF-8·JSON 파싱·TLS가, 세션 유지·재개는 HTTP 쿠키·keep-alive가 한다 — 전부 애플리케이션 계층 프로토콜이 알아서 한다. **면접에서 "그럼 실무에선 어디 있나요"가 나오면 이렇게 답한다.**
- 암기법(1계층 물리부터): **P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way — Physical · Data link · Network · Transport · Session · Presentation · Application.

### 면접 답변 형태 (2026-08-22 정리)

- **Q. 캡슐화가 뭔가요?** 송신 측에서 상위 계층 데이터를 하위 계층이 자기 헤더로 감싸는 과정. 전송 계층은 포트가 담긴 TCP 헤더, 인터넷 계층은 IP 헤더, 링크 계층은 MAC이 담긴 프레임 헤더와 FCS 트레일러를 붙인다. 수신 측이 역순으로 벗기는 것이 비캡슐화.
- **Q. 왜 계층을 나누나요?** 각 계층이 자기 관심사만 보게 하려고. TCP는 신뢰성만, IP는 라우팅만. 그래서 한 계층을 통째로 바꿔도 다른 계층이 영향받지 않는다 — 와이파이→LTE로 바꾸면 링크 계층이 전부 교체되지만 HTTP 코드는 안 바뀐다.
- **Q. 세그먼트·패킷·프레임의 차이는?** 다른 물건이 아니라 같은 데이터가 껍질을 몇 겹 두른 상태. 계층마다 한 덩어리로 취급하는 단위가 달라 이름을 구분한다.
- **Q. IP 주소와 MAC 주소는 왜 둘 다 필요한가요?** 책임지는 거리가 다르다. IP는 최종 목적지까지라 경로 내내 안 바뀌고, MAC은 바로 다음 한 구간이라 홉마다 갈아끼워진다. 라우터가 IP로 다음 홉을 정한 뒤 그 홉의 MAC으로 프레임 헤더를 다시 쓴다.
- **Q. OSI와 TCP/IP의 차이는?** OSI가 애플리케이션을 셋, 링크를 둘로 쪼갠 것. 인터넷 계층을 네트워크 계층이라 부르는 건 이름 차이. 실제 인터넷은 TCP/IP로 동작하고 OSI는 참조 모델이며, 프레젠테이션·세션에 대응하는 실체는 없다.

- 아직 못 채운 것 — **계층별 네트워크 장치**(리피터·허브·브리지·스위치·라우터)는 [[학습/공부/CS/네트워크|네트워크]] W3-1(77~82강)에서 채운다.

## 기록

### 2026-08-21 — 44강으로 대응표를 채웠다

- 맥락: [[학습/공부/CS/네트워크|네트워크]] W1-2(44강 「TCP/IP 4계층 #1. 캡슐화, 비캡슐화, PDU, OSI 7계층」). 계획대로 별도 주차 없이 여기서 함께 다뤘다.
- 배운 것:
  - **OSI를 먼저 배우고 TCP/IP를 배우는 순서가 오히려 헷갈린다.** 실제 인터넷은 TCP/IP 4계층으로 돌고, OSI는 그것을 더 잘게 쪼갠 참조 모델이다 — 4계층을 기준으로 놓고 "애플리케이션이 셋, 링크가 둘로 갈라진 것"으로 외우는 게 맞다.
  - **프레젠테이션·세션 계층은 TCP/IP에는 대응하는 별도 계층이 없다.** 인코딩/암호화와 세션 관리는 실제로는 애플리케이션 계층 프로토콜이 알아서 한다. OSI에만 있는 칸이라는 걸 알고 있어야 면접에서 "그래서 실무에선 어디 있나요"에 답할 수 있다.
  - 각 계층의 PDU 이름이 곧 캡슐화 단계다 — 자세한 건 [[학습/공부/CS/네트워크#핵심 정리|네트워크 핵심 정리]].
- 근거: 교안 「CS - 네트워크」 pp.34~38 (OSI 7계층 절 p.38, PDU p.37)

### 2026-08-22 — "왜 모델이 두 개냐"가 역사로 풀렸다

- 맥락: 44강을 다시 설명받으며 OSI를 재정리 ([[학습/공부/CS/네트워크|네트워크]] 2026-08-22 기록과 같은 세션).
- 배운 것:
  - **OSI가 헷갈렸던 건 "표준인데 왜 안 쓰나"가 안 풀려서였다.** TCP/IP가 1970년대 개발·1983년 ARPANET 전면 전환한 실물, OSI가 1984년 표준안(ISO 7498 = ITU-T X.200)이고 **경쟁에서 실물이 이겼다**는 순서를 알면 끝난다. OSI는 규격이 아니라 어휘로 남은 것.
  - **5·6계층은 "TCP/IP에서 어디로 갔나"를 찾을 게 아니라 처음부터 실체가 없는 칸**이다. 그 일을 애플리케이션 프로토콜이 한다.
  - 위 `## 핵심 정리`에 면접 답변 5문항을 문장 형태로 박아뒀다 — W11(면접 예상 질문으로 핵심 정리 검증) 때 이 답변을 소리 내어 검증할 것.
- 근거: 교안 pp.34~38 + 44강 재정리

# 운영체제 학습 계획

[[학습/공부/CS/운영체제/운영체제|운영체제]] 폴더의 **세션 체크리스트**다. 슬롯·요일·주차 표의 정본은 공부 학습 계획, 세션 구조(55분: 복습 5 / 영상 30 / 명령 검증 10 / 말로 뱉기 10)의 정본은 공부 학습 계획, 세션 운영 규칙은 [[학습/공부/CS/네트워크/학습 계획|네트워크 학습 계획]]이다. 일간 루틴은 이 파일의 `### 영상 세션`·`### 영어 원문 학습 세션`에서 다음 미체크 항목을 뽑는다. (2026-09-16 [[학습/공부/CS/운영체제/운영체제|운영체제]]에서 분리)

## 학습 계획

**2026-09-13 재편 — 주 교재를 강의로 바꿨다.** 9·10월 1획독 목표에 따라 이 파일의 10월 자리는 인프런 [CS 지식의 정석](https://www.inflearn.com/course/%EA%B0%9C%EB%B0%9C%EC%9E%90-%EB%A9%B4%EC%A0%91-cs-%ED%8A%B9%EA%B0%95) **섹션 4 운영체제(190분)**를 **7 영상세션**(세션당 약 27분)에 배분한다. 세션 구조·시각·운영 규칙은 [[학습/공부/CS/네트워크/네트워크|네트워크]] `## 학습 계획`이 정본이다 — 오후 13:00~16:00 하루 3세션, 화~금 영상 + 토요일 영어 원문 학습(2026-09-23).

> [!important] 2026-09-13 — 아래 OSTEP W4~W11 계획은 **1획독 이후로 미뤘다** (폐기 아님)
> 이 파일에는 8월에 짠 OSTEP 8세션 계획이 10-27까지 미체크로 깔려 있었고, 이제 같은 자리에 강의 1획독이 들어온다. **두 축을 같은 슬롯에 겹쳐 두면 또 0이 된다** — 08-21 이후 CS 실행이 0회였던 것이 그 모양이었다(네트워크 파일 09-13 경고).
> **강의가 먼저인 이유**: 1획독의 목적은 OS 전체 지형을 한 번 훑어 전체 지형을 한 번 훑은 상태를 만드는 것이고, OSTEP 정독은 그 지형이 생긴 뒤에 깊이를 넣는 작업이다. 190분 강의로 지형을, 토요일 영어 원문 학습 세션 한 번으로 **OSTEP을 맛만** 본다.
> **살려 둔 것**: 영어 원문 세션의 OSTEP Ch.26~28(동시성)은 남는다(2026-09-23 판: 10-03). 동시성은 소마 Spring 서버의 스레드 모델과 직결이라 1획독 중에도 한 번은 원전으로 읽는다.

### 영상 세션 — 화~금 **13:00~16:00 (3시간 = 세션 3개)**, 세션당 영상 약 27분

**강 번호는 첫 세션에서 채운다.** 네트워크가 99강에서 끝나므로 섹션 4는 100강부터일 것이 유력하지만, 강의 목록을 열어 확인하기 전에는 적지 않는다 — 08-17에 네트워크를 38~99강으로 확정한 것과 같은 절차다.

- [ ] **O1** (09-25 금 ③): 섹션 4 시작 — 강의 목록에서 **강 번호·각 강 길이를 이 목록에 채우는 것부터.** 그다음 운영체제·컴퓨터 구조 기초
- [ ] **O2** (09-29 화 ①): 프로세스·스레드
- [ ] **O3** (09-29 화 ②): 메모리 계층·가상 메모리
- [ ] **O4** (09-29 화 ③): 페이징·세그멘테이션·페이지 교체
- [ ] **O5** (09-30 수 ①): CPU 스케줄링
- [ ] **O6** (09-30 수 ②): 동시성 — 임계 영역·뮤텍스·세마포어·데드락
- [ ] **O7** (09-30 수 ③): 섹션 4 종료 + `## 핵심 정리` 작성. 남으면 "Q." 강의로 자기 점검

**10-01(목)부터는** [[학습/공부/CS/데이터베이스/학습 계획|데이터베이스]] 섹션으로 넘어간다.

### 영어 원문 세션 — **10-03 토 오후 블록 뒷자리**

방식은 **에이전트가 한국어 요약을 먼저 주고 홍이 원문에서 근거 문장을 찾는 것**이다 (2026-09-17 변경, 정본은 공부 학습 계획).

- [ ] **10-03 토**: OSTEP Ch.26 «Concurrency and Threads» — https://pages.cs.wisc.edu/~remzi/OSTEP/threads-intro.pdf · Ch.27 «Thread API» — https://pages.cs.wisc.edu/~remzi/OSTEP/threads-api.pdf
  - **동시성 개론 두 장.** 강의 O6(동시성, 09-30) 뒤에 읽는다 — 스레드가 왜 필요한가와 API 모양만 잡는다. 원문 한 문장 인용
- [ ] **10-03 토 (이어서)**: OSTEP Ch.28 «Locks» — https://pages.cs.wisc.edu/~remzi/OSTEP/threads-locks.pdf
  - O6(09-30)에서 들은 임계 영역·뮤텍스를 원문으로 다시 본다. **소마 Spring 서버의 스레드 모델과 JS 이벤트 루프를 각각 한 줄로 연결**해 `## 기록`에. 원문 한 문장 인용

> [!note] 2026-09-17 — 10-17과 10-24의 순서를 바꿨다
> 09-13 판은 10-17 하나에 «Locks»를 넣었는데, 재배분으로 강의 동시성(O6)이 **10-20**으로 밀리면서 **원문이 강의보다 먼저 오게 됐다.** 개론(Ch.26~27)을 앞에, «Locks»를 O6 뒤인 10-24로 옮겼다. *2026-09-23 3세션제로 O6가 09-30으로 당겨져, 세 장 모두 강의(O6) 뒤인 10-03에 온다.*

- [ ] 세마포어·데드락 — OSTEP Ch.31~32
- [ ] 파일시스템·I/O — OSTEP Ch.36~40 (I/O Devices, Disks, File System Implementation)

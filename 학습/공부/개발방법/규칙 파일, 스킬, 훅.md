# 규칙 파일, 스킬, 훅

셋을 가르는 것은 **누가 실행하느냐**다. 규칙 파일과 스킬은 AI가 읽고 따르는 글이고, 훅은 정해진 순간에 시스템이 자동으로 돌리는 프로그램이다.

## 핵심 정리

| | 무엇인가 | 누가 지키나 | 이 볼트의 예 |
|---|---|---|---|
| **규칙 파일** | AI가 작업 전에 읽는 글 | AI가 읽고 따른다. 잊거나 틀릴 수 있다 | `AGENTS.md`, Claude 전역 `CLAUDE.md` |
| **스킬** | 특정 작업용 절차서 | 그 작업일 때만 AI가 불러 읽는다 | `wiki` 스킬 (「위키에 정리해줘」) |
| **훅** | 특정 순간에 자동으로 도는 프로그램 | 시스템이 실행한다. AI가 잊어도 돈다 | `.githooks/pre-commit` (커밋 직전 검사) |

- 비유: 규칙 파일은 사내 규정집, 스킬은 업무 매뉴얼, 훅은 출입문 보안 검색대다.
- **git 훅은 AI 기능이 아니라 git 기능이다.** 커밋하는 쪽이 Claude든, Codex든, Obsidian 플러그인이든 같은 검사를 받는다.
- Claude Code에도 따로 훅이 있다. 원리는 같고, 순간이 「AI가 명령을 실행하기 직전」 같은 것이다. 이 볼트에서는 AI가 파일을 한꺼번에 stage하려 하면 막는 훅이 있다.
- 지금까지 본 고르는 기준: **꼭 지켜져야 하고 판단이 필요 없으면 훅, 판단이 필요하면 규칙이나 스킬.**

## 기록

### 2026-10-17: 체크가 왜 GitHub에 안 올라갔고, 왜 규칙이 아니라 훅으로 고쳤나

- 궁금했던 것: 일간에서 체크한 CS 세션과 청소가 다음 날 계획에 또 들어왔다. 로컬 볼트 동기화 문제였다.
- 파고든 길: Obsidian Git 자동 커밋이 켜져 있는데도 체크가 GitHub에 없었다. 커밋 직전 훅을 손으로 돌려 보니 두 가지에 걸렸다. 일간 파일 빈 줄의 탭 한 글자(줄 끝 공백 검사)와, 다른 AI 세션이 log 중간에 끼운 기록(append-only 검사)이었다.
- 알게 된 것:
  - 자동 커밋은 볼트 전체를 한 커밋으로 올린다. 파일 하나만 검사에 걸려도 전부 막히고, 실패는 플러그인 알림으로만 잠깐 보인다.
  - 탭은 사람이 편집하다 들어가는 것이라 규칙 파일에 「탭 넣지 마」라고 써도 소용이 없다. 판단이 필요 없는 일이라 훅이 자동으로 지우게 했다.
  - log 중간 삽입은 훅에서 자동으로 고치지 않았다. 어디로 옮길지 판단이 필요해서다.
- 근거: `.githooks/pre-commit` 0) 단계, [MyWiki 구조 lint와 pre-commit 훅](../../../%EC%9E%91%EC%97%85%EB%85%B8%ED%8A%B8/%EB%8F%84%EA%B5%AC/MyWiki%20%EA%B5%AC%EC%A1%B0%20lint%EC%99%80%20pre-commit%20%ED%9B%85.md) 2026-10-17 항목

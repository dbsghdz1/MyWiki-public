# 공부

**내(홍)가 다시 읽고 이해를 쌓는 학습 노트 영역이다.** 판정 질문은 **"왜 그런지 궁금해서 파고들었나?"** — 그렇다면 여기에 쓴다. 좋은 노트 = **압축**된 것, 덮고 말할 수 있는 것. 길어서 다시 안 읽으면 실패다.

**2026-09-16 재편 — 폴더를 한 단계 더 나누고 큰 파일을 쪼갰다.** `CS/`는 `네트워크`·`운영체제`·`데이터베이스`·`자료구조`·`보안`·`컴퓨터구조`, `JS/`는 `언어`·`React`·`Next.js` 폴더로 나눴다. 세션 체크리스트는 각 폴더의 **`학습 계획.md`**, 개요·압축 요약은 폴더 이름과 같은 파일(`네트워크/네트워크.md`), 파고든 과정은 주제 노트의 `## 기록`이다. 슬롯·주차 표·결정 이력은 학습 계획으로 분리했다 — 이 README는 규칙과 목록만 든다.

**2026-08-30 재편**: 최상위 `공부/`가 [[학습/README|학습]] 아래 **`학습/공부/`**로 이동했다. 형제 영역으로 `학습/아카이빙/`(비활성 노트 보관)이 있다. 손으로 배우는 실습 세션 기록은 그 작업이 속한 프로젝트 폴더에 둔다.

**2026-08-28 분리**: AI가 작업하며 남기는 경험 노트(이미 밟은 지뢰, 비자명한 API 동작, 재현된 원인 — 내가 다시 읽지 않는 것)는 [[작업노트/README|작업노트]]로 분리했다. 판정 질문이 "이 프로젝트를 다시 만질 때 필요한가?"이면 그쪽이다. `_wiki/`가 외부 출처(Sources)를 종합한 지식이라면, 공부는 실제 작업·학습 경험에서 나온 1인칭 노트다.

## 원칙

1. **주제별 파일, 날짜별 항목 append.** 같은 주제로 배운 게 쌓이며 한 파일이 두꺼워지는 것이 목적이다. 날짜별 파일은 만들지 않는다.
2. **양방향 연결.** 공부 항목은 맥락이 된 프로젝트를 링크하고, 그 프로젝트 README의 `## 배운 것` 섹션은 공부 주제를 링크한다. 작업 기록 파일(`<주제> YYYY-MM-DD.md`)에도 `배운 것:` 한 줄로 공부 주제를 링크한다. 한쪽만 있으면 미완성이다.
    - **맥락이 프로젝트가 아닐 수 있다** (2026-08-22 추가). 볼트 운영·비용·인프라처럼 특정 프로젝트에 속하지 않는 주제는 `프로젝트/` 대신 그 맥락이 된 문서(`운영/…`, `금융/…`)를 링크한다. 억지로 프로젝트를 붙이지 않는다 — 근거가 약해질 뿐이다. 이때도 **상대 문서 쪽에 역링크를 남기는 의무는 그대로다.**
    - 비공개 영역(`운영`·`금융`·`계획`·`커리어`)을 맥락으로 링크할 때는 **금액·개인 사정을 공부 본문에 그대로 옮기지 않는다.** 필요하면 `<!-- private:start -->`로 감싼다 — 공부는 공개 영역이라 그대로 public 저장소로 나간다.
3. **작업에 닿아 있어야 한다.** 근거는 커밋·파일·재현한 현상·실제 결정이다. 작업과 무관한 일반론을 옮겨 적지 않는다.
4. **CS 주제는 유명 레퍼런스를 붙인다.** 자료구조·알고리즘, OS, 네트워크, DB, 언어 런타임·컴파일러, 분산 시스템, 보안 등 CS 주제 파일에는 `## 참고 자료`에 널리 인정되는 자료(교과서, 공식 문서, RFC, 대학 강의, 널리 인용되는 글) 2~4개를 **URL을 실제로 확인한 뒤** 첨부하고 `YYYY-MM-DD 확인`을 표기한다. 확인 못 한 링크는 넣지 않는다.
5. **내가 붙여넣은 링크는 정리 + 원전 보강까지가 기록이다** (2026-08-28 추가). 공부하다 찾은 블로그 글(주로 한국어)을 붙여넣으면 에이전트가 두 가지를 한다: ① 핵심 개념·규칙·예제를 주제 파일 본문에 **바로 읽을 수 있게 옮겨 적는다** — 링크만 남기면 다시 열어봐야 하므로 기록이 아니다. ② 같은 주제의 **공식 문서**와 **영어권에서 널리 인용되는 글**을 추가로 찾아 `## 참고 자료`에 함께 첨부한다 — 블로그는 2차 자료라 원전으로 교차 검증이 돼야 이해가 완성된다. 원 블로그 링크도 출처로 남기고, 모든 URL은 원칙 4와 동일하게 실제로 열어 확인 후 `YYYY-MM-DD 확인` 표기. 블로그 내용이 원전과 어긋나면 지우지 말고 그 차이를 명시한다.
6. **궁금증 사슬을 남긴다** (2026-09-14 추가). 한 궁금증을 파고들다 새로 생긴 궁금증을 `새로 생긴 궁금증:`에 적고, 그걸 파고든 노트가 생기면 서로 링크한다 — 무엇이 궁금해서 어디까지 따라갔는지가 노트 사이에 보이게 한다. 좋은 예: [[학습/공부/CS/네트워크/CORS와 동일 출처 정책|CORS와 동일 출처 정책]](예측이 틀림 → 헤더 확인 → POST면 OPTIONS가 생길지라는 다음 궁금증).
7. **`_wiki` 승격.** 한 주제가 외부 출처 여럿을 종합할 만큼 커지면 `_wiki/`에 주제 허브를 만들고 공부 파일에서 링크한다. 공부 파일은 그대로 남긴다.

## 파일 규칙

- 경로: **`학습/공부/<분야>/<주제>.md`**, `CS`·`JS`는 **`학습/공부/<분야>/<세부>/<주제>.md`** (2026-09-16 재편). 분야는 `CS` · `JS` · `백엔드` · `개발방법` 넷이고 (2026-08-28 분리로 Apple·AppStore·도구·Flutter는 [[작업노트/README|작업노트]] 소속), **아래 「주제 목록」의 절 이름과 폴더를 1:1로 맞춘다.** 주제명은 검색 가능한 명사구 (예: `HTTP 캐싱.md`).
- **세부 폴더는 파일 셋을 둘 수 있다** (2026-09-16): ① 폴더 이름과 같은 **개요 파일**(`네트워크/네트워크.md`) — 폴더 지도 + 한 줄씩의 압축 요약 + `## 막힌 것` + 폴더 전체 교재. ② **`학습 계획.md`** — 세션 체크리스트(`## 학습 계획` → `### 영상 세션` / `### 영어 원문 학습 세션`), 일간 루틴이 읽는 파일. ③ **주제 노트** — 궁금증 하나를 파고든 기록과 그 요약. **한 파일이 150줄을 넘으면 쪼갤 때다.** 개요 파일에는 `## 기록`을 쌓지 않는다.
- **어느 분야인지 애매하면 폴더를 새로 만들지 않는다.** 작업 경험 성격이면 [[작업노트/미분류|작업노트/미분류]]에 append하고, 내가 이해할 개념인데 분야가 애매하면 가장 가까운 분야에 둔다. 같은 성격이 3개 모이면 그때 분야를 만들고, 만들면 주제 목록에 절을 함께 추가한다.

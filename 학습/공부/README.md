# 공부

**내(홍)가 다시 읽고 이해를 쌓는 학습 노트 영역이다.** 판정 질문은 **"왜 그런지 궁금해서 파고들었나?"** — 그렇다면 여기에 쓴다. 좋은 노트 = **압축**된 것, 덮고 말할 수 있는 것. 길어서 다시 안 읽으면 실패다.

**2026-09-16 재편 — 폴더를 한 단계 더 나누고 큰 파일을 쪼갰다.** `CS/`는 `네트워크`·`운영체제`·`데이터베이스`·`자료구조`·`보안`·`컴퓨터구조`, `JS/`는 `언어`·`React`·`Next.js` 폴더로 나눴다. 세션 체크리스트는 각 폴더의 **`학습 계획.md`**, 개요·압축 요약은 폴더 이름과 같은 파일(`네트워크/네트워크.md`), 파고든 과정은 주제 노트의 `## 기록`이다. 슬롯·주차 표·결정 이력은 [[학습/공부/학습 계획|학습 계획]]으로 분리했다 — 이 README는 규칙과 목록만 든다.

**2026-08-30 재편**: 최상위 `공부/`가 [[학습/README|학습]] 아래 **`학습/공부/`**로 이동했다. 형제 영역으로 `학습/아카이빙/`(비활성 노트 보관)이 있다. 손으로 배우는 실습 세션 기록은 그 작업이 속한 프로젝트 폴더에 둔다.

**2026-08-28 분리**: AI가 작업하며 남기는 경험 노트(이미 밟은 지뢰, 비자명한 API 동작, 재현된 원인 — 내가 다시 읽지 않는 것)는 [[작업노트/README|작업노트]]로 분리했다. 판정 질문이 "이 프로젝트를 다시 만질 때 필요한가?"이면 그쪽이다. `_wiki/`가 외부 출처(Sources)를 종합한 지식이라면, 공부는 실제 작업·학습 경험에서 나온 1인칭 노트다.

## 원칙

1. **주제별 파일, 날짜별 항목 append.** 같은 주제로 배운 게 쌓이며 한 파일이 두꺼워지는 것이 목적이다. 날짜별 파일은 만들지 않는다.
2. **양방향 연결.** 공부 항목은 맥락이 된 프로젝트를 링크하고, 그 프로젝트 README의 `## 배운 것` 섹션은 공부 주제를 링크한다. 작업 기록 파일(`<주제> YYYY-MM-DD.md`)에도 `배운 것:` 한 줄로 공부 주제를 링크한다. 한쪽만 있으면 미완성이다.
    - **맥락이 프로젝트가 아닐 수 있다** (2026-08-22 추가). 볼트 운영·비용·인프라처럼 특정 프로젝트에 속하지 않는 주제는 `프로젝트/` 대신 그 맥락이 된 문서(`운영/…`, `금융/…`)를 링크한다. 억지로 프로젝트를 붙이지 않는다 — 근거가 약해질 뿐이다. 이때도 **상대 문서 쪽에 역링크를 남기는 의무는 그대로다.**

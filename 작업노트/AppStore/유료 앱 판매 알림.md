# 유료 앱 판매 알림

한 줄 요약 — **유료 다운로드 앱은 App Store Server Notifications가 오지 않는다**(IAP·구독 전용). "구매하면 Slack" 은 실시간이 불가능하고, ASC `salesReports`(일일)를 크론으로 당겨 **다음 날 아침 요약**으로 받는 것이 최선이다. Zappy(IAP)와 한능검(유료 앱)은 그래서 파이프라인이 다르다.

## 핵심 정리

- **두 파이프라인 비교**
  | | Zappy+ (비소모성 IAP ₩3,300) | 한능검 정복 (유료 다운로드 ₩6,600) |
  |---|---|---|
  | 소스 | [[작업노트/AppStore/App Store Server Notifications\|ASSN V2]] 웹훅 `ONE_TIME_CHARGE` | `GET /v1/salesReports` DAILY·SUMMARY·SALES |
  | 지연 | 구매 즉시(분 단위) | 해당일(PT) 마감 후 다음 날 — 크론 `0 22 * * *` UTC = 07:00 KST |
  | 파일 | `landing/api/appstore-webhook.js` | `landing/api/hangeom-sales.js` (같은 Zappy 랜딩 Vercel 프로젝트 `zappy-landing`에 동거) |
  | 인증 | `?token=WEBHOOK_TOKEN` | Vercel이 붙이는 `Authorization: Bearer $CRON_SECRET`, 수동은 `?token=WEBHOOK_TOKEN` |
- **salesReports 호출**: `filter[frequency]=DAILY&filter[reportDate]=YYYY-MM-DD&filter[reportSubType]=SUMMARY&filter[reportType]=SALES&filter[vendorNumber]=…`, `Accept: application/a-gzip` → gzip TSV. `vendorNumber`는 API로 못 얻고 ASC 웹 「지급 및 재무 보고서」에서 본다([[작업노트/AppStore/App Store Connect 분석 리포트 API|분석 리포트 API]]). JWT는 ASC 팀 키(fastlane `AuthKey.p8`)로 충분 — `kid`·`iss`·`aud: appstoreconnect-v1`, ES256 `ieee-p1363`.
- **벤더 전체에 그날 거래가 0이면 리포트 자체가 없어 404**가 온다 — 에러가 아니라 "0건"으로 처리해야 한다.
- **TSV 해석**: `Product Type Identifier` `1`·`1F`·`1T`·`1E*` = 앱 다운로드(무료 포함, 환불은 `Units` 음수), `7*` = 업데이트, `3*` = 재다운로드. **유료 판매는 `Customer Price > 0`으로 가른다** — 무료 시절 다운로드도 type 1 · 0.00으로 같은 행에 찍힌다(2026-09-01 실측). 앱 구분은 `SKU` 열(한능검은 `hangeom`). 매출은 `Customer Price`×`Units`(`Customer Currency`), 수익은 `Developer Proceeds`×`Units`(`Currency of Proceeds`).
- **Vercel Cron 운영**: `vercel.json`의 `crons`는 **프로덕션 배포 시점에 프로젝트에 등록**된다 — 등록 확인은 `GET https://api.vercel.com/v9/projects/<id>?teamId=<org>` 응답의 `crons.definitions`. Hobby 플랜은 일 1회 크론 허용. **수동 실행은 CLI/REST에 없고 대시보드 Settings → Cron Jobs → Run 뿐**(요청은 `GET`, UA `vercel-cron/1.0`, `CRON_SECRET` 헤더 자동 첨부) — 테스트는 Aside 브라우저로 눌렀다.
- **실패도 Slack으로 보낸다.** Zappy 웹훅이 4일간 404였던 전례([[작업노트/도구/Vercel 배포|Vercel 배포]])처럼 크론은 죽으면 조용히 사라지므로, catch 블록에서 `⚠️ 한능검 판매 리포트 실패 (날짜): 메시지`를 같은 웹훅으로 보낸다. 매일 07:00에 메시지가 **안 오는 것 자체가 장애 신호**다.

## 기록

### 2026-09-03 — 한능검 ₩6,600 판매 Slack 알림을 Zappy와 "똑같이" 하려다 구조가 다름을 확인, 크론으로 배포
- 맥락: [[프로젝트/개인/한능검/README|한능검]] 유료 전환(₩6,600, 09-03) 직후 홍 요청 "구매하면 내 슬랙으로 알림, Zappy처럼". 09-15 트립와이어(판매 10건 미만이면 IAP 전환) 판정에 이 숫자가 필요하다.
- 배운 것: 위 「핵심 정리」. Zappy 방식(ASSN 웹훅)은 유료 다운로드에 아예 발화하지 않아 복제가 불가능했고, 일일 판매 리포트 크론이 대안.
- 근거: Zappy 레포 커밋 `75c3b93`(`landing/api/hangeom-sales.js` + `landing/vercel.json`), 환경변수 7개(`ASC_KEY_ID`·`ASC_ISSUER_ID`·`ASC_PRIVATE_KEY`·`ASC_VENDOR_NUMBER`·`CRON_SECRET`·`SLACK_WEBHOOK_URL`·`WEBHOOK_TOKEN`)는 `zappy-landing` Production. 배포 후 `POST /api/hangeom-sales` → 401(404 아님), 프로젝트 API `crons.definitions`에 `/api/hangeom-sales 0 22 * * *` 등록 확인. 대시보드 Run → 23:37:32 KST `GET 200` 951ms, Slack `#70-밥벌이-재피`에 `📊 한능검 정복 2026-09-02(PT) 판매 0건 (무료 다운로드 8건)` 도착(Slack 검색 `ts 1788446253.579729`).
- 남은 것: 첫 유료 판매가 찍히면 `🎉 … 판매 N건 · 매출 ₩… · 수익 ₩…` 포맷을 실물로 확인. 지금은 무료 시절 다운로드(type 1 · 0.00)만 관측했다.

# 유료 앱 판매 알림

한 줄 요약 — **유료 다운로드 앱은 App Store Server Notifications가 오지 않는다**(IAP·구독 전용). "구매하면 Slack" 은 실시간이 불가능하고, ASC `salesReports`(일일)를 크론으로 당겨 **다음 날 아침 요약**으로 받는 것이 최선이다. Zappy(IAP)와 한능검(유료 앱)은 그래서 파이프라인이 다르다.

## 핵심 정리

- **두 파이프라인 비교**
  | | Zappy+ (비소모성 IAP ₩3,300) | 한능검 정복 (유료 다운로드 ₩6,600) |
  |---|---|---|
  | 소스 | [ASSN V2](App%20Store%20Server%20Notifications.md) 웹훅 `ONE_TIME_CHARGE` | `GET /v1/salesReports` DAILY·SUMMARY·SALES |
  | 지연 | 구매 즉시(분 단위) | 해당일(PT) 마감 후 다음 날 — 크론 `0 22 * * *` UTC = 07:00 KST |
  | 파일 | `landing/api/appstore-webhook.js` | `landing/api/hangeom-sales.js` (같은 Zappy 랜딩 Vercel 프로젝트 `zappy-landing`에 동거) |
  | 인증 | `?token=WEBHOOK_TOKEN` | Vercel이 붙이는 `Authorization: Bearer $CRON_SECRET`, 수동은 `?token=WEBHOOK_TOKEN` |
- **salesReports 호출**: `filter[frequency]=DAILY&filter[reportDate]=YYYY-MM-DD&filter[reportSubType]=SUMMARY&filter[reportType]=SALES&filter[vendorNumber]=…`, `Accept: application/a-gzip` → gzip TSV. `vendorNumber`는 API로 못 얻고 ASC 웹 「지급 및 재무 보고서」에서 본다([분석 리포트 API](App%20Store%20Connect%20%EB%B6%84%EC%84%9D%20%EB%A6%AC%ED%8F%AC%ED%8A%B8%20API.md)). JWT는 ASC 팀 키(fastlane `AuthKey.p8`)로 충분 — `kid`·`iss`·`aud: appstoreconnect-v1`, ES256 `ieee-p1363`.
- **벤더 전체에 그날 거래가 0이면 리포트 자체가 없어 404**가 온다 — 에러가 아니라 "0건"으로 처리해야 한다.
- **TSV 해석**: `Product Type Identifier` `1`·`1F`·`1T`·`1E*` = 앱 다운로드(무료 포함, 환불은 `Units` 음수), `7*` = 업데이트, `3*` = 재다운로드. **유료 판매는 `Customer Price > 0`으로 가른다** — 무료 시절 다운로드도 type 1 · 0.00으로 같은 행에 찍힌다(2026-09-01 실측). 앱 구분은 `SKU` 열(한능검은 `hangeom`). 매출은 `Customer Price`×`Units`(`Customer Currency`), 수익은 `Developer Proceeds`×`Units`(`Currency of Proceeds`).
- **Vercel Cron 운영**: `vercel.json`의 `crons`는 **프로덕션 배포 시점에 프로젝트에 등록**된다 — 등록 확인은 `GET https://api.vercel.com/v9/projects/<id>?teamId=<org>` 응답의 `crons.definitions`. Hobby 플랜은 일 1회 크론 허용. **수동 실행은 CLI/REST에 없고 대시보드 Settings → Cron Jobs → Run 뿐**(요청은 `GET`, UA `vercel-cron/1.0`, `CRON_SECRET` 헤더 자동 첨부) — 테스트는 Aside 브라우저로 눌렀다.
- **실패도 Slack으로 보낸다.** Zappy 웹훅이 4일간 404였던 전례([Vercel 배포](../%EB%8F%84%EA%B5%AC/Vercel%20%EB%B0%B0%ED%8F%AC.md))처럼 크론은 죽으면 조용히 사라지므로, catch 블록에서 `⚠️ 한능검 판매 리포트 실패 (날짜): 메시지`를 같은 웹훅으로 보낸다. 매일 07:00에 메시지가 **안 오는 것 자체가 장애 신호**다.

- **유료 앱을 무료+IAP로 바꾸면 이 파이프라인이 조용히 0을 보고한다.** 판매 리포트에서 IAP는 ① **자기 SKU**로 찍히고(앱 SKU가 아니다) ② `Product Type Identifier`가 **`IA*`**라 `"1"`로 시작하지 않는다. 앱 SKU + type "1" 필터를 그대로 두면 몇 건이 팔리든 「판매 0건 (무료 다운로드 N건)」만 온다 — **에러가 아니라 정상 메시지로 위장한 실패라 더 늦게 발견된다.**
- 부모 앱은 **`Parent Identifier` 열**(= 부모 앱의 SKU)이 가리킨다. IAP 행을 앱에 묶을 때 이걸 쓰고, 형태가 다를 때를 대비해 제품 ID 목록으로도 이중으로 잡는다.
- **역할을 나눠 두 파이프라인을 다 쓴다**: ASSN 웹훅 = 구매 즉시, 판매 리포트 크론 = 일일 합계·환불. 웹훅이 죽어도 다음 날 아침에 드러나는 이중 안전장치가 된다.
- **집계 로직은 함수로 빼서 테스트한다.** 매출이 0으로 잘못 보고되는 것은 알림이 아예 없는 것보다 나쁘다 — 있는 줄 알기 때문이다. 합성 TSV로 6가지(IAP·환불 분리·다른 앱 제외·업데이트 무시 등)를 고정해 뒀다(`landing/test/sales.test.js`).

## 기록

### 2026-09-03 — 한능검 ₩6,600 판매 Slack 알림을 Zappy와 "똑같이" 하려다 구조가 다름을 확인, 크론으로 배포
- 맥락: [한능검](../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/%ED%95%9C%EB%8A%A5%EA%B2%80/README.md) 유료 전환(₩6,600, 09-03) 직후 홍 요청 "구매하면 내 슬랙으로 알림, Zappy처럼". 09-15 트립와이어(판매 10건 미만이면 IAP 전환) 판정에 이 숫자가 필요하다.
- 배운 것: 위 「핵심 정리」. Zappy 방식(ASSN 웹훅)은 유료 다운로드에 아예 발화하지 않아 복제가 불가능했고, 일일 판매 리포트 크론이 대안.
- 근거: Zappy 레포 커밋 `75c3b93`(`landing/api/hangeom-sales.js` + `landing/vercel.json`), 환경변수 7개(`ASC_KEY_ID`·`ASC_ISSUER_ID`·`ASC_PRIVATE_KEY`·`ASC_VENDOR_NUMBER`·`CRON_SECRET`·`SLACK_WEBHOOK_URL`·`WEBHOOK_TOKEN`)는 `zappy-landing` Production. 배포 후 `POST /api/hangeom-sales` → 401(404 아님), 프로젝트 API `crons.definitions`에 `/api/hangeom-sales 0 22 * * *` 등록 확인. 대시보드 Run → 23:37:32 KST `GET 200` 951ms, Slack `#70-밥벌이-재피`에 `📊 한능검 정복 2026-09-02(PT) 판매 0건 (무료 다운로드 8건)` 도착(Slack 검색 `ts 1788446253.579729`).
- 남은 것: 첫 유료 판매가 찍히면 `🎉 … 판매 N건 · 매출 ₩… · 수익 ₩…` 포맷을 실물로 확인. 지금은 무료 시절 다운로드(type 1 · 0.00)만 관측했다.

### 2026-10-05 — 일일 요약 크론 폐지, 결제 순간 웹훅만 (채널 `#밥벌이`)
- 맥락: 홍 요청 "채널명을 밥벌이로 바꾸고 알림은 결제된 순간만". [한능검](../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/%ED%95%9C%EB%8A%A5%EA%B2%80/README.md)이 무료+IAP가 된 뒤라 웹훅으로 결제 순간을 받을 수 있다.
- 배운 것:
  - **일일 요약을 끄기 전에 실시간 경로가 정말 살아 있는지 먼저 본다.** 10-03 한능검 결제가 아침 요약에만 찍히고 웹훅 메시지는 없었다 — ASC에 한능검 알림 URL이 등록돼 있지 않았다([ASSN](App%20Store%20Server%20Notifications.md) `4040007`). 요약만 껐으면 결제가 아무 데도 안 찍혔다.
  - 크론은 `vercel.json`에서 `crons`를 빼고 배포하면 프로젝트 `crons.definitions`가 `[]`가 된다.
  - **`zappy-landing`은 지금 GitHub 연동(Root Directory `landing`)이라 main push가 곧 프로덕션 배포다.** `landing/`에서 `vercel deploy --prod`를 치면 `The provided path “…/landing/landing” does not exist`. 배포 확인은 `vercel ls zappy-landing --prod`의 새 항목 + 별칭 `zappy-landing-git-main-…`.
  - Slack 채널 이름을 바꿔도 Incoming Webhook은 채널 ID에 묶여 그대로 온다.
- 근거: Zappy 레포 커밋 `025db0c`(웹훅 `SLACK_TYPES` = `ONE_TIME_CHARGE`·`TEST`, `vercel.json` 크론 제거, 테스트 11개), 프로젝트 API `crons.definitions: []`, 10-06 13:20·13:47 «한능검 정복 — 해설·요약 노트 잠금해제 구매!» 실시간 도착(Slack `#밥벌이`).

### 2026-10-06 — 결제 알림에 서비스별 누적 매출
- 맥락: 홍 요청 "누적 매출도 나오게, 서비스별로, 출시부터 전부". 결제 알림 끝에 `📈 누적 매출` 줄과 서비스별 줄(Zappy+ · 한능검 정복 앱 · 한능검 예상 모의고사 웹)을 붙였다.
- 구조: **누적 = ASC 일일 판매 리포트 합(`rev:seed`) + 리포트 이후 결제 순간 기록(`rev:tx`)**. 리포트는 하루 늦게 나오고 웹훅은 기록을 시작한 뒤의 결제만 안다 — 둘을 잇는 경계가 `rev:seed.through`(리포트가 덮는 마지막 PT 날의 끝)다. App Store 결제는 경계 이전이면 `rev:tx`에서 건너뛰어 이중으로 안 센다. 토스 결제는 리포트가 없어 `rev:tx`가 전부다. 기록 시작 시각(`rev:live`)이 경계보다 뒤면 그 사이가 비어 있어 「일부」로 표시한다. 과거분은 매일 크론(`revenue-seed`, Slack 메시지 없음)이 다시 더하고, 실패는 다음 결제 알림의 누적 줄 아래 ⚠️로 드러난다.
- 배운 것:
  - **아직 생성 안 된 일일 리포트도 404다** — 「그날 거래 0건」과 구분이 안 된다. PT 00:54에 수동 실행했더니 막 끝난 10-05(PT) 결제 2건이 0으로 잡혔다. PT 정오 전에는 그제까지만 센다(`lastReportDate`).
  - **Zappy+ 리포트 행은 SKU가 제품 ID가 아니고 `Parent Identifier`가 앱 SKU `com.hong.zappy`다.** 한능검(`hangeom`)과 모양이 달랐다. 모르는 앱 행을 버리지 않고 `sku:<부모 SKU>`로 따로 모아 둔 덕에 첫 실행 로그에서 바로 보였다.
  - **분류가 끝난 값을 캐시하면 규칙을 고쳐도 옛 답이 남는다.** 날짜별 캐시(`rev:day:<버전>:<날짜>`)에 버전을 붙여 규칙이 바뀌면 새로 받게 했다.
  - **Vercel Marketplace 「Redis」는 `REDIS_URL`(redis:// 연결 문자열) 하나만 넣는다** — Upstash REST 변수(`KV_REST_API_URL`·`KV_REST_API_TOKEN`)가 아니다. npm `redis`로 붙고 `RESP: 2`로 고정했다. v6 클라이언트는 기본으로 `HELLO`(RESP3)를 보내고, RESP3면 `HGETALL`이 맵으로 와서 REST 응답과 모양이 달라진다.
  - **크론 수동 실행은 CLI로 된다**: `vercel crons run /api/revenue-seed`(CLI 58, 베타). 2026-09-03엔 대시보드 Run만 있다고 적었는데 대시보드에 Run 버튼이 안 보였다. 실행 결과는 응답이 아니라 `vercel logs --json`의 `logs[].message`로만 보여서 합계를 `console.log`로 남겼다.
  - 리포트로 센 Zappy+ 판매는 8건인데 Slack 알림은 4건이었다. 알림이 08-08부터 시작됐고 웹훅이 404였던 기간이 있어서로 보인다(날짜별 대조는 안 했다). **누적은 리포트를 기준으로 삼는다.**
- 근거: Zappy 레포 커밋 `034b935`·`9e8b37b`·`94a48fc`·`169e9f6`·`88462d6`(`landing/api/_revenue.js`·`revenue-seed.js`·`appstore-webhook.js`, `landing/test/revenue.test.js`), 예상 모의고사 웹 `predict-site/api/_revenue.js`(ESM 사본)·`_lib.js` — 배포 `dpl_CGy44xASwvugMPgjYTncNMXL5Dzz`. 크론 실행 로그(배포 `17zk6rzdf`) `revenue-seed 2026-10-04(PT)까지, 리포트 77일 받음` — Zappy+ 8건 · 한능검 정복 앱 1건.
- 남은 것: 10-05(PT) 한능검 결제 2건은 10-07 15:00 PT 크론에서 들어오고, 기록 시작(10-06 07:47 UTC)을 리포트가 넘는 10-08 07:00 KST부터 「일부」 표시가 사라진다. 첫 실결제 알림에서 누적 줄을 실물로 확인한다. 앱인토스 미니앱 IAP는 알림이 없어 누적에 없다.

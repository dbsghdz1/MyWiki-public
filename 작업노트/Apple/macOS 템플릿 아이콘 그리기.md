# macOS 템플릿 아이콘 그리기

`NSImage.isTemplate = true`인 이미지는 **알파 채널만 남고 색은 전부 버려진다**. macOS가 메뉴바 톤(라이트=검정, 다크=흰색, 선택 상태=강조색)에 맞춰 실루엣을 다시 칠하기 때문이다. 그래서 템플릿 아이콘을 그리는 일은 "색칠"이 아니라 **실루엣 조각**이고, 컬러 아이콘에서 당연하던 표현들이 통째로 성립하지 않는다.

## 핵심 정리

- **색은 정보가 될 수 없다.** 컬러에서 색으로 나르던 신호(계절·상태·강조)는 템플릿에선 **형태**로 옮겨야 한다. 옮길 형태가 없으면 그 정보는 모노에서 사라진다 — "색만 다른 두 상태"는 템플릿에서 같은 그림이다.
- **채움 위에 무언가를 얹으려면 뚫어야 한다(knockout).** 검정 위에 검정을 그리면 아무 일도 일어나지 않는다. `CGContext.setBlendMode(.clear)`로 그리면 이미 칠한 알파가 지워져 "구멍"이 생기고, 그 구멍이 곧 눈·입·무늬가 된다.
  ```swift
  func withKnockout(_ on: Bool, _ draw: () -> Void) {
      if on { NSGraphicsContext.current?.cgContext.setBlendMode(.clear) }
      draw()
      if on { NSGraphicsContext.current?.cgContext.setBlendMode(.normal) }
  }
  ```
- **`.clear`는 파괴적이라 그리기 순서가 곧 z축이다.** 가는 선(1~2pt) 위에 knockout을 얹으면 선이 끊긴다. 얹은 것과 밑바탕을 분리해 보이고 싶으면 **틈만 뚫고**(밑바탕보다 살짝 넓게), 지워지면 안 되는 부분은 **그 뒤에 다시 그려 되메운다**.
- **경계가 얼굴을 가로지를 땐 두 번 그린다(split face).** 채움 경계(예: 차오르는 물)가 눈·입을 지나가면 안쪽은 뚫고 바깥쪽은 칠해야 깔끔하게 반전된다. 같은 그리기 클로저를 두 번 호출하되, 한 번은 채움 경로로 clip + `.clear`, 한 번은 `evenOdd`로 만든 여집합으로 clip + 일반 모드.
  ```swift
  fill.addClip();          /* .clear */  draw()
  let inv = NSBezierPath(rect: bounds); inv.append(fill); inv.windingRule = .evenOdd
  inv.addClip();           /* .normal */ draw()
  ```
- **컬러의 디테일은 대개 모노에서 빼야 한다.** 하이라이트·음영·결·주름처럼 컬러에서 입체를 만들던 요소는 knockout으로 옮기는 순간 실루엣을 조각내 "부서진 그림"이 된다. 실측한 판단 기준: **그 디테일이 없어도 정보가 남으면 뺀다.** 정보를 나르는 디테일만 knockout으로 살린다.
- **얹힌 것/밑에 있는 것은 knockout 틈으로만 표현된다.** 컬러는 흰 눈 / 갈색 가지처럼 색으로 저절로 분리되지만 템플릿은 둘 다 검정이라 그냥 겹치면 "굵어진 하나"가 된다. `밑바탕(검정) → 틈(투명) → 얹은 것(검정)` 3단으로 그려야 얹힌 것으로 읽힌다.
- **부분 알파는 회색으로 렌더된다.** `withAlphaComponent`는 템플릿에서도 유효해서 **페이드인/아웃**을 쓸 수 있다(요소를 문턱값에서 튀어나오게 하지 않고 서서히 등장시키기). 다만 반투명은 채도 없는 중간톤이 되므로 실루엣 판독에 쓰지 말고 전환 연출에만 쓴다.
- **눈으로 볼 때는 두 배경 모두에서 본다.** 템플릿 이미지를 흰 배경에 그대로 그리면 검정으로 보이지만 다크 메뉴바에서는 흰색으로 반전된다. 검증 스크립트에서는 어두운 배경 위에 `NSRect.fill(using: .sourceAtop)`으로 흰색을 덧입혀 반전 결과를 흉내 내면 두 모드를 한 번에 확인할 수 있다.

- **새 캐릭터를 그릴 때는 «원 조립»이 아니라 «실루엣 한 획»이 낫다** (2026-09-11, 홍이 신한카드 펭귄 리뉴얼을 레퍼런스로 제시). 머리 원 + 몸 타원을 붙이면 눈이 **이음매를 먼저 보고** «부품이 붙은 것»으로 읽는다. 턱→얼굴→귀→등→엉덩이→배를 끊기지 않는 path 하나로 그리면 도형 수는 **오히려 줄고**(6개 → 1개) 캐릭터로 읽힌다. 이목구비를 아래쪽 1/3에 모으고 눈 사이를 좁히는 것이 가장 큰 레버다 — 이마가 넓어지고 그게 «아기» 비율이 된다.
- **다만 이 규칙을 이미 성립한 디자인에 소급하면 안 된다** (2026-09-11 실패에서). Zappy 18종에 적용하자고 제안했다가 홍에게 «훨씬 훨씬 별로»로 기각당했고 기각이 옳았다. **눈사람은 공 두 개인 것이 정체성인데** «실루엣 한 획»으로 합치니 펭귄·유령이 됐다. 규칙은 **빈 종이에서 시작할 때** 쓰는 것이고, 각자 문법이 선 것에 덮어씌우면 개성이 지워진다.
- **«작은 크기에서 안 보이는 디테일»을 함부로 덜어내지 말 것.** 눈사람의 단추·당근 홈·목도리 자락을 «22pt에서 안 보인다»며 뺐는데, 개별로는 안 보여도 **밀도**를 만들고 있었다. 빼고 나니 밋밋해졌다.
- **«줄어든다»와 «녹는다»는 다르다.** 잔량이 줄 때 도형을 균일 축소하면 «멀어진 것»으로 보인다. 녹는 것은 가로로 퍼지며 낮아져야 한다 — 축 하나를 늘리고 하나를 줄인다. (다만 Zappy 원본은 이미 그렇게 돼 있었다.)
- **메뉴바 아이콘 판정은 «배경 5종 × 실제 크기»에서 한다.** 회색 배경 한 장만 보고 «흰 몸이 밝은 배경에서 사라진다»고 단정했다가 틀렸다 — 흰색·밝은 회색·연한 하늘·중간 회색·어두운 배경에 실제 크기로 올려 보니 어디서도 안 사라졌다. **연한 외곽선은 약한 게 아니라 재료 표현일 수 있다**(눈/얼음). 검사 도구는 `CuteBattery/docs/sketches/bg-check.swift`.

## 기록

### 2026-08-25 — 나무 테마의 '가지 위에 쌓인 눈' (Zappy 1.10.0)

[[프로젝트/개인/Zappy/README|Zappy]]에 계절 테마를 넣으며 겨울 눈을 가지에 얹었다. 컬러는 가지 경로를 위로 1pt 민 선을 흰색으로 그리면 그대로 눈이 됐지만, **모노는 같은 코드가 "가지가 굵어진 것"으로만 보였다** — 둘 다 검정이라 분리될 근거가 없다. 사이에 knockout으로 틈을 내서야 얹힌 것으로 읽혔고, 그 틈이 줄기 윗동을 갉아먹어 줄기를 눈보다 **뒤에** 그려 되메웠다. 실루엣 렌더링에는 "위에 얹힌다"는 개념이 없고, 오직 **구멍**만 있다는 것이 요점.

같은 세션에서 잔가지를 잎이 무성할 때 숨기려고 `withAlphaComponent`로 페이드했는데, 템플릿에서도 그대로 회색 반투명으로 렌더되어 문턱값에서 툭 튀어나오는 문제 없이 등장시킬 수 있었다.

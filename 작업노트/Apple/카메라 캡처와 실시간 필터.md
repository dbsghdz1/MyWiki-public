# 카메라 캡처와 실시간 필터

iOS 카메라 앱에서 **촬영음·실시간 필터·프리뷰 크기**는 서로 다른 문제처럼 보이지만, `AVCapturePhotoOutput`을 쓰느냐 `AVCaptureVideoDataOutput`을 쓰느냐 하나로 셋이 같이 결정된다.

## 핵심 정리

### 촬영음은 관할에 따라 앱이 못 끈다 ★

iOS 18에 공식 API가 있다. **SDK 주석이 답을 그대로 말한다:**

```
shutterSoundSuppressionSupported
  On iOS, this property returns NO in jurisdictions where shutter sound
  production cannot be disabled. On all other platforms, it always returns NO.

shutterSoundSuppressionEnabled
  AVCapturePhotoOutput throws an NSInvalidArgumentException in
  `-capturePhotoWithSettings:` if its `shutterSoundSuppressionSupported`
  property returns NO.
```

- **한국·일본에 판매된 기기는 `NO`다.** 한국은 2004년 정통부 권고(촬영 시 65dB 이상), 일본은 업계 자율규제
- **지원 안 되는데 켜면 예외를 던져 앱이 죽는다.** 반드시 `isShutterSoundSuppressionSupported`를 먼저 본다
- iOS 18.0+ (`macos(15.0), ios(18.0)`). 그 아래 타깃이면 `#available` 분기 필요

### 진짜 무음은 사진 출력을 안 쓰는 것 ★

**`AVCaptureVideoDataOutput`에서 프레임을 뽑는 경로에는 시스템 촬영음이 없다.** 관할과 무관하게 조용하다 — 국내 무음 카메라 앱들(SNOW 등)이 쓰는 방법이 이것이다.

```swift
output.videoSettings = [kCVPixelBufferPixelFormatTypeKey as String: kCVPixelFormatType_32BGRA]
output.alwaysDiscardsLateVideoFrames = true
output.setSampleBufferDelegate(self, queue: queue)
// 촬영 = "다음 프레임 한 장 주세요" 플래그를 세우는 것
```

**대가는 해상도다.** 비디오 프레임 크기가 곧 사진 크기의 상한이 된다.

### 그러면 포맷을 직접 고른다

`sessionPreset`은 두루뭉술하다. **필요한 최소 크기를 정하고 그 이상 중 가장 작은 포맷**을 고르는 편이 맞다 — 클수록 프레임마다 거는 필터가 무거워진다.

```swift
session.sessionPreset = .inputPriority          // 포맷을 직접 고르면 이걸로 둔다
let ok = device.formats.filter { f in
    f.videoSupportedFrameRateRanges.contains { $0.maxFrameRate >= 30 }
}
// 내보내기가 1440px 정사각이면 짧은 변 1440 이상이면 충분하다
let picked = ok.filter { min(dims($0).width, dims($0).height) >= 1440 }
             .min { area($0) < area($1) }
device.lockForConfiguration(); device.activeFormat = picked; device.unlockForConfiguration()
```

### `AVCaptureVideoPreviewLayer`에는 필터를 못 건다 ★

하드웨어가 그대로 그리는 화면이라 CoreImage가 끼어들 자리가 없다. **필터를 고르는 UI를 만들어 놓고 프리뷰가 안 바뀌면 사용자는 필터가 고장 났다고 읽는다** — 실제로 결과에는 적용되고 있어도 그렇다.

프레임마다 CIFilter를 걸어야 하므로 CPU로는 못 따라간다. `MTKView` + Metal 백엔드 `CIContext`로 드로어블에 바로 렌더한다.

```swift
view.framebufferOnly = false        // ★ CIContext가 드로어블 텍스처에 직접 쓴다
view.isPaused = false; view.enableSetNeedsDisplay = false
ciContext = CIContext(mtlDevice: device, options: [.workingColorSpace: sRGB])
// draw(in:)에서
ciContext.render(image, to: drawable.texture, commandBuffer: buf,
                 bounds: drawableRect, colorSpace: sRGB)
buf.present(drawable); buf.commit()
```

- **`framebufferOnly = false`를 안 하면 렌더가 실패한다.** 기본값은 `true`다
- 프레임은 카메라 큐에서 들어오고 그리기는 렌더 스레드다. `CIImage` 참조 교체는 원자적이라 이 용도엔 락이 필요 없지만, **캡처 핸들러 같은 클로저는 락으로 감싼다**(메인에서 쓰고 카메라 큐에서 지운다)

### 방향은 연결에서 세운다 — EXIF 문제가 사라진다

```swift
if #available(iOS 17.0, *), c.isVideoRotationAngleSupported(90) { c.videoRotationAngle = 90 }
```

파이프라인에서 세워 들어오므로 [[작업노트/Apple/CoreImage 색 파이프라인|`CIImage(image:)`가 `imageOrientation`을 무시하는 함정]]을 이 경로에서는 아예 안 만난다.

### 크롭 가이드는 프레임 중심과 같은 자리여야 한다

프리뷰가 화면 중앙 기준 aspect fill이고 촬영이 프레임 가운데를 자른다면, **가이드 사각형도 정확히 화면 정중앙이어야 한다.** 조작부 자리를 주려고 위로 올리면 표시한 영역과 실제로 남는 영역이 어긋난다. 조작부는 프리뷰 위에 얹는다 — 아이폰 기본 카메라도 그렇게 한다.

## 기록

### 2026-08-26 — Fadeo 촬영 경로를 갈아엎었다 (즉석카메라)

- 맥락: 사용자 요청 셋 — *"촬영음을 꺼달라(SNOW처럼)"*, *"카메라 화면이 아직도 작다"*, *"필터가 안 먹히는 것 같다"*. 세 개가 **전부 같은 선택 하나**로 풀렸다.
- 배운 것: 위 「핵심 정리」 전부. 특히 ① 촬영음은 관할에 따라 공식 API로도 못 끄고 **억지로 켜면 앱이 죽는다** ② 진짜 무음은 사진 출력을 안 쓰는 것 ③ `AVCaptureVideoPreviewLayer`에는 필터를 못 건다 — 필터 UI를 만들어 놓고 프리뷰가 안 바뀌면 **고장으로 읽힌다.**
- 근거: `(로컬 경로)` 커밋 `8b54e48`. `Sources/Camera/CameraSession.swift`(비디오 프레임 캡처·포맷 선택), `Sources/Camera/FilmPreview.swift`(MTKView 렌더러). 네 톤을 프리뷰에 걸어 시뮬레이터에서 차이를 확인했다.
- 남은 것: **실기기에서 실제로 잡히는 포맷 크기 확인**(DEBUG 로그 `[camera] active format WxH`). 1440 미만이면 화질 손해다.

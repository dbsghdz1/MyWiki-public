# Jev와 System One 판단 모델

Jev는 글을 쓰는 모델이 아니라 **정해진 후보 중 하나를 고르고 확률을 돌려주는 판단 모델**이다. 검색도 못 하고 이유도 설명하지 않는다. 후보를 만드는 일은 코드나 Claude가, 고르는 일만 Jev가 한다. 59건 시험에서 **확신 높은 답의 95.5%가 정답과 같았고 확신 낮은 답은 53%**였다. 그래서 "확신 높으면 자동, 낮으면 사람"으로 쓴다.

## 핵심 정리

- **정체**: TypeSafe의 System One 모델 중 첫 번째(`jev-latest`, `POST /v1/systemone`). 입력은 텍스트나 JSON 상태뿐이고 출력은 타입이 있는 값과 확률이다. 질문 유형은 셋이다: Choice(후보 중 하나), Score(순서 있는 척도), Noul(참일 확률).
- **confidence의 뜻**: 정답일 확률이 아니다. 확률 분포가 한 후보에 몰린 정도다. Choice는 `(p_max − 1/n) / (1 − 1/n)`. 문서는 "보정은 예측 집단 단위로 측정되며 개별 답의 정확성을 보장하지 않는다"고 적는다. Noul에는 confidence 필드가 없다.
- **이 환경의 연결**: Claude Code user scope에 등록한 MCP `aside-jev-direct`(스크립트 `(로컬 경로)`, 키는 macOS Keychain, 원문을 읽거나 출력하지 않는다). 도구는 `mcp__aside-jev-direct__jev_choose`(후보 선택), `jev_browser_step`(링크 한 단계 선택), `aside_tabs`(탭 조회). `jev_choose`는 `choice`, `confidence`, `ready`를 돌려주고 기본 최소 confidence는 0.7이다. `ready=false`는 0.7 미만이다. 현재 Noul 도구는 없어서 "맞음/아님" 두 후보의 Choice로 대신한다.
- **쓰는 규칙**: 전역 `(로컬 경로)`에 두 절이 있다. 「Aside 탐색의 Jev 사용」(상품 비교, 링크 선택)과 「MyWiki 검색의 Jev 사용」(2026-10-16 추가: 후보는 index, grep으로 먼저 뽑고, 후보 설명은 제목과 `summary`만, 본문과 금액, 토큰, 제3자 실명은 보내지 않는다). Claude 전용 지침이라 자동으로 강제되지 않고 Codex와 Hermes에는 적용되지 않는다.
- **한계**: 검색을 못 한다. 근거를 설명하지 않는다. 텍스트만 받는다. **입력이 부실해도 확신 높게 답한다**(업무 설명이 없는 공고를 0.98로 판정한 사례). 사용 전에 업무와 자격 같은 판단 근거가 입력에 들어갔는지 코드로 먼저 거른다.

## 기록

### 2026-10-16 위키 허브 분류 시험 (11건)
- 맥락: 운영. 위키 검색에 Jev를 붙일 수 있는지 보려고 허브와 프로젝트 요약을 후보로 `jev_choose`를 돌렸다.
- 배운 것:
  - 만든 가상 자료 5건과 공개 Sources 6건 모두 기대한 허브와 같았다. 다만 6건 중 4건은 제목에 프로젝트명이 있어서 **문자열 매칭에 가까운 쉬운 시험**이었다.
  - 여러 허브에 걸친 자료는 confidence가 내려갔다(0.79, 0.86). 반대로 실제로 두 곳에 링크된 자료가 0.99로 나오기도 해서, Choice는 **복수 링크를 못 잡는다**. 복수 판정은 허브마다 Noul로 따로 물어야 한다.
  - 위키 분류는 건수가 적고 틀려도 되돌리기 쉬워 Jev의 이득이 작다고 판단했다. 반복 선택 작업이 맞는 쓰임이다.
- 근거: 세션 중 `jev_choose` 호출 결과(파일로 남기지 않음).

### 2026-10-16 채용 공고 선별 시험 (59건)
- 맥락: 운영. 사람이 반복해서 거르는 일에 Jev를 붙여 보려고, 에이전트가 이미 분류해 둔 공고 59건을 정답으로 삼아 "웹 프론트엔드 또는 웹 UI를 만드는 웹 풀스택 직무인가"를 `jev_choose`로 물었다. 후보는 `target`(지원 대상)과 `not`(백엔드 중심, React Native 전용, 디자인 중심, 고객 현장 엔지니어, 직무 불명 공채 등) 둘이다.
- 결과:

| 구분 | 건수 | 정답과 같음 |
|---|---|---|
| 확신 높음 (`ready=true`) | 44 | 42 (95.5%) |
| 확신 낮음 (`ready=false`) | 15 | 8 (53%) |
| 전체 | 59 | 50 (85%) |

- 배운 것:
  - 확신 높게 `target`이라 답한 건 전부 맞았고, **확신 높은 오답 2건은 둘 다 `not` 쪽(놓치는 방향)**이었다. 그래서 `target`+`ready`는 후보로 올리고, `ready=false`는 사람이 보고, 확신 높은 `not`은 제목 목록으로 훑게 하는 구조가 맞다.
  - 확신 낮음 구간은 거의 동전 던지기였다. 사람이 볼 몫은 전체의 약 25%였다.
  - 확신 높은 오답 하나는 요약에 업무 설명이 없던 **입력 문제**였다. 회사 소개만 있는 공고는 판정 대상에서 먼저 빼야 한다.
  - 정답이 에이전트 분류(홍이 직접 확인한 게 아님)이고 본문 요약을 사람(Claude)이 줄여서 보냈다. 표본 59건이라 수치는 감만 준다. 오분류율을 믿으려면 100건 이상이 필요하다.
- 근거: 세션 중 `jev_choose` 호출 결과. 샘플은 세션 임시 파일에만 있다.

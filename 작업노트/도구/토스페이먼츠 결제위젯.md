# 토스페이먼츠 결제위젯

웹(일반 브라우저)에 카드·카카오 페이·네이버 페이·토스페이·페이코를 **계약 하나**로 붙이는 방법. 토스페이먼츠 결제위젯 v2를 Vite + React + Vercel 함수(해시 라우터)에 붙이며 알게 된 것. 맥락: [예상 모의고사 웹 판매](../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/%ED%95%9C%EB%8A%A5%EA%B2%80/%EC%98%88%EC%83%81%20%EB%AA%A8%EC%9D%98%EA%B3%A0%EC%82%AC%20%EC%9B%B9%20%ED%8C%90%EB%A7%A4%202026-10-01.md) 4차(2026-10-02).

## 기록

### 2026-10-02 — 예상 모의고사 웹에 결제위젯 연동 (한능검 `predict-site/`)

- **SDK**: `@tosspayments/tosspayments-sdk` 2.9.0. `loadTossPayments(clientKey)` → `tp.widgets({ customerKey: ANONYMOUS })` → `setAmount({ currency: 'KRW', value })` → `renderPaymentMethods({ selector, variantKey: 'DEFAULT' })` → `renderAgreement({ selector, variantKey: 'AGREEMENT' })` → `requestPayment({ orderId, orderName, successUrl, failUrl })`. **`setAmount`는 숫자가 아니라 `{currency, value}` 객체**다(v1과 다름). 비회원은 `ANONYMOUS` 상수(값 `@@ANONYMOUS`)를 customerKey로 준다. 위젯은 한 페이지에 한 번만 렌더하고 플랜을 바꿀 땐 `setAmount`만 다시 부른다.
- **공개 테스트 키**(토스 문서·샘플 저장소 `tosspayments/payment-widget-sample`의 `java-vanillajs`에 박혀 있다): 클라이언트 `test_gck_docs_Ovk5rk1EwkEbP0W43n07xlzm` · 시크릿 `test_gsk_docs_OaPz8L5KdmQXkzRz3y47BMw6`. 가입 없이 위젯 렌더·승인 API까지 돈다. 다만 **문서 키로 `/v1/payments/orders/{orderId}` 조회는 `NOT_FOUND_MERCHANT`** — 주문번호 복원 API는 실키에서만 검증된다. 키 유효성은 bogus paymentKey로 `/v1/payments/confirm`을 쳐서 `NOT_FOUND_PAYMENT_SESSION`(유효) vs `UNAUTHORIZED_KEY`(무효)로 가른다.
- **승인은 서버에서**: `POST https://api.tosspayments.com/v1/payments/confirm` body `{paymentKey, orderId, amount}`, 헤더 `Authorization: Basic base64(secretKey + ':')`. 금액은 클라이언트 쿼리값이 아니라 **주문번호에서 복원한 정가**와 대조한다(`api/_lib.js parseOrderId`). 새로고침 재승인은 `ALREADY_PROCESSED_PAYMENT` → `GET /v1/payments/{paymentKey}`로 `status === 'DONE'` 확인 뒤 지급.
- **주문번호 제약**: 영문·숫자·`-_=` 6~64자 — **한글 불가**. 상품·수준·회차를 `p80-all-<hex>` / `p80-one-a2-<hex>`(a=심화·b=기본)로 인코딩하면 서버가 DB 없이 범위를 복원한다.
- **해시 라우터와 successUrl**: 토스가 `successUrl`에 `?paymentType&amount&orderId&paymentKey`를 **덧붙인다**. `#/심화/2` 같은 해시 주소를 주면 쿼리가 해시 뒤에 붙어 `location.search`가 비므로, **쿼리만 쓴다**(`/?pay=ok&r=심화/2`) → 승인 뒤 `history.replaceState`로 `#/심화/2`로 돌린다. 실패는 `?code&message&orderId`, 사용자 취소 코드는 `PAY_PROCESS_CANCELED`.
- **테스트 모드도 카드 인증창은 진짜다**: 위젯 위에 "테스트 환경이에요" 배너가 뜨지만 카드 선택 → 결제하기를 누르면 **실제 카드사 인증창(KB Pay·앱 없이 결제 등)**이 iframe으로 열린다. 돈은 안 빠지지만 카드 정보 입력은 필요해서 헤드리스로 완주할 수 없다. 돌아오는 경로는 `/?pay=ok&paymentKey=bogus…`를 직접 열어 승인 실패 → 플래시 메시지 → 해시 라우트 복귀까지만 확인했다.
- **Vercel 프리뷰 배포는 Vercel Authentication으로 막혀** 리다이렉트 결제 테스트가 안 된다(302 → vercel.com/sso-api). 결제 테스트는 프로덕션 URL에서 테스트 키로 한다. 환경 변수 `VITE_TOSS_CLIENT_KEY`(빌드 시 번들에 박힘)·`TOSS_SECRET_KEY`(함수)로 두고, 실키 전환은 둘만 바꿔 재배포.
- **Aside REPL은 호출마다 새 세션**이다 — `aside repl "…"`를 두 번 나눠 부르면 두 번째에서 `page`가 null. 다단계 UI 흐름은 한 호출 안에 다 넣는다. `page.setViewportSize`는 없다. 스크린샷은 `./artifacts/`에 저장되는데 실제 경로는 `(로컬 경로)`.
- **동시 세션 지뢰(실제로 밟음)**: 같은 `predict-site/`를 다른 Claude 세션이 몇 분 전에 고치고 있었다(토스 검수 반려 수정 — `config.ts`의 SKU를 콘솔 발급 productId로 교체, Paywall의 `← 목록으로`를 토스 밖에서만). 내가 세션 초반에 읽은 파일을 통째로 다시 써서 두 변경을 날렸고, 그 세션이 빌드해 둔 `hangeom-predict.ait`(zip)의 번들 JS를 grep해 복구했다. **git 없는 폴더는 Write 직전에 mtime을 다시 보고, 덮어쓰기 대신 치환으로 고친다.**

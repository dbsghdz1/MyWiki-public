# 셸 초기화와 터미널 통합

**`.zshrc`에 쓴 것이 최종이 아니다.** 터미널 앱의 셸 통합은 rc 파일이 전부 실행된 *뒤* 첫 프롬프트에서 한 번 더 끼어들 수 있고, 이때 내가 정의한 함수를 조용히 되돌린다.

## 핵심 정리

- zsh 초기화 순서는 `.zshenv` → (로그인) `.zprofile` → (인터랙티브) `.zshrc` → (로그인) `.zlogin`인데, **파일이 끝이 아니다.** `precmd` 훅은 *모든 rc가 끝난 뒤 첫 프롬프트 직전*에 돌기 때문에, rc에서 정의한 것을 훅이 덮어쓰면 훅이 이긴다.
- **CLI 이름을 내 함수로 감싸는 것은 터미널 앱과 이름을 두고 경쟁하는 일이다.** 겹치지 않는 이름으로 옮기는 쪽이 근본 해결이고, 훅 순서를 다투는 것은 다음 업데이트에 또 깨진다.
- 진단할 때 **`type -w`는 "function"까지만 알려주고 *누구의* 함수인지는 말해주지 않는다.** 본문은 `functions <이름>`으로 직접 봐야 한다. 이걸 안 봐서 한참 엉뚱한 데를 팠다.
- **"source 하면 되는데 새 탭이면 또 안 된다"는 신호가 결정적이다.** 그 조합은 "쉘이 오래됐다"가 아니라 **"매 세션 시작 때 무언가가 내 설정을 되돌린다"**를 가리킨다. 되돌리는 쪽이 1회성(자기를 훅에서 제거)이면 수동 source가 그 탭에서만 영구히 먹히는 것까지 설명된다.
- cmux가 터미널 환경을 가로채는 다른 사례(`GHOSTTY_RESOURCES_DIR`·PATH의 `ghostty`): [[작업노트/도구/Ghostty 설정|Ghostty 설정]] (2026-08-30)
- **macOS(BSD) grep의 `-Z`는 GNU의 `-Z`가 아니다.** 파일 목록을 NUL로 구분하려면 **`--null`**을 써야 하고, `-Z`는 조용히 무시돼 개행 구분 출력이 나온다. 공백 있는 경로를 `xargs -0`에 넘기면 전부 한 인자로 뭉쳐 `File name too long`이 난다 — **에러 메시지가 원인(구분자)과 전혀 안 닮아서** 경로 길이 문제로 오해하기 쉽다.

## 기록

### 2026-08-24 — cmux 셸 통합이 내 `claude()` 함수를 첫 프롬프트에서 덮어쓴다

- 맥락: 볼트를 한 번에 열려고 `(로컬 경로)`에 `claude()` 래퍼를 두고 커스텀 플래그 `--obsidian`을 처리했다(`alias co='claude --obsidian'`). 그런데 새 터미널을 열 때마다 `error: unknown option '--obsidian'`이 났다.
- 배운 것:
  - **원인은 내 스크립트가 아니라 터미널 앱이었다.** cmux(내장 ghostty)의 셸 통합이 `claude()`를 자기 래퍼로 정의하고, 그 위에 **`precmd` 훅으로 "사용자 startup이 바꿔놨을 경우를 대비해" 첫 프롬프트에서 한 번 더 재설치**한다. `.zshrc`는 이미 다 실행된 뒤라 내 함수가 진다.
  - 그 훅은 실행 직후 `add-zsh-hook -d precmd`로 **자기를 훅 목록에서 제거**한다 → `source (로컬 경로)`를 하면 그 탭에서는 영구히 고쳐지고, 새 탭에서는 처음부터 다시 깨진다. 증상이 "고쳤는데 또 안 된다"로 보인 이유가 이것이다.
  - `type -w claude`가 `function`으로 나와서 "내 함수가 살아있다"고 오판했다. **함수가 있느냐가 아니라 누구 함수냐를 봤어야 했다.**
- 근거:
  - `/Applications/cmux.app/Contents/Resources/shell-integration/cmux-zsh-integration.zsh:369` — `eval "$command_name() { _cmux_claude_wrapper_command \"\$@\"; }"`
  - 같은 파일 `:1903` 주석 — *"We fix this once on first prompt (after all init files have run), and reinstall cmux-owned wrapper functions in case user startup replaced them."* → `add-zsh-hook precmd _cmux_fix_path`
  - 가로채는 이름은 `claude`, `grok` 둘 (`_cmux_install_cli_wrapper` 호출부). PATH 앞에도 `$TMPDIR/cmux-cli-shims/claude` 셰임을 심는다.
  - 재현/반증: cmux 밖에서는 `zsh -li`를 **pty까지 붙여도**(`script -q /dev/null /bin/zsh -lic ...`) 전혀 재현되지 않았다. 환경 판별은 `TERM_PROGRAM=ghostty`인데 `GHOSTTY_RESOURCES_DIR`이 `/Applications/cmux.app/...`을 가리키는 것으로 했다.
- 해결: `claude()`를 버리고 **`co()` 함수**로 옮겼다(cmux가 안 건드리는 이름). 실제 실행은 `(( $+functions[_cmux_claude_wrapper_command] ))`이면 그 래퍼를 태워 cmux 연동을 유지하고, 없으면 `command claude`로 폴백한다. `(로컬 경로)`에 원본 보관.

### 2026-08-25 — `grep -Z`가 macOS에서 안 통해 공백 경로가 뭉쳤다

- 맥락: 공부 노트에 `audience` 도입하며 `(로컬 경로)`에 "프로젝트 관련 `audience: ai` 노트 찾기" 커맨드를 넣던 중. 볼트 경로(`(로컬 경로)`)에 공백이 있어 NUL 구분이 필요했다.
- 배운 것:
  - `grep -rlZ "^audience: ai" "$VAULT/공부" | xargs -0 grep -l Zappy` → 23개 경로가 **한 인자로 뭉쳐** `grep: <전부 이어붙은 문자열>: File name too long`. macOS grep이 `-Z`를 NUL 구분자로 받지 않는다.
  - `--null`로 바꾸니 정상 동작(Zappy 관련 12개). GNU grep은 `-Z`/`--null` 둘 다 되지만 **BSD는 긴 이름만** 된다.
  - **문서에 커맨드를 적을 때는 적기 전에 실행해 볼 것.** 안 그러면 나중 세션의 에이전트가 깨진 커맨드를 그대로 믿고 실행한다 — 이번엔 커밋 직전에 잡았다.
- 근거: 위 두 커맨드의 실제 출력. 대안으로 `while IFS= read -r f` 루프도 같은 12개를 냈다.

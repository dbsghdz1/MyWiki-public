# 앱인토스 미니앱

기존 Vite+React 웹을 토스 앱 안 미니앱으로 내는 절차와, 공식 문서가 안 알려주는 것들. 문서 진입점은 `https://developers-apps-in-toss.toss.im/llms.txt`(전체 목록) — 개별 `.html` 주소는 404가 잦고 **`.md` 주소가 산다**(예: `/documentation/common/monetization/iap/in-app-purchase.md`).

## 핵심 정리

- **패키지**: `@apps-in-toss/web-framework`(3.7.0, 2026-10-01). 설치하면 `npx ait` CLI(`@apps-in-toss/cli`)가 따라온다. 명령은 `ait build`(→ `<appName>.ait` 번들 + deploymentId) · `ait token add` · `ait deploy [--profile]` · `ait migrate`(2.x→3.x). **React 19에서도 설치·빌드된다**(peerDependencies 없음). 문서의 `@toss/tds-mobile`은 react 18 peer라 안 깔았다 — 미니앱 내비바는 토스 컨테이너가 그리므로 TDS 없이도 된다.
- **설정 파일 이름**: 문서는 `granite.config.ts`라고 하는데 CLI 3.x는 `apps-in-toss.config.ts`를 우선 읽는다(둘 다 인식, CLI 소스에 두 이름 공존). `defineConfig`는 `@apps-in-toss/web-framework/config`에서. 필드: `appName`(딥링크 `intoss://<appName>`·콘솔 이름과 일치) · `brand.primaryColor` · `permissions: []` · `navigationBar{withBackButton,withHomeButton,withTitle,theme}` · `webView{bounces,pullToRefreshEnabled,…}` · `webBundleDir`(vite `dist`).
- **토스 안인지 판별**: SDK가 `window.ReactNativeWebView`·`window.__appsInToss`(`__appsInTossConstants`)를 본다. 일반 브라우저에는 브리지가 없어 모든 네이티브 API가 실패하므로 **이 둘 유무로 분기**하고 바깥 경로를 따로 둔다.
- **인앱결제(IAP)**: `import { IAP } from '@apps-in-toss/web-framework'`. `IAP.createOneTimePurchaseOrder({ options: { sku, processProductGrant: ({orderId}) => boolean }, onEvent: ({type:'success', data:{orderId,…}}) => …, onError })` — **반환값이 cleanup 함수이고 흐름이 끝나면 반드시 호출**. `productId`는 deprecated, `sku`를 쓴다. 지급 완료 보고는 `IAP.completeProductGrant({ params: { orderId } })`. 복원은 `IAP.getPendingOrders()`(결제됐는데 지급 안 된 것)와 `IAP.getCompletedOrRefundedOrders()`(status `COMPLETED|REFUNDED`, 페이지네이션 `hasNext/nextKey`). 각 함수에 `isSupported()`와 `MIN_TOSS_APP_VERSION`(5.219~5.233)이 붙어 있다. 서버 검증은 `POST https://apps-in-toss-api.toss.im/api-partner/v1/apps-in-toss/order/get-order-status`(mTLS 인증서 필요).
- **수수료·가격**: 앱마켓 15% + 토스 5% = **20%**. 상품은 콘솔에서 등록 — 비소모성/소모성/구독, **공급가 400~1,400,000원(10원 단위)**, 판매가 = 공급가 + VAT 자동. 비게임 미니앱은 상품 30개 한도. 1024×1024 상품 이미지 필수. 실물·서비스는 토스페이(`checkoutPayment`), 디지털 콘텐츠·권한은 IAP.
- **검수 요건(비게임)** 중 걸리기 쉬운 것: **라이트 테마 구현 필수**, 진입 즉시 바텀시트 금지, 외부 도메인으로 리다이렉트·외부 콘텐츠 렌더 금지, **CSR·SSG만(SSR 불가)**, `eval` 금지, 제스처 줌 비활성(`user-scalable=no`), 자체 서비스 홍보·앱 설치 링크 금지(→ 토스 안에서는 App Store 링크를 숨겼다), UX 카피는 해요체. 사업자 정보 + 정산 정보 등록 검토 2~3영업일, 앱 검수 2~3영업일.
- **테스트**: 샌드박스 앱(iOS 시뮬레이터 드래그 설치 / Android APK)에서 `intoss://<appName>` 입력. IAP는 샌드박스에서 과금 없이 되고, 검수에 ①정상 구매 ②성공-지급 실패-복원 ③오류 처리 세 시나리오를 요구한다.

- **콘솔 MCP가 있다** (2026-10-02 확인): 공식 플러그인 `toss/apps-in-toss-harness` — `claude plugin marketplace add toss/apps-in-toss-harness` → `claude plugin install ait@apps-in-toss` → 세션에서 `/mcp`로 `apps-in-toss-console` OAuth. 문서 검색·미니앱 생성·**콘솔 등록·배포 준비·정책 점검**을 AI가 한다. 플러그인은 세션 시작 때 로드되므로 설치 뒤 새 세션. 수동 연결은 `claude mcp add --transport http apps-in-toss-console https://mcp.toss.im/adapters/apps-in-toss-console/mcp --client-id mcp-gateway`.

### 2026-10-02 — 최초 검토 반려 2건 + 앱 로고 반려 → 수정 재제출 (hangeom-predict, 번들 20261002-3)

맥락: [예상 모의고사 웹 판매](../../%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8/%EA%B0%9C%EC%9D%B8/%ED%95%9C%EB%8A%A5%EA%B2%80/%EC%98%88%EC%83%81%20%EB%AA%A8%EC%9D%98%EA%B3%A0%EC%82%AC%20%EC%9B%B9%20%ED%8C%90%EB%A7%A4%202026-10-01.md). 첫 제출(01:57) → 반려(02:07, **10분 — AI 검수로 보인다**) → 수정 재제출(02:21, reviewRequestId `226469`).

- **반려 1 "공통 내비게이션 바에 브랜드 로고가 표시되지 않거나 콘솔 앱 정보와 상이"** — ⚠️ 아래 `brand.icon` 처방은 **틀렸다**(같은 사유로 재반려, 다음 항목 참고). 당시 원인 추정: `apps-in-toss.config.ts`의 `brand`에 `primaryColor`만 있었다. SDK 3.x `AppsInTossConfig` 타입은 `brand: { primaryColor }`뿐이고 `ait migrate`도 "brand에서 primaryColor 외는 지운다"고 하지만, **호스트는 bundle.json의 `config.brand.icon`·`displayName`을 내비바 로고·이름으로 읽는다**(승인된 두뇌 풀가동의 `granite.config.ts`가 둘 다 갖고 있었고, 2.x 튜토리얼 `ai-vibe-coding/tutorials/webview.md`도 "콘솔에서 업로드한 이미지 URL을 icon에"라고 한다). 수정: 타입 밖 필드라 `const brand = {...}`로 만들어 넘겼다 — CLI는 `primaryColor`만 검사하고 나머지는 bundle.json에 그대로 통과(빌드 뒤 `unzip -p x.ait bundle.json`으로 확인). icon URL은 콘솔 앱 정보의 로고 `<img src>`(`static.toss.im/appsintoss/<ws>/live-managed-v1-….png`) — **`miniapp_get`은 최초 승인 전엔 iconUri를 빈 값으로 주므로** Aside로 DOM에서 읽었다. 로고를 바꾸면 URL도 바뀌니 config도 다시 맞춰야 한다.
- **반려 2 "내비바 뒤로가기와 자체 헤더 뒤로가기가 함께 노출"** — `Quiz.tsx`의 `Top`(← 목록)·결과 화면(← 다른 회차)·`Paywall.tsx`(← 목록으로)·에러 화면 링크를 `inToss()`면 숨겼다. 토스 내비바 `withBackButton: true`가 해시 라우팅의 history를 되돌린다.
- **앱 정보 반려 "로고 배경에 투명색 불가, 둥근 모서리 불가, 브랜드 컬러 또는 흰색 배경"** — PIL `rounded_rectangle` + RGBA로 만든 600×600이 걸렸다. **정사각 단색(#191f28) RGB**로 다시 만들어 콘솔 로고 교체(Aside) → 새 URL을 config `brand.icon`에 → 재빌드. IAP 상품 이미지(1024)도 같은 규칙으로 바꿨다.
- **IAP 상품 등록 — `iap_product_create_inspection`은 호출 즉시 APPROVED**(비동기 심사 아님). `postInspectionStatus: 'ACTIVE'`로 바로 판매 가능. **productId는 자동 발급이라 코드의 SKU를 지정할 수 없다** — `ait.0000081529.0fbc910d.74383be499.0875112092`(1회분·소모성·900→990) / `ait.0000081529.93629862.85b9dbe7f5.0875113848`(전체·비소모성·2,640→2,904). `src/config.ts`의 `SKU_ONE/ALL`을 이 값으로 바꾸고 토스 안 표시가는 `TOSS_PRICE_*`(2,904는 웹 송금가 2,900과 4원 다름). **공급가는 10원 단위**라 2,636 → 2,640. 이미지는 `image_upload_url` → PUT → uploadId를 `iconImgUrl`에.
- **IAP 선행조건은 Aside로**: 약관(「앱인토스 디지털콘텐츠 위탁매매 약관」) 동의는 콘솔 웹에서 OWNER가 체크 — Aside가 했다. 거래처·정산 정보는 **워크스페이스 단위라 두뇌 풀가동 때 등록한 사업자·정산 정보가 그대로 쓰인다** — 새로 안 넣었다. 정산 계좌 변경은 계좌번호 직접 입력 + 통장 사본 업로드를 요구하니 바꾸려면 홍이 직접.
- **Aside 지뢰**: 같은 콘솔 탭을 두 세션이 쓰면 화면이 서로 바뀌어 한쪽이 멈춘다(IAP 세션이 "앱 출시 화면으로 자꾸 바뀐다"며 중단). 콘솔 작업은 **세션 하나를 resume**해서 순서대로 시키는 게 안전하다. `(로컬 경로)` 경로 파일은 접근 거부, 세션 tmp 폴더로 복사하면 된다(확인됨).
- 상태 확인 체인: `review_list`(reviewRequestId·status) → `miniapp_meta_status`(앱 정보 reviewState·rejectedMessage) → `bundle_list`(번들 reviewReason). 번들 반려 사유는 `bundle_list[].reviewReason`, 앱 정보 반려 사유는 `miniapp_meta_status.rejectedMessage`에 따로 온다.

### 2026-10-02 — 내비바 로고 반려 재발: SDK 3.x는 `brand.icon`이 안 먹는다 → `withTitle: false` (번들 20261002-4)

- 원인: **SDK 3.x 마이그레이션 문서(`/documentation/integration/sdk-3.x.md`)가 `brand`에서 `displayName`·`icon`을 삭제했다고 명시**한다 — 3.x 호스트는 bundle.json의 brand.icon을 읽지 않는다. 승인된 두뇌 풀가동은 **SDK 2.x(RN 번들 `bundle.ios.0_84_0.js` + `web/appsintoss-logo.png`를 .ait에 동봉)**라서 config의 icon이 먹었던 것. 2.x 예시를 3.x에 그대로 옮긴 게 실수였다.

- 재제출: 번들 `20261002-4`(deploymentId `01a0f88a-f5b7-782f-bdf0-154e27bbbfbd`), 02:4x. 출시 뒤 앱 정보가 승인되면 `withTitle: true`로 되돌려 로고를 다시 띄울지 확인할 것.

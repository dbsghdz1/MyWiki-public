# LLM 콘텐츠 생산 파이프라인

에이전트로 대량 텍스트 콘텐츠(요약·해설)를 만들 때의 구조와 밟은 함정. 한능검에서 요약 노트 154 topic + 해설 1,742문항을 하루에 생산·검증했다.

## 핵심 정리

- **재료를 원문으로 한정하고, 검증기를 먼저 만든다.** 에이전트 프롬프트에 "기출에 나온 사실만"을 박고, 병합 스크립트가 형식·정합·복제를 기계로 막는다. 사람 검수는 표본만.
- **원문 복제 검사는 필수** — 에이전트는 자연스럽게 선지 문장을 베낀다(1차 초안에서 회차당 20~117건). 전수 대조 검증기 + 에이전트 자체 부분 문자열 검사 이중으로.
- **재료를 자르면 안 된다** — 토큰 아끼려 자료를 600자에서 잘랐더니 <보기> 조합형 문항의 ㄷ·ㄹ 문장이 사라져 해설이 추정으로 흘렀고, 한 에이전트는 **정답이 틀렸다고 의심**하기까지 했다. 정답은 답지 대조 100%였고 잘못은 잘린 자료였다. 10문항 재작성.
- **정답은 원전(답지)이 진실이다** — 에이전트가 "연대상 안 맞는다"고 하면 특정이 틀린 것부터 의심한다(61-29: (라)를 제왕운기로 잘못 특정 → 실제 발해고).

## 기록

### 2026-09-04 — 새 문항 250개를 만들 때: 생성보다 검증, 검증 중에서도 블라인드 풀이가 결함을 잡았다
- 맥락: [[프로젝트/개인/한능검/README|한능검]] 2.2.0 AI 예상 모의고사 5회분([[프로젝트/개인/한능검/AI 예상 모의고사 2026-09-04|기록]]). 기출 교정(원문이 있는 작업)과 달리 **정답이 없는 창작**이라 검증 구조를 새로 짰다.
- 배운 것:
  - **슬롯을 통계로 먼저 고정한다.** 번호별 시대·주제 빈도로 50슬롯을 만들어 주면 에이전트는 "무엇을"이 아니라 "어떻게"만 고민한다. 배점 합 100, 시대 안 연대순 같은 형식 제약도 슬롯 단계에서 끝낸다.
  - **재료 한정 + 12자 복제 검사**는 이번에도 필수였다 — 세트당 25~30건이 기출 문장을 베꼈고 검사기가 전부 잡았다. 반면 재료에 있는 사실도 틀릴 수 있다(기출 해설이 "대성동 고분군 금동관"이라 써 놓음) — 풀이자가 잡았다.
  - **블라인드 풀이(정답을 뗀 사본을 다른 에이전트가 푼다)가 유일하게 "정답이 둘"을 잡았다.** 300문항 중 정답 불일치는 0이었지만 low 확신 2건이 실제 결함(시기 조건을 만족하는 오답, 한정어 빠진 오답). 정답 일치율만 보면 놓친다 — **low·doubt 필드를 반드시 받아 읽는다.**
  - **작성 에이전트는 정답 위치를 규칙적으로 놓는다**(세트 4는 ①→⑤ 순환, 다른 세트는 12개씩 딱 맞춤). 내보낼 때 균형 셔플 + 해설의 원문자 재매핑이 필요하고, 연표형((가)~(마))은 섞으면 안 된다.
  - **병렬 에이전트는 같은 주제를 같은 자료 형식으로 쓴다**(세트 2·4·5가 똑같은 김규식 인물 카드). 3-gram Jaccard ≥0.4로 세트 간 중복을 걸러 예비로 대체하거나 다시 쓴다. 구조 중복(문장은 다르지만 같은 네 기관 비교)은 n-gram이 못 잡으니 자신 없는 문항 보고를 읽어야 한다.
  - **판정을 손으로 고치면 재현이 깨진다.** verdict를 직접 pass로 바꿨더니 compare 재실행 때 되돌아가 엉뚱한 예비로 대체됐다. 수정은 원천(풀이 파일의 confidence·doubt)에 하고, 대체 규칙은 "같은 주제 예비만"으로 못 박는다.
  - 병렬 에이전트가 **공용 스크래치패드의 스크립트 파일을 서로 덮어썼다** — 에이전트별 하위 폴더를 쓰게 하거나 파일명을 고유하게.
- 근거: `(로컬 경로)`, `data/predict/{SPEC.md,slots.json,gen,solve,verdict}`. 결함 2건: set-1 slot 1, set-2 slot 22.

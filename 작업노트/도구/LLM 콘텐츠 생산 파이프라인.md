# LLM 콘텐츠 생산 파이프라인

에이전트로 대량 텍스트 콘텐츠(요약·해설)를 만들 때의 구조와 밟은 함정. 한능검에서 요약 노트 154 topic + 해설 1,742문항을 하루에 생산·검증했다.

## 핵심 정리

- **재료를 원문으로 한정하고, 검증기를 먼저 만든다.** 에이전트 프롬프트에 "기출에 나온 사실만"을 박고, 병합 스크립트가 형식·정합·복제를 기계로 막는다. 사람 검수는 표본만.
- **원문 복제 검사는 필수** — 에이전트는 자연스럽게 선지 문장을 베낀다(1차 초안에서 회차당 20~117건). 전수 대조 검증기 + 에이전트 자체 부분 문자열 검사 이중으로.
- **재료를 자르면 안 된다** — 토큰 아끼려 자료를 600자에서 잘랐더니 <보기> 조합형 문항의 ㄷ·ㄹ 문장이 사라져 해설이 추정으로 흘렀고, 한 에이전트는 **정답이 틀렸다고 의심**하기까지 했다. 정답은 답지 대조 100%였고 잘못은 잘린 자료였다. 10문항 재작성.
- **정답은 원전(답지)이 진실이다** — 에이전트가 "연대상 안 맞는다"고 하면 특정이 틀린 것부터 의심한다(61-29: (라)를 제왕운기로 잘못 특정 → 실제 발해고).

# Claude 아티팩트 공개 배포

**아티팩트는 Claude 계정이 없는 사람에게 못 보여준다.** 외부에 공유할 페이지면 처음부터 정적 호스팅으로 만들고, 이때 **아티팩트가 자동으로 씌워주던 문서 뼈대를 직접 붙여야 한다** — 안 붙이면 모바일에서 페이지 전체가 축소돼 나온다.

## 핵심 정리

- **공유를 켜도 뷰어에게 claude.ai 로그인을 요구한다.** 선물·고객 전달처럼 상대가 계정이 없는 경우 아티팩트는 배포 수단이 아니다. 이걸 모르고 끝까지 만들면 마지막에 통째로 옮겨야 한다.
- **아티팩트는 publish 시 `<!doctype html>` + `<head>`(charset·viewport meta·리셋 CSS) + `<body>`를 자동으로 씌운다.** 그래서 아티팩트용 파일에는 그 태그들이 없다. **같은 파일을 Vercel 등에 그대로 올리면 `<meta name="viewport">`가 없어 브라우저가 980px 가상 뷰포트로 렌더링하고 전체를 축소한다** — 증상은 "폰에서 화면 절반 폭의 좁은 기둥으로 나온다". 정적 호스팅용 빌드에서는 직접 붙인다:
  ```html
  <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
  ```
- **`assets` capability가 없는 계정에서는 미디어를 `data:` URI로 인라인할 수밖에 없다.** 렌더 페이지 상한 16MB에 **base64가 원본을 약 33% 부풀리므로 실질 예산은 원본 12MB**다. `Artifact` 도구의 `upload_asset`은 페이지가 `assets`를 선언해야 동작하는데, 이 capability가 로스터에 없으면 쓸 수 없다 — `artifact-capabilities` 스킬이 계정별 사용 가능 목록을 알려준다.
- **인라인 data URI는 첫 화면까지 전부 받아야 뜬다.** 정적 호스팅으로 옮기면 미디어를 개별 파일로 분리할 수 있고, HTML이 수십 KB로 줄어 첫 화면이 즉시 뜬다. 브라우저 캐시도 파일 단위로 걸린다. **같은 소스에서 인라인/파일 두 벌을 뽑도록 빌드 스크립트를 짜두면** 아티팩트로 미리보고 정적 호스팅으로 내보내는 흐름이 된다.
- **아티팩트 삭제는 도구로 못 한다.** `Artifact` 액션에 delete가 없다. 사용자가 `/artifacts`(터미널) 또는 claude.ai/code/artifacts에서 직접 지워야 한다. 공유를 켠 채로 두면 링크를 가진 사람이 계속 볼 수 있다.

## 기록

### 2026-09-10 — 아티팩트로 다 만들고 나서 "로그인해야 보인다"를 발견해 Vercel로 옮겼다

- 맥락: 외부에 링크 하나로 전달할 개인용 페이지(사진·영상·오디오 포함)를 아티팩트로 만들었다. 공유를 켠 뒤 상대가 열 수 없다는 것이 드러났다.
- 배운 것:
  - **로그인 요구**가 결정적 제약이었다. 대상이 Claude 사용자가 아니면 아티팩트는 최종 배포처가 될 수 없다. 요구사항을 받을 때 "누가 여는가"를 먼저 물었어야 했다.
  - Vercel로 옮긴 직후 **폰에서 화면 절반 폭으로 축소**돼 나왔다. 원인은 `viewport` 메타 누락 — 아티팩트 런타임이 씌워주던 것을 파일이 갖고 있지 않았다. 아티팩트에서 잘 보이던 페이지가 옮기자마자 깨지는 전형적인 자리다.
  - 인라인(11.7MB) → 파일 분리(HTML 30KB + 미디어 16MB)로 바꾸자 첫 화면 로딩이 사라졌다. **아티팩트 16MB 제한 때문에 조여둔 인코딩 설정을 옮긴 뒤에도 그대로 쓰고 있었던 것**이 화질 저하의 원인이었다 — 호스팅을 바꾸면 미디어 예산도 다시 잡아야 한다.
- 근거: `build.py`에 `--files` 플래그로 인라인/파일 분리 두 모드. 파일 모드에서만 doctype·head·og 태그를 조립.

### 2026-09-10 — 부모 `z-index`가 만든 쌓임 맥락 때문에 자식 클릭이 막혔다

- 맥락: 같은 페이지. 전체 화면을 덮는 투명 버튼(`.tap`, `z-index:3`)으로 좌우 탭 전환을 만들고, 카드 안의 요소 하나를 클릭 가능하게 하려 했다.
- 배운 것: **`.card { position:absolute; z-index:1 }`이 쌓임 맥락을 만들어, 그 안의 자식에 `z-index:5`를 줘도 카드 밖 형제인 `z-index:3` 위로 못 올라간다.** 자식 z-index는 부모 맥락 안에서만 의미가 있다. 해결은 **카드째 올리고 클릭은 통과시키는 것**:
  ```css
  .card.finale { z-index: 5; pointer-events: none; }
  .finale .candle { pointer-events: auto; }
  ```
  이러면 빈 곳의 탭은 아래 버튼으로 내려가고 특정 요소만 클릭을 받는다.
- 곁가지: 그래도 안 눌린다면 **히트 영역 크기**를 의심한다. 폭 30px짜리 요소는 손가락으로 못 맞춘다 — `::after`로 넓은 투명 판을 깔았다.

### 2026-09-10 — append 직후 클래스를 바꾸면 CSS transition이 생략된다

- 맥락: 같은 페이지. 글자를 한 자씩 `<span>`으로 붙이고 `setTimeout(..., 0)`으로 `.in` 클래스를 달아 페이드시키려 했다. 앞 문장(지연 600ms)은 정상인데 **지연 0인 것만 전환 없이 즉시 나타났다.**
- 배운 것: **요소를 삽입한 프레임 안에서 속성을 바꾸면 브라우저가 시작 상태를 한 번도 계산하지 않아 transition이 돌지 않는다.** 삽입 후 리플로우를 강제하거나 최소 지연을 준다.
  ```js
  el.appendChild(sp);
  void el.offsetWidth;        // 시작 상태를 계산하게 강제
  setTimeout(fn, Math.max(delay, 60));
  ```
- 곁가지: `animation`을 `none`으로 껐다가 다시 켜서 재생시킬 때도 같은 리플로우가 필요하다.

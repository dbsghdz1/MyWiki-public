# iOS 접근성 트리 공백

## 핵심 정리

- 보험찾개냥 iOS에서 **일부 화면은 접근성 트리가 통째로 빈다**(상태바 요소만 남음). XCTest 기반 도구(Maestro)의 텍스트 셀렉터·assert가 전부 실패하고, VoiceOver 사용자도 그 화면을 못 읽는다는 뜻이다.
- **자동화가 특정 화면에서만 "Element not found"를 내면 셀렉터를 고치기 전에 트리부터 덤프한다** — `maestro hierarchy`.

## 기록

### 2026-08-27 — 04c(직접 입력)에서 재현 (보험찾개냥 SSH-292 스크린샷 자동화)

- 온보딩·로그인·홈·04(업로드)까지는 트리가 정상인데 **04c 진입 직후부터 텍스트가 하나도 안 잡혔다.** `maestro hierarchy` 라이브 덤프로 확인 — 상태바 3개 요소뿐.
- 코드에는 `ExcludeSemantics`/`BlockSemantics` 없음. 04c는 병원 검색 오버레이(`hospital_search_field`, CompositedTransform/Overlay 계열)를 쓰는 화면이라 **오버레이 위젯이 의심 지점**이나 원인 미확정. 05(추출 확인)도 같은 위젯을 써서 같을 가능성.
- 영향: Maestro 텍스트 탭·assert 불가 → 좌표 탭만 남는데, 좌표 blind 체이닝은 화면 전환 검증이 없어 드리프트로 실패했다. 안드로이드는 adb(트리 무관) + 매 탭 스크린샷 검증으로 우회 성공.
- **접근성 버그로서 별도 티켓감** — 자동화 문제가 아니라 VoiceOver 사용자 문제다. (2026-08-27 기준 티켓 미생성)

### 2026-09-16 — 보험 등록 화면도 트리가 비어 있다 · iOS 시뮬레이터를 좌표로 모는 법

- 맥락: 보험찾개냥 SSH-568 PR에 붙일 마이페이지 스크린샷을 iOS 시뮬레이터에서 찍으려고 Mock 플레이버를 Maestro로 몰았다(시뮬레이터가 되기 시작한 경위는 [[작업노트/Flutter/Google ML Kit 텍스트 인식|ML Kit 09-16 항목]]).
- 배운 것:
  - **화면마다 다르다.** 온보딩·로그인·반려동물 등록에서는 글자 탭(`건너뛰기`·`카카오 로그인`·`강아지`·`다음`)이 먹었는데, **보험 등록 화면은 `maestro hierarchy`에 텍스트 노드가 하나도 안 올라온다** — 눈에 보이는 `선택해 주세요`조차 못 찾는다. 그 화면부터는 좌표로만 몬다.
  - **좌표는 안드로이드와 다르다.** 같은 폼인데 이름 칸이 안드로이드 34%, iOS 37%였다. 퍼센트를 그대로 옮기면 빗나가고, 빗나간 탭은 `COMPLETED`로 찍혀 **성공처럼 보인다.**
  - **한글 키보드가 하단 버튼을 덮는다.** 입력 뒤 `hideKeyboard` 없이 `다음`을 누르면 키보드가 그 자리를 가로채 화면이 안 넘어간다. 안드로이드에서는 안 겪은 함정이다.
  - **전환 직후 `assertVisible`은 이르게 판정된다.** `가입한 보험을 알려주세요`가 FAILED로 찍혔는데 스크린샷을 보니 **화면은 이미 넘어가 있었다.** 실패를 곧이곧대로 믿고 되돌리면 멀쩡한 흐름을 다시 짠다 — 실패하면 먼저 화면을 찍어 본다.
  - 다크 모드는 `xcrun simctl ui <udid> appearance dark|light`. 앱 재시작이 필요 없다.
  - Mock 로그인 계정은 비어 있어 마이페이지까지 5단계다 — 온보딩 건너뛰기 → 카카오 로그인 → 반려동물 등록(이름 좌표 탭 + `inputText` + 키보드 내리기 + 종류 + 다음) → 보험 등록(드롭다운·항목 전부 좌표) → 홈 우상단 프로필(`91%,8%`).
- 근거: 시도 5회의 단계별 스크린샷(세션 스크래치패드), `maestro hierarchy` 빈 출력, PR #145에 붙인 iOS 라이트·다크 2장.

# 드래그 편집 UI의 좌표계와 경계

사진 위에 박스를 얹어 **손으로 옮기고 크기를 바꾸게** 하는 UI에서 밟은 것들. 화면 좌표와 원본 좌표가 둘 다 살아 있을 때 생기는 함정이 대부분이다.

## 핵심 정리

- **표시 좌표 ↔ 원본 좌표는 「이미지를 배율 그대로의 크기로 놓으면」 곱하기 하나로 끝난다.** `BoxFit.contain`으로 큰 상자에 넣으면 레터박스 오프셋(가운데 정렬로 생기는 여백)을 따로 빼야 하는데, `SizedBox(width: imageW * scale, height: imageH * scale)` + `BoxFit.fill`로 놓으면 오프셋이 0이라 `rect * scale`만 하면 된다. 결과는 contain과 같다.
- **정본은 원본(이미지 픽셀) 좌표로 들고 있는다.** 화면 좌표를 state에 두면 회전·시트 높이 변화·키보드로 표시 크기가 바뀔 때마다 박스가 어긋난다.
- **화면 단위 상수를 원본 좌표로 옮기면 배율의 역수만큼 커진다.** 24 논리px짜리 손잡이가 3024×4032 사진을 폭 350에 그릴 때(배율 ≈0.116) **원본 좌표로 229px**이 된다. 이걸 「최소 크기」 하한으로 그대로 쓰면, 그보다 얇은 대상(주민번호 한 줄 ≈135px)에서 **하한이 상한보다 커진다.**
- **`num.clamp`는 `upper < lower`면 `ArgumentError`를 던진다.** `(5.0).clamp(0.0, -3.0)` → throw. `min`/`max`와 달리 조용히 접어 주지 않는다.
- **제스처 콜백에서 던진 예외는 `GestureRecognizer.invokeCallback`이 삼킨다.** 앱이 죽지 않고 **그 조작만 조용히 안 먹는다** — 디버그 콘솔에만 에러가 쌓인다. 그래서 `onPanUpdate` 안의 예외는 「크래시」가 아니라 「이 핸들이 왜 안 움직이지」로 나타난다. 매 프레임 불리는 코드라 한 번 던지기 시작하면 계속 던진다.
- **최소 크기의 하한은 `min(요구 최소, 현재 크기)`로 잡는다.** 목적이 「더 줄지 않게」이므로 이미 그보다 얇은 변은 현재 크기가 하한이면 충분하고, 그러면 경계가 구조적으로 뒤집히지 않는다. 억지로 키우면 사용자가 잡아 둔 자리를 코드가 덮어 버린다.
- **`initState`에는 배율이 없다.** 표시 크기는 `LayoutBuilder` 안에서야 정해진다 — 화면 기준 상수를 initState의 보정에 쓰면 작은 이미지에서 박스를 부풀린다. 초기 보정은 **경계 안으로 넣는 것까지만** 하고 최소 크기는 배율을 아는 쪽에 맡긴다.
- **`Stack(clipBehavior: Clip.none)`은 그리기만 허용하고 히트 테스트는 부모 size 밖으로 안 나간다.** 모서리 손잡이를 박스 꼭짓점 중심에 놓아 절반이 Stack 밖으로 걸치면, **걸친 만큼은 눌리지 않는다**(가장자리에서 24×24가 실질 12×12, 꼭짓점에선 그 1/4).
- **모달 바텀시트의 `backgroundColor`는 `showModalBottomSheet` 호출 시점에 고정된다.** 시트가 떠 있는 동안 라이트↔다크를 바꾸면 **배경은 옛 테마, 본문 글자색은 새 테마**가 되어 글자가 배경에 묻는다. 실사용에서는 여는 순간의 테마로 열리니 문제가 아니지만, **스크린샷을 찍을 때는 테마를 먼저 바꾸고 시트를 새로 열어야** 한다.
- **미리보기 높이를 「화면의 n%」로 고정하면 작은 기기에서 넘친다.** 사진 외 고정 높이(제목·본문·버튼)가 300 논리px쯤이면 화면 640 미만에서 `RenderFlex overflow`다. `Flexible` + `LayoutBuilder`의 `constraints.maxHeight`(유한할 때)를 반영해 사진이 줄어들게 한다.

- 맥락: 보험찾개냥에서 온디바이스 OCR의 실물 검출률이 낮아, 자동으로 찾은 검은 박스를 **사용자가 드래그·리사이즈로 맞추는** 시트를 만들었다. 순수 기하는 `Client/lib/ui/core/ui/mask_box_geometry.dart`로 떼어 유닛 테스트했다.
- **AI 리뷰가 P1로 잡은 것**이 위 「화면 단위 상수 → 원본 좌표」 + 「`num.clamp` 예외」 조합이다. 내 코드에서 `maskBoxMoved`·`maskBoxClamped`는 `math.max`로 하한을 막아 뒀는데 **`maskBoxResized`만 빠져** 있었다. 재현: 얇은 박스를 사진 위쪽 끝에 붙이면 `bottom - minSide < 0` → 위쪽 손잡이가 조용히 먹통. 고친 방식은 하한을 `min(minSide, 현재 변)`으로 바꾸고 `_clamp`가 뒤집힌 경계를 접게 한 것(커밋 `9180893`).
- **테스트가 못 잡은 이유가 분명했다** — 유닛 테스트는 `minSide=8`·박스 40×20, 위젯 테스트는 40×30 사진을 24배로 띄워 `minSide`가 1px이었다. **`minSide > 박스 변` 조합이 0건**이라 통과했다. 실기기 해상도(수천 px)와 테스트 해상도(수십 px)의 배율 차이가 그대로 사각지대였다.
- 임시 파일: OCR이 던지는 경로에서 「바로 세운 중간본」이 캐시에 남았다 — **실패한 쪽이 치워야 한다**(호출자는 성공해야 경로를 받으므로 지울 수단이 없다).

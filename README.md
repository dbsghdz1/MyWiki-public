# MyWiki

에이전트가 관리하고 사람이 검수하는 개인 지식 베이스입니다. Markdown 파일이 지식 베이스, Obsidian이 탐색 화면, LLM 에이전트가 위키 관리자 역할을 합니다.

이 저장소는 **비공개 볼트에서 공개 가능한 부분만 스크립트로 추출한 스냅샷**입니다. 원본에는 금융·일정·구직 활동처럼 공개하지 않는 영역이 함께 들어 있고, 허용목록에 등록된 경로만 여기로 넘어옵니다.

## 무엇을 볼 수 있나

| 폴더 | 내용 |
|---|---|
| [`AGENTS.md`](AGENTS.md) | 에이전트가 따르는 운영 스키마. 이 위키의 실제 설계 문서입니다 — 디렉터리 소유권, 절대 규칙, 수집·연동·질의·검사 4개 오퍼레이션 |
| [`공부/`](공부/) | 사람(홍)이 다시 읽고 이해를 쌓는 1인칭 학습 노트. 날짜별 파일을 만들지 않고 주제 파일에 append합니다 |
| [`작업노트/`](작업노트/) | AI 에이전트가 작업하며 알게 된 것을 다음 작업의 에이전트를 위해 남기는 경험 노트. API명·에러 메시지·커밋 해시 같은 검색 키를 그대로 보존합니다 |

## 이 위키가 지키는 규칙

문서 자체보다 **규칙**이 이 저장소의 핵심입니다. 전문은 [`AGENTS.md`](AGENTS.md)에 있고, 요약하면:

- **원본과 종합을 구분한다.** 수집한 원본은 `_wiki/Sources/`에 그대로 보존하고 수정하지 않습니다. 위키 페이지는 원본을 링크로 참조합니다.
- **틀린 원본도 지우지 않는다.** 조용히 덮어쓰는 대신 위키 쪽에서 무엇이 틀렸는지 설명합니다.
- **충돌은 감춘다 대신 나란히 둔다.** 출처끼리 어긋나면 한쪽을 고르지 않고 `근거 충돌` 경고 블록으로 양쪽을 남깁니다.
- **파일을 늘리기보다 허브를 두껍게 한다.** 개념마다 새 페이지를 파지 않고 기존 주제 허브를 갱신합니다.
- **배운 것은 양방향으로 연결한다.** 학습 노트는 맥락이 된 프로젝트를 링크하고, 프로젝트 README의 `배운 것` 섹션은 학습 노트를 링크합니다. 한쪽만 있으면 미완성으로 봅니다.
- **변하는 주장에는 기준일을 붙인다.** 버전·가격·성능처럼 시간이 지나면 틀려지는 서술에는 `YYYY-MM-DD 기준`을 표기합니다.
- **주기적으로 검사한다.** 끊어진 링크, 고립 페이지, 출처 없는 주장, frontmatter와 본문의 불일치를 lint로 잡습니다.

## 왜 이렇게 만들었나

LLM에게 노트를 맡기면 흔히 두 가지가 무너집니다. 원본이 요약으로 덮어써지고, 페이지가 무한히 늘어나 서로 연결되지 않습니다. 그래서 **원본 보존**과 **허브 우선 갱신**을 절대 규칙으로 못 박고, 링크·출처·기준일을 검사로 강제했습니다. 실패 모드와 대응은 [`_wiki/LLM Wiki`](_wiki/LLM%20Wiki.md)에 정리했습니다.

## 공개 파이프라인

비공개 원본 볼트에서 이 저장소로 넘어오는 과정은 허용목록 기반입니다.

```
publish.allow (허용목록)  →  복사
publish.deny              →  예외 제거
frontmatter visibility    →  문서 단위 제외
<!-- private:start/end -->→  섹션 단위 제거
비공개 링크               →  언링크 (문서 존재 자체를 숨김)
deny-block                →  하나라도 걸리면 중단
deny-warn                 →  사람이 확인
```

허용목록 방식이라 **새로 만든 파일은 기본적으로 비공개**입니다. 공개하려면 명시적으로 등록해야 합니다.

# 공부

프로젝트·운영을 하면서 **내가 새로 이해하게 된 것**을 주제별로 쌓는 영역 허브다. `_wiki/`가 외부 출처(Sources)를 종합한 지식이라면, 공부는 실제 작업 경험에서 나온 1인칭 학습 노트다. CS든 프레임워크든 도구든, 배운 것은 전부 여기로 모인다.

## 원칙

1. **주제별 파일, 날짜별 항목 append.** 같은 주제로 배운 게 쌓이며 한 파일이 두꺼워지는 것이 목적이다. 날짜별 파일은 만들지 않는다.
2. **양방향 연결.** 공부 항목은 맥락이 된 프로젝트를 링크하고, 그 프로젝트 README의 `## 배운 것` 섹션은 공부 주제를 링크한다. 작업 기록 파일(`<주제> YYYY-MM-DD.md`)에도 `배운 것:` 한 줄로 공부 주제를 링크한다. 한쪽만 있으면 미완성이다.
3. **작업에 닿아 있어야 한다.** 근거는 커밋·파일·재현한 현상·실제 결정이다. 작업과 무관한 일반론을 옮겨 적지 않는다.
4. **CS 주제는 유명 레퍼런스를 붙인다.** 자료구조·알고리즘, OS, 네트워크, DB, 언어 런타임·컴파일러, 분산 시스템, 보안 등 CS 주제 파일에는 `## 참고 자료`에 널리 인정되는 자료(교과서, 공식 문서, RFC, 대학 강의, 널리 인용되는 글) 2~4개를 **URL을 실제로 확인한 뒤** 첨부하고 `YYYY-MM-DD 확인`을 표기한다. 확인 못 한 링크는 넣지 않는다.
5. **`_wiki` 승격.** 한 주제가 외부 출처 여럿을 종합할 만큼 커지면 `_wiki/`에 주제 허브를 만들고 공부 파일에서 링크한다. 공부 파일은 그대로 남긴다.

## 파일 규칙

- 경로: `공부/<주제>.md`. 주제명은 검색 가능한 명사구 (예: `Swift 동시성.md`, `HTTP 캐싱.md`, `Git 내부 구조.md`). 분야별 하위 폴더는 파일이 30개를 넘으면 그때 만든다.
- frontmatter:

```yaml
---
type: study
area: CS | 언어·프레임워크 | 도구·인프라 | 개발 방법
status: active | stale
created: YYYY-MM-DD
updated: YYYY-MM-DD
projects:
  - "[[프로젝트/개인/<이름>/README|<이름>]]"
---
```

- 본문 구조:

```markdown
# <주제>

한 줄 요약 — 현재 시점의 내 이해.

## 핵심 정리
누적된 이해를 갱신하는 살아있는 요약. 기록이 쌓이면 여기를 고쳐 쓴다.

## 기록
### YYYY-MM-DD — 제목
- 맥락: [[프로젝트/개인/<이름>/README|<이름>]]에서 무엇을 하다가
- 배운 것: 결론 먼저 1~3불릿
- 근거: 커밋 / 파일 / 재현 / 외부 링크

## 참고 자료
- [제목](URL) — 왜 볼 만한지 한 줄 (YYYY-MM-DD 확인)
```

- **계획 중인 주제**는 `## 학습 계획` 섹션에 웹 학습 체크리스트(주차·자료·범위·완료 기준)를 둔다. 완료한 항목은 체크하고 배운 것을 `## 기록`으로 옮긴다.
- [[공부/미분류|공부/미분류.md]]: 주제가 아직 애매한 항목을 임시로 두는 곳. "공부 미분류 정리해줘"로 주제 파일에 옮기고 원 항목은 삭제한다 (append-only 아님).
- 프로젝트 README의 `## 배운 것` 섹션: 첫 기록 시 만든다. `- [[공부/<주제>|<주제>]] — 이 프로젝트에서 배운 요점 한 줄` 형식의 목록.

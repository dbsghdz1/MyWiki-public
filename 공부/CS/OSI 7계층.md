# OSI 7계층

네트워크 통신을 7개 계층으로 나눈 참조 모델. 실제 인터넷은 TCP/IP 4~5계층으로 돌아가지만, "이 문제가 어느 계층 문제인가"를 말하는 공용 언어로 쓰인다. [[공부/CS/네트워크|네트워크]]의 출발점.

## 핵심 정리

### OSI 7계층 ↔ TCP/IP 4계층 대응표 (2026-08-21, 네트워크 강의 44강)

| OSI | TCP/IP 4계층 | 역할 | 대표 프로토콜 | PDU |
|---|---|---|---|---|
| 7 애플리케이션 | 애플리케이션 | 앱이 네트워크와 통신하게 해주는 프로토콜 집합 | HTTP, SMTP, FTP, SSH | 메시지 |
| 6 프레젠테이션 | 〃 | 데이터 인코딩/디코딩, 암호화 | — | 메시지 |
| 5 세션 | 〃 | 통신 세션 관리 | — | 메시지 |
| 4 전송 | 전송 | 데이터를 쪼개고 오류 없이 순서대로 전달 | TCP, UDP | 세그먼트(TCP) / 데이터그램(UDP) |
| 3 네트워크 | **인터넷** | 노드→노드로 패킷화해 목적지까지 전달, 주소·라우팅 | IP, ICMP, ARP | 패킷 |
| 2 데이터링크 | 링크 | MAC 주소 기반 인접 전달 + 오류 검출 | Ethernet | 프레임 (헤더 + FCS 트레일러) |
| 1 물리 | 〃 | 전기·광 신호로 실제 전송 | — | 비트 |

- **두 모델의 차이는 딱 세 가지다.** ① OSI가 애플리케이션 계층을 셋(애플리케이션·프레젠테이션·세션)으로 쪼갠다 ② OSI가 링크 계층을 데이터링크·물리로 쪼갠다 ③ TCP/IP의 "인터넷 계층"을 OSI는 "네트워크 계층"이라 부른다. 나머지는 같은 것을 다르게 자른 것뿐이다.
- **표의 세로 순서 = 캡슐화 순서다.** 내려갈수록 헤더가 하나씩 더 붙고(메시지→세그먼트→패킷→프레임→비트), 수신 측에서는 역순으로 벗겨진다. **트레일러가 붙는 건 데이터링크 계층뿐**(FCS).
- **PDU 이름을 정확히 부르는 실익**: "프레임 문제"라고 말하는 순간 MAC 주소와 FCS를, "패킷 문제"라고 말하는 순간 IP 헤더를 열어보게 된다. 전부 "패킷"이라 부르면 이 지시가 사라진다.
- 아직 못 채운 것 — **계층별 네트워크 장치**(리피터·허브·브리지·스위치·라우터)는 [[공부/CS/네트워크|네트워크]] W3-1(77~82강)에서 채운다.

## 기록

### 2026-08-21 — 44강으로 대응표를 채웠다

- 맥락: [[공부/CS/네트워크|네트워크]] W1-2(44강 「TCP/IP 4계층 #1. 캡슐화, 비캡슐화, PDU, OSI 7계층」). 계획대로 별도 주차 없이 여기서 함께 다뤘다.
- 배운 것:
  - **OSI를 먼저 배우고 TCP/IP를 배우는 순서가 오히려 헷갈린다.** 실제 인터넷은 TCP/IP 4계층으로 돌고, OSI는 그것을 더 잘게 쪼갠 참조 모델이다 — 4계층을 기준으로 놓고 "애플리케이션이 셋, 링크가 둘로 갈라진 것"으로 외우는 게 맞다.
  - **프레젠테이션·세션 계층은 TCP/IP에는 대응하는 별도 계층이 없다.** 인코딩/암호화와 세션 관리는 실제로는 애플리케이션 계층 프로토콜이 알아서 한다. OSI에만 있는 칸이라는 걸 알고 있어야 면접에서 "그래서 실무에선 어디 있나요"에 답할 수 있다.
  - 각 계층의 PDU 이름이 곧 캡슐화 단계다 — 자세한 건 [[공부/CS/네트워크#핵심 정리|네트워크 핵심 정리]].
- 근거: 교안 「CS - 네트워크」 pp.34~38 (OSI 7계층 절 p.38, PDU p.37)

# 유튜브 임베드 판정

특정 영상을 **내 페이지에 임베드해도 되는지**를 API 키 없이 확인하는 법. 영상 소유자는 임베드를 막을 수 있고, 막힌 영상을 IFrame에 넣으면 재생 자리에 오류만 뜬다.

## 핵심 정리

| 방법 | 임베드 판정 | 비고 |
|---|---|---|
| Data API `status.embeddable` | 정확 | **API 키 필요**, 할당량 소모 |
| `/embed/<id>` 페이지의 `embedded_player_response` | **정확** | 키 불필요. 아래 참조 |
| `youtube.com/oembed` HTTP 상태 | ❌ **쓸 수 없다** | 사실상 *영상 존재* 판정 |

## 기록

### 2026-08-27 — oEmbed 200은 임베드 허용이 아니다, 그리고 "전부 OK"는 검증이 아니다

- 맥락: [[프로젝트/개인/한능검/README|한능검]] 앱의 유일한 차별점이 *문항 → 유튜브 강의 연결*이라, 강의 채널이 임베드를 허용하는지가 착수 게이트였다. API 키 없이 200개를 확인해야 했다.
- 배운 것:
  1. **`youtube.com/oembed?url=...&format=json`의 HTTP 상태로 임베드 여부를 판정하면 안 된다.** 처음에 이걸로 60개를 재보니 **전부 200**이었다. oEmbed는 *영상이 존재하고 메타데이터를 줄 수 있는가*에 가깝지, 소유자가 임베드를 막았는지를 반영하지 않는다. "401이면 임베드 차단"이라는 통설이 있지만 그대로 믿을 게 못 된다.
  2. **판정 근거는 `/embed/<id>` 페이지 안에 있다.** HTML에 `"embedded_player_response":"{...}"`가 **JSON 문자열로 이스케이프되어** 박혀 있고, 두 번 파싱하면 구조체가 나온다.
     - `videoFlags.playableInEmbed` ← 임베드 허용 여부(불리언). **이게 결론이다**
     - `previewPlayabilityStatus.playableInEmbed` / `.status` (`OK`·`UNPLAYABLE`·`ERROR`)
     - `embedPreview.thumbnailPreviewRenderer.title` / `.videoDurationSeconds` ← 제목·길이도 같이 나온다
  3. **`playabilityStatus`를 HTML에서 직접 grep하면 안 나온다.** 시청 페이지(`/watch`)와 달리 embed 페이지는 그 키가 `embedded_player_response` **안쪽**에 있다. 겉에서 찾다 "구조가 바뀌었나" 하고 헤맸다.
  4. **"검사한 200개가 전부 OK"는 그 자체로는 아무 검증도 아니다.** *항상 OK만 뱉는 고장 난 판정기*도 똑같은 결과를 낸다. 그래서 **차단 사례(대조군)를 먼저 확보**했다 — 일본 음반사 채널 24개 중 6개가 `UNPLAYABLE`로 잡히는 걸 확인한 뒤에야 본 검사 결과를 신뢰했다. 국내 방송사(SBS·KBS·MBC·JTBC) 27개는 전부 허용이라 대조군이 못 된다.
  5. 수집 요령: 채널 `/videos`·`/playlist?list=` 페이지 HTML에서 `"videoId":"([\w-]{11})"`로 ID를 긁으면 된다. **재생목록 페이지는 한 번에 100개까지만** 준다(그 이상은 continuation 토큰 필요). 브라우저 User-Agent를 안 주면 응답이 달라진다.
  6. 검사는 **병렬로 돌려야 한다** — 순차로 60개에 2분이 넘어 타임아웃이 났다. `xargs -P 10`으로 충분하다.
- 부수 소득: 임베드 여부만 보려던 검사에서 **강의가 이미 주제 단위로 분절되어 있다**는 걸 제목으로 알게 됐다. 매핑 설계가 *구간 찍기(영상+시작·끝 초)*에서 *영상 고르기*로 바뀌었다. **가용성 조사가 설계를 바꾼 사례다.**
- 근거: `(로컬 경로)`, 결과 `data/youtube/*.tsv`(200개). 정리는 [[프로젝트/개인/한능검/유튜브 임베드 실측 2026-08-27|유튜브 임베드 실측]].

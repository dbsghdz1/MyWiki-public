# 오픈소스 기여

남이 운영하는 코드베이스를 읽고, 그 프로젝트의 규칙 안에서 변경을 제출하는 연습. 첫 대상은 **당근 SEED Design**(`daangn/seed-design`) — 지원하려는 회사의 디자인 시스템이라 코드 읽기 자체가 지원 준비이고, 머지된 PR은 이력서에 쓸 수 있는 근거가 된다.

> [!important] 2026-08-20 — 시작을 **2026-09-22(W6)로 연기**했다 (본인 결정)
> 08-16에 하루 1시간 슬롯으로 신설했지만 **08-18~08-19 이틀 연속 실행 0회**였고, 같은 기간 공부·MyCryptoDiary·이력서 슬롯도 전부 미체크였다. 슬롯이 안 굴러간 게 아니라 **총량이 넘친 것**이다(하루 학습 2시간 + MyCryptoDiary 매일 + 소마 + 알바 주 2일, 실질 휴식 0일).
> 그래서 이 슬롯을 **가장 먼저 덜어낸다.** D-day(2026-11-14)에 직접 걸리는 건 이력서와 MyCryptoDiary이고, 오픈소스 기여는 "있으면 좋은 것"이지 없으면 지원을 못 하는 게 아니다.
> **재개: 2026-09-22 (주간 2026-09-22, W6).** 그때까지 이 파일의 학습 계획은 실행하지 않고, 일간·주간 루틴도 `오픈소스:` 항목을 만들지 않는다.

## 왜 하는가

2026-08-16 학습 계획 2차 재편에서 코테 비중을 주 1회로 줄이는 대신 별도 슬롯으로 신설했다([[공부/README|공부]] 학습 계획). 당근 윈터테크(D-day 2026-11-14) 지원에 "코테 얇게 + 기여 실적"으로 방향을 잡은 결정이다. 프론트 관심사([[공부/JS/Feature-Sliced Design|FSD]], [[공부/JS/JavaScript 모듈 시스템|JS 모듈 시스템]])와도 겹친다. 조사(아래)는 이미 끝나 있으므로 재개할 때 바로 1단계부터 들어가면 된다.

## SEED Design 사전 조사 (2026-08-16, `gh api`로 확인)

- 저장소 `daangn/seed-design`, 기본 브랜치 **`dev`**, Apache-2.0, ★1,048, 마지막 push 2026-08-15 — 활발하다.
- 스택: **Bun** 워크스페이스(npm/yarn 금지), React, TypeScript, bunchee·vite 빌드, Next.js + Fumadocs 문서, Storybook, **Biome** 린트/포맷, changeset.
- 파이프라인 (`TECH.md`): `[Figma] → rootage YAML(토큰) → qvism-preset(recipe) → css(vars/recipes 생성물) → react`. `packages/css/vars/`, `packages/css/recipes/`, `packages/qvism-preset/src/vars/`는 **생성물이라 직접 수정 금지** — 원천 고치고 `bun generate:all`.
- `packages/`: react, react-headless, css, design-token, stylesheet, cli, codemod, mcp, docs-mcp, figma, stackflow, tailwind3-plugin, tailwind4-theme, vite/webpack/rsbuild 플러그인, lynx-* 등 26개. `ecosystem/`: rootage, qvism, figma-extractor, postcss-*.
- 기여 가이드 (`CONTRIBUTING.md`): **오타·문서 보완·버그 픽스는 바로 PR**. 새 컴포넌트·공개 API 변경·새 패키지·외부 의존성 추가는 **이슈로 먼저 논의**. 커밋·PR 제목은 영어 Conventional Commits(`feat(button): add loading state`). 코드 주석 금지(꼭 필요하면 한국어). 유저 향 변경엔 changeset(`/changeset` 스킬).
- 셋업: `bun install → bun ecosystem:build → bun install(다시) → bun generate:all → bun packages:build`. install을 두 번 하는 이유는 ecosystem CLI 빌드 후 워크스페이스 bin 링크를 걸기 위해서 — 이 링크 없으면 `generate:all`이 조용히 다른 CLI를 써서 생성물이 갱신되지 않는다.
- 이슈·라벨: `good first issue` 같은 진입용 라벨이 **없다**(라벨은 `release:*` 3개뿐). 열린 이슈도 거의 없고 열린 PR이 65개 — 내부 팀이 PR 중심으로 움직인다. 즉 **이슈를 골라 잡는 방식이 아니라, 코드를 읽다가 발견한 문서·타입·a11y·테스트 결함을 직접 PR로 내는 방식**이어야 한다.
- 레포에 `AGENTS.md`, `CLAUDE.md`, `.claude/skills`(`create-component`, `changeset`)가 있다 — Claude Code로 작업하는 흐름을 이미 지원한다.

## 학습 계획 (2026-09-22 시작, 2026-08-20 재배치)

**읽기 → 작은 PR → 반복.** 완료하면 체크하고 배운 것을 `## 기록`으로 옮긴다.

> [!warning] 재개 시점에 강도를 먼저 정할 것
> 원안은 "화~토 매일 1시간"이었고 그대로 두었다. 그런데 재개 시점(09-22)은 커리어 로드맵 **Phase 2 후반~Phase 3 마감**과 겹쳐 MyCryptoDiary 최적화·이력서 v2가 동시에 도는 구간이다. **08-16에 실패한 것과 같은 총량 배치를 반복하지 않으려면, 09-22 주간을 세울 때 주 2~3회(예: 화·토)로 낮출지 먼저 판단한다.** 매일 1시간을 기본값으로 두지 않는다.

> [!note] 남는 시간이 7주뿐이다 — 기대치를 낮춰 잡는다
> 09-22 시작이면 D-day(11-14)까지 약 7주다. 현실적 산출은 **머지된 PR 1~2건**이지, 원래 3단계에 적었던 "주 1개 PR" 실적이 아니다. 이력서에는 "기여 실적"이 아니라 **"지원 회사 코드베이스를 읽고 PR을 냈다"** 수준으로 쓸 것을 전제한다.

### 1단계 — 코드 읽기 (W6~W7, 2026-09-22 ~ 10-05)
- [ ] fork + clone(`dev` 브랜치), 위 셋업 절차대로 빌드 성공. `bun docs:dev`·`bun storybook` 띄우기. 막힌 지점은 그 자체가 첫 문서 PR 후보
- [ ] `TECH.md`·`AGENTS.md`·`skills/create-component` 정독 → 파이프라인 그림을 내 말로 다시 그리기(핵심 정리 ①)
- [ ] 컴포넌트 하나(예: Button)를 rootage YAML → qvism recipe → css → react-headless → react 순으로 끝까지 따라가기. 각 층에서 무엇이 결정되는지 표
- [ ] `packages/react-headless` 구조 파악 — 접근성·상태 로직이 어떻게 스타일과 분리돼 있는지. [[공부/JS/Feature-Sliced Design|FSD]]의 public API 관점과 비교
- [ ] 최근 머지된 PR 20개 훑기 — 어떤 변경이 받아들여지는지, 리뷰에서 뭘 지적하는지 패턴 기록

### 2단계 — 첫 PR (W8~W9, 2026-10-06 ~ 10-19)
- [ ] 읽는 중 발견한 오타·문서 불일치·타입 개선 중 하나로 **첫 PR** (Conventional Commits, changeset 여부 판단)
- [ ] 리뷰 코멘트에 대응해 머지까지. 리뷰에서 배운 것을 `## 기록`에
- [ ] 두 번째 PR 후보: 테스트 보강 또는 a11y (`TECH.md` 테스트 규칙 — 생성기 출력은 전체 일치 단언, 네트워크 금지 — 준수)

### 3단계 — 지속 (W10~, 2026-10-20 ~)
- [ ] 두 번째 PR 또는 이슈 논의 참여. 컴포넌트·API 변경급은 이슈 먼저
- [ ] W11(10-27)까지 낸 PR 목록(머지 여부 포함)을 이력서 항목으로 정리 → 취업 운영
- [ ] W12(11-03)부터는 새로 벌이지 않는다 — 지원 자료 마감이 우선

# 블루투스 기기 배터리 읽기

맥에 붙은 마우스·키보드의 잔량을 읽는 길은 **하나가 아니라 둘**이고, 어느 쪽인지는 기기가 클래식 Bluetooth냐 BLE냐가 가른다. IORegistry만 보면 절반(매직 계열)밖에 못 본다.

## 핵심 정리

- **클래식 BT HID(매직 마우스·키보드·트랙패드)는 IORegistry에 잔량이 올라온다.** 커널 드라이버가 HID 배터리 usage를 파싱해 `BatteryPercent` 프로퍼티로 노출한다. `AppleDeviceManagementHIDEventService`(애플 매직 기기)와 `IOHIDDevice`를 `IOServiceGetMatchingServices`로 훑으면 권한 없이 읽힌다 — [[공부/Apple/macOS 메뉴바와 샌드박스|샌드박스도 IORegistry는 막지 않는다]].
- **BLE HID는 IORegistry에 잔량이 아예 없다.** BLE 기기는 GATT **Battery Service `0x180F`** / **Battery Level 캐릭터리스틱 `0x2A19`** 로 잔량을 노출하고, 이걸 읽는 주체는 커널이 아니라 유저스페이스의 `bluetoothd`다. 그래서 Control Center에는 뜨는데 IORegistry에는 안 올라온다. **전체 ioreg 덤프에 `BatteryPercent` 키가 0개인데 Control Center엔 잔량이 보이는 상황**이 바로 이 경우다.
- **기기가 어느 쪽인지 판정하는 가장 빠른 명령은 `hidutil list`다.** Transport 열이 `Bluetooth Low Energy`면 BLE고, 클래스도 `AppleUserHIDEventService` / `IOHIDUserDevice`로 뜬다(클래식은 `AppleDeviceManagementHIDEventService`). `system_profiler SPBluetoothDataType`의 `Services: < BLE >`도 같은 신호.
- **BLE 잔량은 CoreBluetooth로 직접 읽는다. 스캔은 필요 없다.** `retrieveConnectedPeripherals(withServices: [CBUUID("180F")])`가 **이미 시스템에 붙어 있는** 기기를 광고 대기 없이 즉시 돌려준다. 이후 `connect` → `discoverServices` → `discoverCharacteristics` → `readValue`. 값은 1바이트 정수 퍼센트다. HID 링크와 별개인 GATT 링크가 열리므로 읽고 바로 `cancelPeripheralConnection` 한다.
- **대가는 권한이다.** 샌드박스면 `com.apple.security.device.bluetooth` entitlement + Info.plist `NSBluetoothAlwaysUsageDescription`이 필요하고, **TCC 프롬프트는 `CBCentralManager`를 생성하는 순간 뜬다.** 즉 프롬프트 시점은 인스턴스 생성 시점을 미루는 것으로 통제할 수 있다 — 기능을 실제로 쓸 사용자에게만 물어보게 만들 수 있다.
- **"기기가 있는지"는 권한 없이도 알 수 있다.** 잔량은 없어도 `AppleUserHIDEventService`의 `Product`·`Transport`는 IORegistry에서 그냥 읽힌다. 그래서 "권한을 물어볼 가치가 있는 상황인가"를 프롬프트 없이 먼저 판단할 수 있다.
- **`NSBluetoothAlwaysUsageDescription`은 시스템이 읽는 문자열이라 런타임 로컬라이제이션이 안 통한다.** 코드로 언어를 고르는 수동 L10n 구조에서는 이 키만 언어를 못 따라간다 — 한국어 시스템에 영문 프롬프트가 뜬다. 언어별로 내려면 `InfoPlist.strings`(.lproj)를 따로 둬야 한다. [[공부/Apple/WidgetKit과 AppIntents|AppIntents 문구가 컴파일 타임 리터럴만 받는 것]]과 같은 종류의 제약이다.
- **AirPods는 제3의 길이다 — 연결 중일 때만 IORegistry에 좌·우·케이스로 나뉘어 올라온다.** (2026-08-26 수정: 이전에 "이 길로도 안 된다"고 적었는데 절반만 맞았다.) GATT 0x180F를 광고하지 않아 CoreBluetooth로는 못 읽지만, **맥에 연결되어 있는 동안**은 `BatteryPercentLeft`/`BatteryPercentRight`/`BatteryPercentCase` 키가 IORegistry에 올라온다(`ioreg -k BatteryPercentLeft`로 확인 가능). 매직 기기와 같은 경로라 권한·샌드박스 문제 없음. 연결이 끊기면(아이폰으로 넘어가면) 키가 사라진다. 노드 클래스가 불명확하면 매칭 딕셔너리에 **`IOPropertyExistsMatch`**(macOS 12+)를 넣으면 클래스 무관으로 해당 키를 가진 노드만 잡힌다 — `IOServiceGetMatchingServices`에 `["IOPropertyExistsMatch": "BatteryPercentLeft"]`.
- **Apple Watch는 정말로 길이 없다.** 맥에는 잠금 해제용 세션만 붙는다 — 페어링돼 있어도 `system_profiler SPBluetoothDataType`에 주소만 노출되고 배터리 필드가 없으며(실측 2026-08-26), IORegistry·GATT 어디에도 잔량이 안 올라온다. 워치 배터리를 보여주는 맥 앱들은 아이폰 컴패니언 앱을 경유하는 구조다.
- **TCC 부여 여부는 화면 없이 확인할 수 있다**: `sqlite3 (로컬 경로) Support/com.apple.TCC/TCC.db "select service, client, auth_value from access where client like '%<번들ID 일부>%'"` → `kTCCServiceBluetoothAlways|<번들ID>|2`면 허용(2). (읽으려면 터미널에 전체 디스크 접근 권한이 있어야 한다.)

## 기록

### 2026-08-22 — Zappy 주변기기 배터리가 매직 기기만 잡던 이유
- 맥락: [[프로젝트/개인/Zappy/README|Zappy]] 1.9.0의 "주변기기 배터리"(Zappy+)가 사용자 맥에서 아무것도 안 보였다. 붙어 있던 건 Rainy 75 키보드와 로지텍 마우스 둘.
- 원인: 두 기기 다 **BLE**였다. 구현은 IORegistry `BatteryPercent`만 봤고, BLE 기기는 그 키를 아예 안 갖는다. 코드 버그가 아니라 탐지 경로가 절반만 커버한 것.
- 배운 것: 위 핵심 정리 전부. 특히 **"Control Center엔 보이는데 내 코드엔 안 보인다"가 곧 유저스페이스(bluetoothd) 경로라는 신호**라는 점, 그리고 프롬프트 시점을 `CBCentralManager` 생성 시점으로 통제해 무료 사용자에겐 권한을 아예 안 묻게 만들 수 있다는 점.
- 근거: 전체 `ioreg -l` 덤프 54,073줄에 `BatteryPercent` 0개. `hidutil list`에서 두 기기 모두 Transport `Bluetooth Low Energy` / `AppleUserHIDEventService`. CoreBluetooth 프로브로 `retrieveConnectedPeripherals(180F)` 2개 → Rainy 75-1 76%, 로지텍(B031) 90% 읽기 성공. 구현 커밋 `969d623`(`Sources/CuteBattery/Peripherals.swift`의 `BLEBatteryMonitor`), 서명 샌드박스 빌드에서 프롬프트 확인 후 TCC `auth_value=2`. 작업 기록 [[프로젝트/개인/Zappy/Zappy 개발 기록 2026-08-22|Zappy 개발 기록 2026-08-22]].

### 2026-08-26 — AirPods는 되고 Watch는 안 되는 이유
- 맥락: [[프로젝트/개인/Zappy/README|Zappy]] 1.11.0에 "에어팟·워치 배터리도 보여달라"는 요청. 1.9 때 "AirPods 불가" 판정을 재검증했다.
- 알아낸 것: AirPods는 연결 중 IORegistry에 `BatteryPercentLeft/Right/Case`로 올라온다(위 핵심 정리 수정). Watch는 어느 경로에도 없다.
- 근거: `IOPropertyExistsMatch` 매칭 메커니즘은 `IOPlatformUUID` 키로 실측 확인(노드 2개 검출). 단 **에어팟 실기기 값 표시는 배포 시점까지 미검증** — 에어팟이 맥에 연결된 적이 없었고 사용자가 검증 생략을 선택했다. 구현 커밋 `1de8b75`(`ioregSplitBatteries`). 작업 기록 [[프로젝트/개인/Zappy/Zappy 개발 기록 2026-08-26]].

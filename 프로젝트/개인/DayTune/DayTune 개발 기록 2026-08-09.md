# DayTune 개발 기록 2026-08-09

2026-08-05~09 Claude 세션에서 진행한 Figma 디자인 재건축과 앱 코어 플로우 구현 기록. 출처: Claude 대화, 2026-08-09.

## 결정

- **Figma 전면 재건축 (2026-08-07)**: 기존 13개 화면이 전부 절대좌표 배치라 정렬이 계속 어긋났다(카드 밖으로 나온 디바이더, 탭바에 깔린 콘텐츠, 좌우 비대칭 마진). 부분 수정을 반복하다가 톤·컬러만 유지하고 "DayTune 2.0" 페이지에 오토레이아웃 + 로컬 컴포넌트(StatusBar·NavHeader·Button·TabBar 4-variant)로 처음부터 다시 지었다. 이후 Page 1의 구버전 10개를 재건축 클론으로 교체.
- **스크롤 화면은 프레임을 늘린다**: 콘텐츠가 852pt에 안 들어가면 구겨 넣지 말고 프레임을 920~960pt로 — 사용자 명시 요청("화면이 긴거면 모바일 화면이 길어야").
- **디자인 확정 후 코드 반영 순서**: "디자인 깎아줘"는 Figma 편집 요청이다. 코드부터 구현했다가 지적받았다 (메모리 `hong-figma-design-preferences`에도 기록).
- **HealthKit 리포지토리는 던지지 않는다**: 개별 조회 실패·데이터 없음은 nil로 반환하고 도메인 분석기가 missingMetrics로 처리. 시뮬레이터(데이터 없음)에서도 홈이 "주의 상태 + 안내 문구"로 자연스럽게 렌더됨을 확인.
- **도메인 카피 한국어화**: RecommendationEngine의 영문 하드코딩 카피를 `String(localized:defaultValue:)`(ko 기본값)로 교체. Foundation만 쓰므로 도메인 레이어 규칙 위반 아님. 카탈로그에 키가 없어도 defaultValue로 폴백되므로 xcstrings 일괄 수기 등록은 생략.

## 교훈

- **절대좌표 Figma는 에이전트 편집에 취약**: 요소를 옮길 때마다 연쇄 어긋남이 생기고 감사 스크립트로 잡아도 끝이 없다. 오토레이아웃 재건축이 부분 수정 누적보다 빨랐다.
- **UIView로 원형 링을 만들면 cornerRadius 필수**: border만 주면 사각형으로 렌더된다. 시뮬레이터 스크린샷 검증에서 발견 — 코드 리뷰만으론 놓쳤을 버그.
- **시뮬레이터는 UI 탭 자동화가 안 된다** (simctl에 tap 없음): 플로우 중간 화면 검증은 `#if DEBUG` 런치 아규먼트 훅(`-daytune.showAnalyzing`)으로 해결. 전환 애니메이션까지 자연 검증됨.
- **빌드 전 SourceKit 진단은 무시**: Tuist 프로젝트에서 새 파일은 `tuist generate` 전까지 "No such module 'UIKit'" 노이즈를 뿜는다. 실제 판정은 xcodebuild.
- **긴 한국어 카피는 레이아웃 제약과 함께 설계**: 계획 카드 헤드라인이 orb에 밀려 3줄로 깨짐 → 폰트 22pt + 줄당 ≤8자로 카피 재작성이 제약 수정보다 나은 해법이었다.

### 배포 단계 교훈 (추가)

- **ASC 앱 레코드는 공개 API로 생성 불가**: bundle ID·프로비저닝 프로파일은 `-allowProvisioningUpdates` + API 키로 자동 등록되지만, 앱 레코드는 사용자가 ASC 웹에서 만들어야 한다. 에이전트가 할 수 있는 건 아카이브 검증까지 → 사용자 액션 → 폴링 후 업로드.
- **레코드 생성 실패의 흔한 원인 2가지**: ① 앱 이름 선점(에러 메시지가 눈에 안 띔) ② ASC 계정에 팀이 여럿일 때 다른 팀이 선택된 상태 — 이 경우 번들 ID 드롭다운에 대상 ID가 아예 안 뜬다. 사용자에게 "앱 목록에 기존 앱(Zappy 등)이 같이 보이는지"로 팀을 확인시키는 게 빠르다.
- **폴링 모니터는 API 일시 오류를 견디게**: 1분 폴링 중 빈 응답 5연속으로 스크립트가 종료됐다(네트워크/토큰 순간 이슈 추정, 직후 수동 호출은 정상). 실패 임계값을 더 높이거나 종료 대신 경고만 내는 게 낫다.

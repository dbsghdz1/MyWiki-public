# Zappy 개발 기록 2026-09-01 — 리텐션 P0: 체험형 온보딩 + 알림 권한 지연 (1.13.0)

## 배경 — 리텐션 정의를 바꿨다

홍이 가져온 리텐션 분석(1.12.0 코드 기준)의 핵심: **Zappy의 리텐션은 앱을 다시 여는 횟수가 아니라 다음 로그인에도 메뉴바에 살아 있는 상태**다. 그래서 재방문 알림·새 기능보다 *첫 체험 → 자동 실행 → 메뉴바 정착*을 먼저 고친다. 코드로 확인된 이탈 지점 5개가 전부 맞았다:

1. 온보딩이 설명 3행(테마는 메뉴에서 고르라는 텍스트) — 체험 없음
2. `applicationDidFinishLaunching`에서 `requestAuthorization` 즉시 호출 — 가치 보기 전 권한 팝업
3. `onboarded = true`를 `Onboarding.show()` **직전에** 저장 — 바로 닫으면 영영 재안내 없음, 메뉴 재진입 경로도 없음
4. 자동 실행이 80% 알림·% 표시와 같은 줄의 일반 설정
5. 시작 버튼 = 창 닫기 — Dock 창 없는 앱이라 제품이 사라진 것처럼 느껴짐

**하지 않기로 한 것**(분석 그대로 채택): 재방문 알림·주간 리포트 푸시·출석 보상·자동 테마 변경·원격 분석 SDK. 제품이 먼저 말을 거는 건 온보딩 1회와 사용자가 직접 켠 배터리 알림뿐.

## 구현 (P0 다섯 가지)

### 1. 온보딩 완료 분리 + 재진입 (`Onboarding.isDone`, `App.swift`)
- `onboarded`는 **시작 버튼(`startTapped`)에서만** 기록. 창을 띄우는 것만으로는 기록하지 않는다 → 중간에 닫으면 다음 실행에 다시 뜬다
- 메뉴 하단(정보 위)에 항목 하나: 미완료면 **"설정 마치기…"**, 완료면 **"사용 안내…"** — 같은 `onboardingItem`, `update()`에서 제목만 바꾼다
- 기존 사용자(≤1.12)는 `onboarded=true`가 이미 있어 새 온보딩이 자동으로 뜨지 않는다 — "사용 안내…"로만 접근. 업데이트 팝업을 안 만든다는 원칙과 일치

### 2. 알림 권한 지연 (`Notifications.swift` 신설)
- 시작 시 요청 제거. 두 경로에서만 묻는다:
  - `askAfterUserChoice()` — 메뉴에서 80% 알림·완충 알림·저전력 기준(>0)을 **켠 직후**. `notDetermined`면 NSAlert 사전 문구("선택한 배터리 상태를 알려드리려면 알림 허용이 필요합니다.") → 계속 → 시스템 프롬프트. `denied`면 설정(`x-apple.systempreferences:com.apple.Notifications-Settings.extension`)으로 안내. 허용 상태면 아무것도 안 띄움
  - `deliver(content)` — 실제 발송 시점. **저전력 알림이 기본 20%로 켜져 있어** 새 사용자는 아무것도 안 켜도 첫 발송이 온다. 이때 `notDetermined`면 시스템 프롬프트만(사전 알럿 없음 — 작업 중 모달을 겹치지 않기 위해) 띄우고 허용되면 바로 보낸다. 3곳(`checkLowBattery`·`checkFullCharge`·`checkChargeLimit`)의 `UNUserNotificationCenter.add`를 이걸로 교체
- 결정: 저전력 기본값 20%는 유지(스토어 설명이 광고하는 기능). 대신 권한을 "첫 발송 순간"으로 미룬다 — 앱 시작 팝업보다 맥락이 있다

### 3. 체험형 온보딩 ①페이지 (`Onboarding.swift` 전면 재작성, 460×560)
- **지금 잔량의 캐릭터를 5배(175×110)로** — 코드 드로잉이라 확대해도 선명(README 결정 4의 회수 사례 하나 더). 메뉴바와 같은 규칙(`AppDelegate.icon` → 모노 템플릿이면 `ThemeGridView.tinted`로 라벨 색 착색)
- **슬라이더 10→100**, 초기값 = 실제 잔량, 라벨 "배터리 N% · 지금". 충전 씬은 섞지 않는다(방전 변화를 보여주는 게 목적)
- **무료 테마 8종 카드** — `ThemeGridView(freeOnly: true)`: 기존 메뉴 그리드를 재사용하되 Zappy+ 캡션·잠긴 카드·데모 루프를 뺐다. 고르면 `selectTheme` → 메뉴바 아이콘·미리보기 즉시 반영. **페이월은 열리지 않는다**(무료만 진열하므로 경로 자체가 없음)

### 4. 자동 실행 승격 ②페이지
- 제목 "Zappy는 메뉴 막대에서 실행됩니다" / "앱 창을 닫아도 캐릭터와 배터리 알림은 계속 동작합니다."
- **메뉴 막대 모형**(`MenubarMockView`): 와이파이·[고른 캐릭터, 강조 테두리]·시스템 배터리·9:41 — 어디에 앉는지 보여준다
- 체크박스 "Mac을 켤 때 Zappy 자동 실행" **기본 체크**, 등록은 시작 버튼에서 체크 상태대로만 (`register`/`unregister`는 현재 상태와 다를 때만). 동의 없이 강제 등록 없음. 중간에 닫으면 아무것도 등록되지 않는다
- 기본 배터리 숨기기는 보조 행으로 유지(메뉴바 정착에 필요)

### 5. 시작 직후 메뉴 1회 열기 (`onboardingFinished` → `openMenu`)
- 스크린샷 자동화(`openMenuOnLaunch`)에서 쓰던 좌표 지정 `popUp`을 `openMenu()`로 빼서 공유. 창 닫고 0.4초 뒤 활성화 + popUp. `performClick`은 비활성 상태에서 불안정(08-25 실측)이라 그대로 popUp 방식

## 검증
- `swift build`(package-app.sh) + `xcodebuild -project Zappy.xcodeproj` Debug **BUILD SUCCEEDED**, 경고 없음
- `-onboarded NO -renderShots`로 `onboarding.png`·`onboarding-2.png` 렌더 확인(두 페이지 스냅으로 확장). 실행 시 `-onboarded NO`는 argument domain이라 실제 설정을 안 건드리고 온보딩을 강제할 수 있다
- 라이브 실행 크래시 없음. `screencapture`는 화면 기록 권한이 없어 검정 — 실기 확인은 렌더 스트립으로
- 미검증(실기 클릭 필요): 시작 → 메뉴 popUp 연결, 알림 사전 알럿 → 시스템 프롬프트 흐름. 개발 빌드에서 시작을 누르면 **무서명 dev 번들이 로그인 항목으로 등록**되므로 테스트 후 `SMAppService` 해제 필요

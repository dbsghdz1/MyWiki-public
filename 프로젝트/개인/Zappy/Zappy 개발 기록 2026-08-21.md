# Zappy 개발 기록 2026-08-21

**새 캐릭터 선인장 + 1.8.0 제출.** "새로운 캐릭터 하나 만들어볼까"로 시작해 반나절 안에 그리기 → 메뉴바 실기 확인 → 1.8.0(build 14) 제출까지 갔다. 1.7.0은 제출 다음 날 이미 **승인·출시(READY_FOR_SALE)** 돼 있었다 — `asc state`로 확인하기 전까지 위키는 "심사 대기"였다.

## 결정 — 왜 선인장인가

로드맵에 이월돼 있던 후보는 커피잔·해파리(07-28). 선인장을 고른 이유: 기존 14종과 **실루엣·문법이 겹치지 않는다**. 커피잔은 소다와 같은 "채움" 계열이고, 선인장은 "생기(vitality)" 문법 — 역도·로봇의 활력형과 눈사람의 변형형 사이의 새 자리다. Zappy+ 7번째 모션 테마로 배치(`paidMenuOrder` 끝).

## 문법 (코드 `CactusGeom` 기준)

- **잔량 = 생기**, 전부 연속값: 몸통 높이 `7.2 + 4.0t`·폭 `5.8 + 1.8t`, 팔 꺾임 `-3 + 6.5t`(만세 ↔ 축 처짐), 몸색 초록→올리브 보간
- 꽃: ≥70% 개화(5잎 + 꽃술) → ≥40% 봉오리 → 없음 → ≤20% **바닥에 떨어진 꽃잎 + 화분 금 + 몸통 주름 + 시무룩**
- **충전 = 물뿌리개 휴식 씬**(정지) — 눈 감고 `^ ^`
- **상시 모션(Zappy+)**: ≥70%에서 꽃 옆을 맴도는 벌(`phaseAmp`로 위아래 1.4pt)
- 모노: 골(세로 줄)·주름을 **생략** — knockout 선이 몸통을 조각내서 실루엣이 깨졌다. 생기는 팔 각도·꽃·금으로만 읽힌다. 봉오리는 몸통과 붙어 뾰족머리로 보여 밑선 knockout 0.5pt로 분리
- 캔버스 22 안에 꽃 포함 꼭대기 21.8 — 처음엔 화분이 너무 커서(높이 5.8) 선인장이 눌려 보였고, 화분을 4.3으로 낮추고 몸통을 키웠다

## 실기 확인에서 배운 것 (프로젝트 고유)

- `pkill -x Zappy`는 아무것도 안 죽인다 — 실행 파일명이 **`CuteBattery`** 다. 기존 인스턴스가 살아서 새 빌드가 안 뜬 것처럼 보였다. `pkill -x CuteBattery`
- `defaults write com.hong.zappy theme 선인장` 후 재실행해도 테마가 안 바뀌는 경우가 있었다(원인 미확정 — 컨테이너 plist에도 값은 들어갔다). **`-theme "선인장"` 인자 도메인이 확실**하다 → CLAUDE.md 플래그 목록에 추가
- `-forceCharging`은 YES만 강제할 수 있고 **언플러그는 강제 못 한다** — 전원 연결 중엔 메뉴바에서 비충전 모습을 못 본다. 비충전 모습은 렌더 스트립(`swiftc Themes.swift Mono.swift + main.swift`)으로 검증

"1.9.0 가즈아"로 이어졌다. 1.8.0은 **제출 약 10시간 만에 승인**(01:24 제출 → 11:42 `asc state` READY_FOR_SALE)돼 1.9.0을 바로 제출할 수 있었다.

### 해파리 (로드맵의 마지막 이월 후보)

- **잔량 = 부력**: 갓 밑변 높이 `4.2 + 8.8t`(모래 위 ↔ 만땅 13), 갓 폭·높이도 t에 비례, 촉수 길이 `3 + 5t`. 색은 보랏빛 분홍 → 회보라
- ≥50% 갓 둘레에 발광 halo(알파 = (t-0.5)×2×0.35) · ≤20% **모래 바닥에 주저앉고 촉수가 바깥으로 늘어짐** + 시무룩
- **상시 모션(>20%)**: 맥동 — `phaseAmp`로 갓 폭 +5%/높이 −7% 왕복, 촉수는 베지어 제어점을 `(pulse−0.5)×1.6`만큼 좌우로 흔들어 살랑임 (가닥마다 방향 교대)
- **충전 = 해저 휴식**(정지): 갓을 바닥 4.6에 내려놓고 촉수 2.0으로 짧게, 눈 감고 공기방울 3개
- 모노: 갓 하이라이트 knockout을 **생략** — 눈과 붙어 한 덩어리로 보였다(선인장 골 생략과 같은 이유: 모노는 실루엣 우선)
- 공통 기하 `JellyGeom(t:phase:charging:)` — 선인장 `CactusGeom`과 같은 패턴. 이제 "새 테마 = Geom 구조체 + drawX + monoX + 등록 7곳"이 정형화됐다

## 3부 — 캐릭터 대신 "실용" 축: 1.10.0 준비 (충전 습관 + 주변기기 배터리)

사용자: "새 캐릭터 대신 다른 아이디어가 나와야 할 것 같아." 제안 5개(주변기기 배터리 / 공유하기 / 단축어 / 충전 습관 / 팝오버 대시보드) 중 **1·4를 선택**. 두 기능 모두 Zappy+에만 얹는다(1.7 진단 "무료 티어는 두껍고 유료 가치가 캐릭터 수에만 의존" 연장선).

### 80% 충전 제한은 못 한다 (질문에 대한 답)

충전 중단은 SMC 쓰기(`CH0B/CH0C`, `CHWA`)라 root 헬퍼가 필요 → App Sandbox·스토어 심사 둘 다 불가(AlDente가 비스토어인 이유). 가능한 건 80% 알림(있음)과 "80% 이상 꽂아둔 시간"을 보여주는 것까지 — 그래서 습관 리포트의 첫 칸이 이것.

### 충전 습관 리포트 (`Shared.habits`)

- 데이터는 새로 안 모은다 — 1.7의 5분 간격 7일 기록 `[분, 잔량, 전원]`을 **구간 적분**. 연속 샘플 사이 시간을 앞 샘플 상태로 친다
- **함정**: 샘플은 전원 이벤트에서만 남아 100%로 꽂아둔 구간엔 몇 시간씩 공백이 있다. 공백 상한을 30분으로 잡으니 "완충 방치"가 거의 0이고 24시간도 못 채워 "—"만 떴다. 잔량이 1%만 바뀌어도 이벤트가 오므로 **긴 공백 = 상태 불변**이 맞고, 상한을 6시간으로 올려 해결. 충분 조건도 "적분 합 ≥ 24h"가 아니라 "첫~끝 샘플 폭 ≥ 24h"
- 지표 5개: 80% 이상 연결 시간 · 완충 상태 연결 시간 · 20% 이하 방전 횟수(전원 없이 진입한 횟수) · 충전 횟수(전원 연결 전이) · 이번 주 사이클(+N). 사이클은 이력이 없어서 **하루 1회 `cycleLog`에 스냅샷**을 새로 남긴다(8일 보관) — 내일부터 값이 생김
- 평가는 숫자 점수 대신 **3단계 한 줄**(좋음/무난/주의: 완충 방치 10h·30h, 방전 2회·5회 경계) — "텍스트는 담백하게" 원칙
- 실측(이 Mac, 08-21): 80%+ 연결 7시간 · 완충 6시간 · 20% 이하 1회 · 충전 2회 → 좋음

### 주변기기 배터리 (`Peripherals.swift`)

- IORegistry `AppleDeviceManagementHIDEventService`(Magic 기기) + `IOHIDDevice`의 `BatteryPercent` — 1.7 리포트와 같은 근거(샌드박스가 IORegistry 읽기를 안 막음), Bluetooth entitlement 불필요. 내장 키보드/트랙패드는 Transport FIFO/SPI·"Internal"로 제외
- **AirPods는 의도적으로 제외** — 공개 API 없음(`com.apple.Bluetooth.plist` DeviceCache는 현대 macOS에서 비어 있음, 271바이트 확인). 사설 IOBluetooth는 심사 위험
- 메뉴 `menuWillOpen`에서 매번 다시 읽어 잔량 줄 아래에 **현재 테마 캐릭터를 그 기기 잔량으로** 그린 행을 꽂는다. 기기 없으면 아무것도 안 보임. 미구매 + 기기 있음이면 자물쇠 한 줄(→ 페이월)
- **미검증**: 이 Mac엔 배터리를 보고하는 주변기기가 없다(Rainy 75 키보드는 미보고, AirPods 미연결). Magic 기기 연결 후 확인 필요 — 1.10.0 제출 전 체크리스트

## 4부 — 위젯 컬러→모노 깜빡임 수정 (`6a9ad80`)

사용자 제보: "위젯이 색상으로 나오다 갑자기 모노로 바뀐다 — 선택이 해제되면 의도한 거야?" 의도한 게 아니라 버그. 위젯 스타일 "앱 따라가기"와 무관하게, `refreshEntitlements()`가 `Transaction.currentEntitlements`의 **빈 결과**를 `plus=false`로 처리해 App Group에 쓰고 위젯을 리로드한 것이 원인. 빈 결과는 무시하고 `revocationDate`가 관측될 때만 내리도록 비대칭으로 고쳤다. 1.10.0(build 17)에 포함. 배운 것: [[공부/Apple/StoreKit 2 권리 확인|StoreKit 2 권리 확인]]

같은 대화에서 "BarStack은 샌드박스로 통과했는데 80% 충전 제한은 왜 안 되나" → BarStack이 받은 건 **TCC 권한**(화면 기록), 충전 제한은 **root 특권 헬퍼**(SMC 쓰기)라 층이 다르다. BarStack도 같은 이유로 AX 클릭 실행은 포기했다. 가능한 최대치는 "최적화된 배터리 충전이 80%에서 잡고 있음"을 읽기 전용으로 표시하는 것.

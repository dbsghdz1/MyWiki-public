# Zappy 개발 기록 2026-08-19

**1.7.0 개발 — Zappy+ 대폭 강화.** 1.6.1 핫픽스가 심사 대기 중인 상태에서, "유료 고객에게 더 많은 것을 주고 싶다"는 요구로 다음 버전을 만들었다. 커밋 `a791917` (아직 push·제출 안 함).

배운 것: [[공부/Apple/macOS 메뉴바와 샌드박스|macOS 메뉴바와 샌드박스]] · [[공부/Apple/WidgetKit과 AppIntents|WidgetKit과 AppIntents]]

## 왜 1.7인가 — 진단

Zappy+가 실제로 산 것은 **테마 6종 + 컬러 모드**뿐이고, 그 위의 약속은 [[프로젝트/개인/Zappy/Zappy 로드맵과 유료화 계획|로드맵]]의 시즌 테마 캘린더 하나였다. 1.6에서 추가한 위젯·충전 완료 연출·호버 하트는 **전부 무료 티어**여서, 큰 릴리즈를 하나 냈는데도 Zappy+의 가치는 제자리였다. 1.7은 여기에만 얹는다 — **무료 티어는 손대지 않는다**(이미 8종 + 전 기능이라 충분히 넓다).

후보 4개를 놓고 사용자가 셋을 골랐다: **데스크톱 펫 · 위젯 확장 · 배터리 리포트**. (시즌 테마 앞당기기는 로드맵대로 9월 착수로 남김.)

## 1. 데스크톱 펫

메뉴바 밖으로 캐릭터를 꺼낸다. `DesktopPet.swift` — borderless·투명 창에 기존 드로잉을 그대로 크게 다시 호출한다(`NSImage(size:flipped:drawingHandler:)`는 그릴 때마다 핸들러가 재호출되므로 7배로 키워도 벡터처럼 선명하다. 위젯이 쓰던 방식과 같음).

결정:
- **펫은 항상 컬러로 그린다.** 모노는 검정 실루엣이라 어두운 배경화면에서 사라진다. 메뉴바 설정(모노/컬러)을 따라가지 않는 유일한 표면.
- **"항상 위" 토글의 반대는 숨김이 아니라 배경화면 레벨**(`CGWindowLevelForKey(.desktopIconWindow) + 1`). 꺼두면 창 뒤로 들어가 벽지의 일부처럼 산다.
- 창 이동은 `isMovableByWindowBackground`로 공짜. 위치는 `windowDidMove`에서 저장하고, 저장된 좌표가 어느 화면과도 안 겹치면(외장 모니터 분리) 기본 위치로 되돌린다.
- **펫을 우클릭하면 상태 아이템 메뉴가 그대로 열린다** — 같은 `NSMenu` 인스턴스를 `view.menu`에 꽂았다. 펫을 끄는 길이 메뉴바에만 있으면 처음 켠 사람이 못 치운다. 같은 이유로 처음 켤 때 안내 알럿 1회(`petHintShown`), **펫이 화면에 나온 뒤에** 띄운다.

## 2. 배터리 리포트

`IOPSCopyPowerSourcesInfo`(기존)로는 잔량·남은 시간까지가 끝이라, 사이클 수·설계 용량·온도는 IORegistry의 `AppleSmartBattery`에서 직접 읽는다. **샌드박스에서 되는지가 기능의 성립 조건**이었고, 애드혹 서명 테스트로 먼저 확인한 뒤 착수했다 — 상세는 [[공부/Apple/macOS 메뉴바와 샌드박스|공부 노트]].

- 표시: 충전 사이클 / 최대 용량(%) / 완충 용량(mAh) / 온도 / 전력(W) / 남은 시간 + **최근 24시간 잔량 그래프**(충전 중이던 구간은 음영).
- 그래프 데이터는 앱이 `update()`마다 **5분에 한 번** App Group에 남기는 로컬 기록(`Shared.appendSample`). 7일 지나면 스스로 지운다. **App Group에 둔 이유는 위젯 스파크라인이 같은 데이터를 보기 때문.**
- 프라이버시 문구를 창 안에 직접 적었다 — "이 Mac에만 저장, 7일 후 삭제, 어디로도 전송 안 함". Data Not Collected 포지셔닝을 유지하는 기록이라 심사·리뷰 양쪽에 선제적으로 답한다.
- 배터리 없는 Mac(데스크톱)에서는 창 대신 안내 알럿(`BatteryReport.showOrExplain`).
- 개발자 플래그 `-renderShots`에 `report.png`를 추가했다 — 스토어 스크린샷에도 쓸 그림.

## 3. 위젯 확장

- **라지 사이즈 추가** + 24시간 스파크라인. 라지는 Zappy+ 전용(미구매 시 자물쇠 뷰).
- **테마 선택 위젯**(`ZappyThemeWidget`, `AppIntentConfiguration`, macOS 14+): 위젯마다 테마·스타일을 따로 고른다. `WidgetBundle` body에서 `if #available`로 조건부 포함해 배포 타깃(13.0)은 그대로 뒀다.
- 기존 small/medium 무료 위젯은 **그대로 둔다** — 이미 출시된 것을 유료로 되돌리지 않는다.
- 삽질: 인텐트 문구에 `L10n`을 쓰려다 빌드가 깨졌다(컴파일 타임 리터럴 요구). 영어 리터럴 + `Localizable.xcstrings` + `knownRegions`로 해결. 상세는 [[공부/Apple/WidgetKit과 AppIntents|공부 노트]].
- 함정 하나 더: 위젯 갤러리 미리보기는 `placeholder(in:)`로 그려지는데 여기 `plus: false`를 하드코딩해 두면 **구매자에게 갤러리에서 자물쇠가 보인다**. placeholder도 실제 구매 상태를 읽게 고쳤다.

## 불꽃 꼭대기 잘림 수정 (테스트 중 발견, 커밋 `ec67f4e`)

사용자가 1.7.0 개발 빌드를 실기 테스트하다 "불꽃 위쪽이 잘리는 것 같다"고 지적. 확인해보니 **원인이 두 개 겹쳐 있었다**.

1. **드로잉이 캔버스를 넘었다** — 100%에서 불꽃 끝이 `bottom 2.2 + fh 20.4 = 22.6`인데 캔버스는 22.
2. **`iconScale(.fire) = 1.15` 확대가 더 잘라냈다** — `scaledIcon`은 중앙 기준으로 키우고 넘치는 부분을 버린다. 그래서 **원본 좌표에서 실제로 보이는 위 끝은 22가 아니라 ≈20.57**이다. 즉 불꽃은 2.0만큼을 그려놓고 못 보여주고 있었다.

**수정**: 몸통 기하를 `Themes.swift`의 `fireSize(level:phase:)` 하나로 모으고(컬러·모노 단일 출처 — 기존엔 같은 공식이 두 파일에 복붙돼 있었다), `visibleTop(scale:)`으로 확대 후 상한을 역산해 거기 맞춰 **성장 계수를 줄였다**.

- **클램프가 아니라 계수를 줄인 이유**: 클램프하면 90~100%가 같은 높이로 뭉개져 "잔량 = 불꽃 크기"라는 문법이 깨진다. 계수를 줄이면 100%까지 연속으로 자란다.
- 어차피 20.57에서 잘려 안 보이던 부분이라 **보이는 크기는 그대로**, 끝만 뾰족해졌다.
- `iconScale`을 바꾸면 상한이 따라 움직이므로 다음에 스케일을 손봐도 다시 깨지지 않는다.

**검증 방법이 이번 수확**: 육안 대신 **픽셀 검사**를 썼다 — 최종 아이콘(확대 적용 후)을 8배로 래스터화해 위/아래 가장자리 행에 잉크가 있는지 본다.

| | 위 잘림 | 아래 닿음 |
|---|---|---|
| 수정 전 | **32건** | 168건 |
| 수정 후 | **0건** | 168건 (지면 구도, 회귀 아님) |

`docs/theme-reference` 불꽃 6종 재생성. 규칙은 레포 `CLAUDE.md` 코드 규칙에 한 줄로 박아 뒀다(커밋 `bc7ef9c`).

### 다른 확대 테마 점검

같은 픽셀 검사를 전 테마에 돌리고 모노 스트립으로 눈으로 판정했다.

- **역도**: 바벨 원판 위쪽이 평평하게 잘린다(100·80·75·70%). **불꽃과 같은 성격의 진짜 잘림** → 이어서 수정(아래).
- **날씨**: 해의 12시 방향 광선 끝이 살짝 닿는다. 미세.
- **로봇**: 안테나 끝 공이 살짝 닿는다. 미세.
- **달**: 달 원 자체는 온전하고 `zzz`의 z가 모서리에 닿는 정도. 문제 없음.
- **소다·슬라임**: 빨대가 위로 나가고 충전 방울이 위에서 떨어지는 **의도된 구도**. 손대면 안 된다.

→ 가장자리에 "닿는 것"과 "잘린 것"은 다르다. 픽셀 검사는 후보를 좁혀줄 뿐이고 판정은 눈으로 해야 한다.

## 역도 바벨 원판 잘림 수정 (커밋 `e97d0e7`)

불꽃 수정 뒤 전 테마 점검에서 찾아 사용자 승인 후 이어서 고쳤다.

- **원인**: 프레스 자세(`t >= 0.7`)의 `barY = 19.2`인데 원판이 바 중심 위로 **컬러 3.15**(반지름 2.7 + 테두리 절반 0.45) / **모노 3.1** 뻗어 꼭대기가 22.35까지 나갔다. 역도는 `iconScale`이 1.0이라 **확대 문제가 아니라 순수하게 드로잉이 캔버스를 넘긴 경우** — 불꽃과 원인이 반만 겹친다.
- **수정**: `lifterPressBarY(phase:)`를 `Themes.swift`에 두어 컬러·모노 단일 출처로 만들고(여기도 `barY` 상수가 두 파일에 복붙돼 있었다), 상한을 원판 크기에서 역산해 19.2 → **18.7**. 들썩임 진폭 0.7은 그대로라 모션은 유지된다.
- **컬러 기준으로 잡은 이유**: 원판이 모노(3.1)보다 컬러(3.15)가 근소하게 크다. 작은 쪽에 맞추면 컬러만 다시 잘리고, 두 모드의 포즈가 어긋난다.
- 검증: 픽셀 검사 위 잘림 0건, 컬러·모노 × 페이즈 0/2 육안 확인. `docs/theme-reference` 역도 4종 재생성(충전 씬은 바벨을 바닥에 두므로 무변화).

### 이번에 반복된 패턴

불꽃·역도 모두 **같은 기하 상수가 `Themes.swift`와 `Mono.swift`에 복붙**돼 있었고, 그래서 한쪽만 고치면 두 모드가 어긋날 구조였다. 둘 다 계산 함수(`fireSize`, `lifterPressBarY`)를 컬러 쪽에 두고 모노가 불러 쓰게 바꿨다. **컬러·모노 쌍 규칙(CLAUDE.md)은 "같이 고쳐라"인데, 애초에 나눠 갖지 않는 편이 낫다.**

## 3D 데스크톱 펫 — 시도와 보류 (커밋 `3ae766d` ~ `d69e9fb`)

배운 것: [[공부/Apple/SceneKit과 3D 에셋 파이프라인|SceneKit과 3D 에셋 파이프라인]]

### 왜 3D로 갔나

펫을 실기로 보고 사용자 판단: **"원·사각형·타원 조합이라 별로"**. 원인은 벡터라서가 아니라 **35×22 메뉴바에 맞춰 최소 도형으로 짠 구도**를 7배로 키운 것이었다. 세 방향(현재 벡터 / 코드 벡터 고급화 / 3D)을 같은 캐릭터로 렌더해 비교했고, **3D 선택** — 2026-08-09에 만들어 둔 `zappy-snowman.usdz`가 이미 있고 Blender 경험도 있어서 새 작화 없이 시작할 수 있었다.

### 만든 것

SceneKit `SCNView`로 usdz를 배경 투명 실시간 렌더. 잔량 = 녹은 정도, 커서 추적(루트 회전), 클릭하면 통통, 완충 시 점프, 드래그 이동. 3D 모델이 없는 테마는 기존 벡터 펫으로 폴백. 용량 +약 390KB, 의존성 0(SceneKit은 시스템 프레임워크).

원본 `.blend`를 열어보니 **코드로 흉내 내던 것이 이미 다 있었다** — `Melt` 셰이프 키, `MouthFlat`(납작한 입), `Puddle`(물웅덩이), `Sweat`, 220프레임 녹기 애니메이션. 노드 배율로 만든 녹기를 걷어내고 셰이프 키로 교체하니 코드는 줄고 표현은 늘었다.

### 사고 두 번 — 생김새를 두 번 바꿨다

사용자가 **"생긴 건 그대로, 녹는 것만"** 이라고 명시했는데 두 번 어겼다. 둘 다 **usdz를 다시 구운 것**이 원인이다. 앱이 쓰던 usdz는 08-09 산출물이고 `.blend`는 08-18에 수정돼 있어서 — **같은 캐릭터의 다른 버전**이었다. 그냥 다시 구우면 코 각도·머리 높이가 달라진다.

복구: 두 모델의 노드 자세를 덤프해 비교하고(메시는 정점 수까지 동일), Blender에서 **예전 자세로 되돌린 뒤** 셰이프 키만 얹어 다시 구웠다. 100% 상태를 나란히 렌더해 동일함을 확인.

> **규칙**: 시각 산출물에서 "생긴 건 그대로"는 **파이프라인 재실행까지 금지**라는 뜻이다. 다시 구워야 한다면 기존 산출물의 자세를 먼저 덤프해 대조하고, 같아진 것을 확인한 뒤 진행한다.

### 왜 보류했나

기능은 다 돌아갔지만(녹기·물웅덩이·부위 낙하·입 전환·커서 추적) 사용자 판단 **"뭔가 별로"**. 뜯어보니 기술이 아니라 설계 문제였다:

1. **사람이 실제로 머무는 100~50% 구간에서 아무 일도 안 일어난다.** "귀엽게" 하려고 녹기를 후반 가속(지수 1.35)으로 밀고 상한을 0.82로 자른 결과, 평소엔 그냥 서 있는 3D 눈사람이 됐다. **"잔량 = 표정과 형태"라는 앱의 문법 자체가 안 보인다** — 가장 큰 실패.
2. **다 녹은 모습이 귀엽기보다 침울하다.** 부품이 웅덩이에 흩어지고 눈 하나만 남는 것은 "귀엽다"가 아니라 "처참하다"에 가깝다. 2D는 녹아도 캐릭터의 꼴을 유지하고 표정으로 처리했는데 3D는 해체 쪽으로 갔다.
3. **캐릭터에 개성이 없다.** 잘 만든 스톡 3D 에셋처럼 보인다. 2D 벡터는 과장된 비율과 또렷한 실루엣으로 성격이 있었는데, 3D로 옮기며 "예쁘지만 심심한" 쪽으로 이동했다.

→ 1·2번은 숫자 조정이지만 **3번이면 Blender에서 캐릭터를 다시 잡아야 한다**(머리 크게·과장 넣기, 반나절~하루). 사용자가 **"조금 다르게 접근해야 할 것 같다"**며 펫 자체를 보류. 코드는 전부 커밋돼 있어 언제든 재개 가능.

## 남은 판단 (사용자 결정 대기)

0. **1.7 스코프.** 데스크톱 펫이 보류되면 1.7은 **배터리 리포트 + 위젯 확장** 둘이 된다. 그대로 내보낼지, 펫이 정리될 때까지 1.7 전체를 미룰지 결정 필요.
1. **제출 타이밍.** 1.6.1(build 12)이 아직 심사 중이다. 1.7.0을 내려면 1.6.1을 자진 취소해야 하는데, 1.6.1은 **What's New에 5개 언어로 광고된 호버 하트를 고치는 핫픽스**라 먼저 라이브가 되는 편이 낫다고 본다 → 1.6.1 승인 후 1.7.0 제출 권장.
2. **가격.** Zappy+ ₩3,300 / $2.99 유지 여부. 가치가 눈에 띄게 늘었으니 인상 명분은 생겼지만, 인상은 "지금 사면 싸다"는 압박을 만드는 대신 초기 전환을 깎는다. 리뷰 0개 단계에선 유지 쪽으로 기운다.
3. **스크린샷.** 데스크톱 펫은 스토어 스크린샷·SNS 클립으로 팔릴 소재다. 무가공 풀스크린 원칙([[프로젝트/개인/Zappy/App Store 심사 이력|심사 이력]] 2.3.3 교훈)을 지켜 펫이 떠 있는 바탕화면을 그대로 찍는 것이 좋다.

# Zappy 개발 기록 2026-08-18

1.6.0 출시(08-17) 직후 하루. 런치 문구를 만들다가 **릴리즈 노트에 광고한 기능이 동작하지 않는다**는 것을 사용자가 발견해 원인을 찾고 1.6.1 핫픽스를 냈다.

배운 것: [[작업노트/Apple/Swift와 Objective-C 브리징|Swift와 Objective-C 브리징]]

## 호버 하트 — 한 번도 동작한 적 없었다

**증상**: 메뉴바 아이콘에 마우스를 올려도 하트가 뜨지 않는다 (1.6.0, build 11, 스토어 설치본).

**원인**: `AppDelegate`는 `NSResponder`가 아니라서, `@objc func mouseEntered(with:)`가 ObjC 셀렉터 **`mouseEnteredWith:`** 로 내보내진다. AppKit이 tracking area 소유자에게 보내는 것은 **`mouseEntered:`** 라 이름이 어긋나고, `respondsToSelector:`에서 걸러져 **호출 자체가 없었다**. tracking area 등록(`.inVisibleRect`)도 하트 드로잉(35×22 캔버스 안, 좌표 정상)도 모두 멀쩡했다.

**수정**: `@objc(mouseEntered:)` / `@objc(mouseExited:)`로 셀렉터 명시 (커밋 `f7e0889`).

**진단에서 통한 것 / 헛수고한 것**:
- 헛수고: 독립 하네스로 status item을 띄워 마우스를 워프시켜 재현하려 했으나, 번들 없이 띄운 status item 창이 화면 밖(x=-5868)에 주차돼 검증이 안 됐다. `CGWarpMouseCursorPosition`은 화면 밖 좌표로는 클램프되고 tracking area도 갱신하지 않는다.
- 통한 것: **출시된 바이너리에 `strings -a | grep -E "^mouseEntered"`** — `mouseEnteredWith:`만 있고 `mouseEntered:`가 없다는 사실이 결정적이었다. 이어서 20줄짜리 스크립트로 `responds(to:)`를 선언 변형별(NSObject / `@objc(mouseEntered:)` / NSResponder 상속)로 찍어 확정.
- 교훈: 메뉴바 앱의 **호버·트래킹 계열은 유닛 테스트도 렌더 스크립트도 잡아주지 못한다.** 실기에서 한 번 올려보는 것 외에 방법이 없으니, 이런 기능은 릴리즈 전 수동 체크리스트에 넣는다. 반대로 사후 확인은 `strings`가 가장 빠르다.

**파장**: 이 기능은 1.6.0 What's New 3번째 줄에 **5개 언어로 광고**돼 있었다. 스토어에 적힌 기능이 동작하지 않는 상태라 즉시 핫픽스.

- `fastlane mac release` — 업로드 성공. precheck 자체 오류는 이번에도 났고 제출과 무관(1.3.0 때와 동일).

## 런치 문구 (카카오톡)

- 1.6.0이 08-17에 이미 라이브인 것을 `itunes lookup` API로 확인(0.8MB, macOS 13+, 리뷰 0개). **`asc` CLI가 없는 환경에서도 스토어 상태를 볼 수 있는 방법**: `curl "https://itunes.apple.com/lookup?id=6794384033&country=kr&entity=macSoftware"`.
- 소프트웨어 마에스트로 17기 단톡방에 뿌릴 문구 작성. 결정: **지인·동료 커뮤니티에서는 신원을 밝힌다**(스토어 개발자명이 실명이라 익명이 성립하지 않고, 들키면 더 나쁘다). 리뷰 요청은 "별점 주세요"(부탁)가 아니라 "아직 리뷰가 0개라"(사정 설명)로. 첫 메시지에 기술 디테일(반려 3번·0.8MB)은 넣지 않고 질문이 오면 푼다.

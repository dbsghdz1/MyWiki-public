# Zappy 개발 기록 2026-08-22

**"내 마우스는 왜 안 보여?"에서 시작해 1.9.1 제출까지.** 1.9.0으로 낸 주변기기 배터리(Zappy+)가 사용자 맥에서 아무것도 안 보였다. 원인은 코드 버그가 아니라 **탐지 경로가 절반만 커버**한 것이었고, CoreBluetooth를 붙여 나머지 절반을 열었다.

배운 것: [[작업노트/Apple/블루투스 기기 배터리 읽기|블루투스 기기 배터리 읽기]]

## 진단 — IORegistry에 없는 것을 찾고 있었다

1.9.0 구현(`Peripherals.swift`)은 `AppleDeviceManagementHIDEventService`와 `IOHIDDevice`에서 `BatteryPercent`를 읽었다. 사용자 맥에 붙어 있던 건 Rainy 75 키보드와 로지텍 마우스(B031) 둘인데:

- `system_profiler SPBluetoothDataType` — 둘 다 `Services: < BLE >`
- `hidutil list` — 둘 다 Transport **`Bluetooth Low Energy`**, 클래스는 `AppleUserHIDEventService` / `IOHIDUserDevice`. 스캔하던 두 클래스 어느 쪽도 아니다
- 클래스를 추가해도 소용없었다: **전체 `ioreg -l` 덤프 54,073줄에 `BatteryPercent` 키가 0개**

BLE 기기의 잔량은 GATT Battery Service(0x180F)에 있고 그건 `bluetoothd`가 유저스페이스에서 읽는다. **Control Center엔 보이는데 IORegistry엔 없는 상태**가 곧 그 신호다.

## 결정 — 권한 팝업을 감수하되, 물어보는 시점을 통제한다

CoreBluetooth 경로는 `com.apple.security.device.bluetooth` + `NSBluetoothAlwaysUsageDescription`이 필요하다. Zappy의 포지셔닝은 **"권한은 알림 1개, 네트워크 없음"** 이라 이걸 그냥 추가하면 정체성이 깨진다.

해법: **TCC 프롬프트는 `CBCentralManager`를 만드는 순간 뜬다**는 점을 이용해, 인스턴스 생성을 `menuWillOpen`에서 `isPlus`일 때로 미뤘다. 무료 사용자는 팝업을 영영 보지 않는다.

곁가지 문제 하나: 그러면 무료 사용자에게 자물쇠 줄(업셀)을 언제 띄우나. 잔량은 못 읽어도 **기기의 존재는 IORegistry에서 권한 없이 읽힌다**(`AppleUserHIDEventService`의 `Product`·`Transport`) → `bleHIDDeviceNames()`로 "권한을 물어볼 가치가 있는가"를 프롬프트 없이 판단한다.

## 구현 (`Peripherals.swift`, `App.swift`)

- `BLEBatteryMonitor` — `retrieveConnectedPeripherals(180F)`로 **스캔 없이** 이미 붙어 있는 기기를 즉시 얻고, connect → 0x2A19 read → 바로 `cancelPeripheralConnection`. HID 링크와 별개인 GATT 링크를 붙들고 있지 않기 위해서다. 60초 스로틀, 무응답 기기용 10초 타임아웃(안 걸면 `inFlight`에 남아 다음 갱신을 막는다)
- `peripheralBatteries()` = IORegistry(즉시) + BLE 캐시(비동기) 이름 기준 병합
- BLE 값은 왕복 뒤에 도착하므로 `onUpdate` 콜백 + `menuOpen` 플래그로 **열려 있는 메뉴를 다시 그린다**
- 권한 거부 + BLE 기기 있음 → 설정으로 가는 안내 줄(`L10n.peripheralsBluetoothDenied`, 5개 언어)

## 검증

- CoreBluetooth 프로브(별도 CLI)로 먼저 확인: `retrieveConnectedPeripherals(180F)` 2개 → **Rainy 75-1 76% · 홍마우스 90%**
- 무서명 빌드 실기: 잔량 줄 바로 아래에 픽셀 테마 캐릭터로 두 기기가 뜬다
- 서명 샌드박스 빌드(`xcodebuild` Debug): BUILD SUCCEEDED, `codesign -d --entitlements`에 `com.apple.security.device.bluetooth` 확인, 실행 시 권한 프롬프트 정상 표시 → TCC DB `kTCCServiceBluetoothAlways|com.hong.zappy|2`(허용)

## 남긴 것 — 권한 프롬프트가 영문으로 뜬다

`NSBluetoothAlwaysUsageDescription`은 시스템이 읽는 키라 이 앱의 런타임 `L10n.pick`이 안 통한다. `.lproj`가 없는 구조라 지금은 영어 한 벌이고, **한국어 시스템에서도 영문으로 뜬다**(실기 확인). 5개 언어로 하려면 `InfoPlist.strings` 5개를 pbxproj에 리소스로 물려야 하는데 위젯 익스텐션이 있는 동기화 폴더 구성이라 export가 깨질 여지가 있어, 평생 한 번 뜨는 프롬프트라는 판단으로 영어로 두기로 했다(사용자 동의).

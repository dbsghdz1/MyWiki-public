# Zappy 개발 기록 (2026-07-26 ~ 07-29)

## 경위 요약

**07-26 — 심사 대응 + 테마 확장**
- 2.3.3(스크린샷)·1.5(Support URL) 반려 수신 → 실기기 캡처 3장(2880×1800 컴포지션) 제작, Notion 보강은 사용자 담당. 상세: [[프로젝트/개인/Zappy/App Store 심사 이력|심사 이력]]
- 불꽃 테마를 모닥불에서 **불꽃 정령**(왕눈이+벌린 입)으로 리디자인
- 신규 테마 **로봇·너구리** 구현, 달 테마 반짝이 제거
- 포지셔닝 확정: "RunCat이 CPU를 속도로 보여준다면, Zappy는 배터리를 몸짓과 표정으로"

**07-28 — 로봇 고도화 + 역도**
- 로봇 풀바디 리디자인: 머리·몸통(잔량색 가슴 코어)·다리, 춤출 때 팔·다리 교차 스텝
- 신규 테마 **역도**: 잔량 = 바벨 높이 (머리 위→가슴→무릎→바닥 4단계). 모노는 바벨 주위 knockout 틈으로 실루엣 분리

**07-29 — 모션 표준화 + 유료화 구현**
- 모션 4단계 표준(70/40/20) 확립, 로봇 3단계를 **주저앉아 고개 떨군 자세**로 (끄덕이는 숨 모션)
- 역도 전 구간 상시 모션 (프레스 들썩·낑낑·용쓰기·가쁜 숨)
- 충전 번개 아이콘 전 테마 제거 (숨쉬기 모션만 유지)
- **80% 충전 알림 토글** (진짜 충전 제한은 샌드박스상 SMC 접근 불가 → 옵트인 알림으로 대체)
- **StoreKit 2 유료화 구현**: Store.swift(구매·복원·Transaction.updates), 무료 = 모찌·픽셀+모노크롬, 잠긴 테마 🔒 + 구매 알럿, Products.storekit 테스트 파일. RevenueCat 배제(네트워크 없음 포지셔닝 보호)
- **GitHub 연결**: `dbsghdz1/Zappy` (private), 가격 ₩3,300($2.99) 확정

**07-29 (계속) — 역도 치비 리메이크 + 충전 애니메이션 수정**
- 역도 표정이 메뉴바 크기에서 안 보이는 문제 → **치비(2등신) 리메이크**: 머리 2배 확대로 표정(미소·><·시무룩) 가독 확보, 바벨 플레이트 = 잔량 색. "메뉴바 사람형 캐릭터는 얼굴이 커야 한다"는 원칙 확립
- 충전 스쿼시 애니메이션이 축소 리샘플링으로 흐릿해지는 문제 → **정수 1pt 수직 bob**으로 교체 (스케일 없음, 픽셀 퍼펙트)

**07-30 — 날씨 테마 (12번째)**

**07-30 — 사과 테마(13번째)·아이콘 크기 보정·1.1.0 준비**
- 사과 테마(사용자 아이디어: 벌레가 사과를 먹는다): 잔량 = 남은 사과. 70%+ 온전한 사과에서 애벌레 빼꼼 → 40~70 한입 두입 냠냠 → 20~40 절반 이상, 속살 노출 → <20 사과심만 남고 배부른 애벌레 잠듦(zzz). 빼꼼·냠냠은 phase 모션
- 크기 보정: 상대적으로 작던 테마에 배율 — 달 1.18x, 불꽃 1.15x, 눈사람·로봇·날씨 1.10x. `scaledIcon()`이 벡터 drawingHandler를 큰 rect로 재호출하므로 확대해도 선명. 유령은 캔버스 상단에 이미 닿아 있어 제외
- 화질 점검: 8배 확대 렌더로 전 테마 확인 — 실제 경로는 선명. 미리보기 도구가 템플릿 아이콘을 원본 크기로 래스터화해 흐려 보였던 것
- 1.1.0 버전 부여: MARKETING_VERSION 1.1.0, build 2. Zappy+ 유료 테마는 11종으로 확대(날씨·사과 포함)

## 기술 노트 (재사용 가치)

- **모노 실루엣 분리**: 솔리드끼리 겹쳐 뭉개질 때, 앞 오브젝트 주위에 약간 두꺼운 knockout(blend .clear)을 먼저 깔고 본체를 그리면 얇은 틈이 생겨 분리되어 보인다 (역도 바벨)
- **상시 모션 구조**: draw 함수에 `phase: Int = 0` 파라미터 → 타이머(0.55s)가 phase 토글 → `shouldAnimate`가 테마·잔량 조건으로 타이머 수명 관리, 조건 깨지면 틱에서 자기 정지
- **충전 제한은 MAS 불가**: SMC 쓰기는 루트 특권 헬퍼 필요 → App Sandbox 금지. AlDente가 스토어 밖인 이유. 대안은 임계값 알림
- **StoreKit 2 최소 구현**: 비소모성 1개는 `Product.products → purchase → Transaction.currentEntitlements → AppStore.sync` 4개 API로 끝. `Transaction.updates` 감시로 환불도 자동 처리. `@MainActor` 클래스로 만들면 AppKit 델리게이트(비격리)에서 `||`/`&&` 우변 autoclosure 접근이 컴파일 에러 — 격리 없이 onChange만 메인 큐 디스패치가 실용적

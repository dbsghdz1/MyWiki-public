# 약국맵 사다리 3-B·3-C — SSR과 하이드레이션 (2026-09-09)

**결론 한 줄**: 서버가 약국 목록을 HTML로 그려 보내고(`renderToString`), 브라우저가 그 HTML을 **버리지 않고 이어받게**(`hydrateRoot`) 했다 — 데이터가 이미 HTML에 있는데도 나가던 `/api/pharmacies` 요청이 **1줄 → 0줄**이 됐다.

**몰입 판정**: **에너지 7 → 5, 중간에 한 번 끊겼다가 회복.** 3-A 직후 이어붙인 3-B에서 *"왜 3000과 5173이 다른데, 아 몰입 안 되네"* → 자리를 옮기고(밖에 나갔다 옴) 재개. 3-C는 속도가 붙어 **손은 갔는데 이해가 안 따라왔다**(끝 퀴즈 3문항 전부 못 답).

> [!important] 이 세션이 남긴 규칙 후보 — **하루에 세 칸은 이해가 못 따라온다**
> 3-A는 예측→측정을 홍이 주도했고 퀴즈 3/5였다. 3-C는 에이전트가 끌었고 퀴즈 0/3이었다. **차이는 난이도가 아니라 「누가 재고 누가 예측했나」다.** 같은 날 칸을 이어붙이면 뒤로 갈수록 에이전트가 끌게 된다 — 다음부터 **하루 한 칸**, 남는 시간은 같은 칸을 다시 설명하는 데 쓴다.

## 3-B — 서버가 HTML을 만든다

**측정 먼저**(3-A에서 통한 순서 그대로): `curl -s localhost:5173 | grep -c "약국"` → **0**. 크롤러가 받는 HTML이 `<div id="root"></div>` 하나뿐이라는 것을 눈으로 봤다. 이 프로젝트가 SSR을 스택에 넣은 사업적 이유(`<동네명> 문 연 약국` 검색 유입)가 여기서 확인됐다.

| 예측 질문 | 홍의 예측 | 실제 | |
|---|---|---|---|
| `curl localhost:5173`에 약국 이름이 있나 | **없다** (이유: "3000번을 안 거쳐서") | 없다. **이유는 `curl`이 JS를 실행하지 않아서** | 결론 적중·이유 어긋남 |
| `document`가 없는 Node에서 React가 뭘 만드나 | "window?" | **문자열** | 누락 |

- `renderToString(h("ul", null, items.map(p => h("li", {key: p.hpid}, p.dutyName))))`
- **`server/main.js`는 JSX를 못 쓴다** → `createElement`를 손으로 호출. 09-08의 *"JSX는 함수 호출로 컴파일된다"*가 실물로 나온 자리
- 공공 API 호출을 `fetchPharmacies()`로 분리해 `/`와 `/api/pharmacies`가 공유. 라우트 등록은 `app.get("/api/pharmacies", fetchPharmacies)` — **함수를 넘기는 자리의 정상 버전**(이틀 연속 틀렸던 그 자리)
- 검증: `curl -s localhost:3000/` → `<div id="root"><ul><li>1번약국</li><li>○○약국</li><li>△△약국</li></ul></div>` (상호 일부 가림)

### `.ts`는 되는데 `.tsx`는 안 된다 (홍 질문: *"왜 main.js야, ts로 하면 안 돼?"*)

Node 24에서 실측:

```
node .probe.ts   → ts 실행됨: 3
node .probe2.tsx → TypeError [ERR_UNKNOWN_FILE_EXTENSION]: Unknown file extension ".tsx"
```

**타입 지우기(erasure)와 변환(transform)의 차이다.** `: number`는 지우면 유효한 JS가 되지만, `<li>약국</li>`은 지우면 아무것도 안 남는다 — `h("li", null, "약국")`으로 **바꿔야** 한다. Node는 지우기만 하고 바꾸지는 않는다. 그리고 지우기는 **검사가 아니다** — 틀린 타입도 그냥 실행된다.

## 3-C — 브라우저가 그 HTML을 이어받는다

| 예측 질문 | 홍의 예측 | 실제 |
|---|---|---|
| `<script>`만 끼우면 React가 서버 HTML을 (a) 이어받나 (b) 지우고 다시 그리나 | **(b)** | **(b) 적중.** 데이터가 HTML에 있는데도 Network에 `/api/pharmacies` 1줄 |

**중간 실험이 이 세션의 핵심이었다.** `createRoot`인 채로 `<script>`만 끼워 브라우저에서 열어 보니 요청이 한 줄 더 나갔다 — **서버 렌더링이 헛수고가 되는 것을 눈으로 확인**한 뒤 `hydrateRoot`로 바꿨다.

- 서버가 `window.__PHARMACIES__ = ${JSON.stringify(items)}`를 심고, 클라이언트는 그걸로 **서버와 똑같은 첫 렌더**를 만든다. 같아야 이어받는다
- `<li>1번약국</li>`은 **글자**지 데이터가 아니라서, 같은 내용을 HTML과 JSON **두 형태로** 보낸다. 이 중복을 없애는 게 사다리 6번(`dehydrate`)
- `vite.config.ts`에 `build.rollupOptions.output.entryFileNames: "client.js"` — 해시 이름이면 서버 HTML에서 참조할 수 없다
- 정적 파일 서빙도 라우트 하나다: `app.get("/client.js", …)` + `readFile("dist/client.js")`
- **워크플로 함정**: 서버는 `dist/client.js`를 읽는다. `main.tsx`를 고치고 `npm run build`를 안 하면 옛날 JS가 나간다(`--watch`는 서버 파일만 본다)
- 검증: Network `pharmacies` **0줄** · 하이드레이션 경고 **0**

### 한글이 깨졌다 — `charset`을 안 알려줬다

`1번약국` → `1ë²ˆì•½êµ­`. `reply.type("text/html")`은 인코딩 정보가 없어서 브라우저가 추측한다(한국어 환경에선 EUC-KR). UTF-8 한글 3바이트가 1바이트 문자 3개로 읽혀 깨진다. **`curl`에서 멀쩡했던 건 터미널이 UTF-8을 기본값으로 써서지 서버가 잘 보내서가 아니었다.**

```js
reply.type("text/html; charset=utf-8");   // 헤더가 <meta charset>보다 우선이고 더 확실하다
```

## 오늘의 총정리 — **웹이 iOS보다 어려운 이유** (홍의 관찰)

홍: *"웹 만드는 게 iOS보다 훨씬 어렵다."* 맞는 관찰이고, 이유가 하나로 설명된다 — **코드가 도는 곳이 여러 개다.**

| 어디서 | 파일 | 되는 것 / 안 되는 것 |
|---|---|---|
| 브라우저 | `src/main.tsx` | `document` 있음 · JSX 됨 · **비밀 못 담음** |
| Node 서버 | `server/main.js` | `document` 없음 · **JSX 안 됨** · 비밀 담김 |
| 빌드 타임 | `vite.config.ts` | 실행 전에 코드를 바꿔치기(`import.meta.env` 치환) |

**오늘 막힌 자리가 거의 전부 이 표에서 나왔다** — 키가 번들에 실림 / `.tsx` 실행 거부 / `createRoot` vs `hydrateRoot` / 한글 깨짐. iOS는 언어·도구·실행 환경이 하나라 물을 필요가 없던 질문이라, **막히면 첫 질문을 「이 코드는 어디서 도는가」로 두는 것**이 이 프로젝트의 기본 자세가 된다.

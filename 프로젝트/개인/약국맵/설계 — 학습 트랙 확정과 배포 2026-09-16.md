# 설계 — 학습 트랙 확정과 배포

`/gstack-office-hours` 세션 산출물 (2026-09-16). 대상: `(로컬 경로)` (커밋 7개, 원격 없음, 배포 없음, 마지막 커밋 `f4de709` 09-13).

## 이 세션이 뒤집은 것

세션을 **09-19 제품 판정**을 살리는 방향으로 시작했다가, 두 가지 증거를 받고 방향을 바꿨다.

**① 수요 근거가 재현되지 않았다.** 홍이 주말 근무 하루에 "오늘 문 열었나요" 전화를 실제로 셌고 **0통**이었다. 홍 본인 표현으로 *"쪼금 드문 케이스"*. [[프로젝트/개인/약국맵/README|README]]의 유일한 수요 근거였던 09-06 인터뷰의 "주말 4~5통"과 정면으로 어긋나고, **더 최근 관측이 이쪽이다.** 표본은 여전히 각각 1일이라 확정은 아니지만, 가설이 시험대에 올라가서 떨어진 쪽이다.

**② 핵심 기능이 코드에 없다.** 적대적 리뷰 뒤 직접 확인했다.

| 위치 | 실측 |
|---|---|
| `server/main.js:57-59` | `Date.parse("2026-09-10T17:59:59+09:00") < Date.parse("2026-09-10T18:00:00+09:00")` — **항상 참.** 서버는 언제나 「열림」을 그리고, 약국별이 아니라 페이지 전체에 상태 하나다. **「지금 문 연 약국」이라는 제품의 전부가 없다** |
| `server/main.js:27` | `numOfRows=3` — 관악구 3곳 고정 |
| `server/main.js:8` | 제보는 `new Set()` 프로세스 메모리. 재시작하면 사라진다 → **10월 제보 판정을 셀 방법이 없다** |
| `server/main.js:70` | `<head>` 없음, `<title>` 0개 |
| `server/main.js:73` | `app.listen({ port: 3000 })` — host 미지정이라 어느 PaaS에서도 헬스체크 실패 |
| `package.json` | `start` 스크립트 없음 (`dev`/`build`/`lint`/`preview`뿐) |
| `src/main.tsx:129` | `부모 다시렌더 {testCount}` 디버그 버튼이 실사용자 화면에 보인다 |

로드맵의 **2-C(「지금 열림」 필터와 `refetchInterval`)가 미완료**인 것이 이 상태의 원인이다.

## 결정 — 학습 트랙으로 확정한다

약국맵은 `launch_gate: exempt`인 **비수익 학습 프로젝트**다. 수익 트랙은 HSW에서 따로 돈다. 수요 근거가 흔들리고 핵심 기능이 없는 상태에서 제품 판정을 8일 안에 내리는 것은 근거 없이 결론을 사는 일이다. **제품 판정을 내려놓고 배우는 값만 남긴다.** 배포·HTTP·DNS를 배우는 값은 수요가 0이어도 그대로다.

## 09-26 판정 — 네 개 관측치

`site:` 연산자는 쓰지 않는다. 색인된 페이지에도 0을 내놓는 것이 흔해서, 0이 나와도 "설정이 틀렸다"와 "구글이 아직 안 왔다"를 구분할 수 없다.

1. `curl -I https://<host>/robots.txt` · `/sitemap.xml` → 둘 다 **200**
2. GSC 소유확인 완료 + 사이트맵 제출 상태 **성공**
3. GSC URL 검사 라이브 테스트 **"URL을 사용할 수 있음"** + 색인 요청 제출 완료
4. Render 액세스 로그에 **Googlebot 히트 1회 이상** ← 씨앗이 들어갔다는 진짜 증거

전부 결정론적으로 관측되고, 실패하면 어디서 막혔는지를 바로 가리킨다. **그 실패 지점이 칸 10(HTTP)·11(DNS)의 재료다.**

## 이번 범위 밖 — 명시적으로

**09-20 판정은 배관 점검이다. 페이지 내용의 정확성은 재지 않는다.** 배포되는 페이지는 관악구 3곳에 가짜 「열림」이 붙고 디버그 버튼이 보이는 상태 그대로다. 학습 트랙이므로 이것이 흠이 아니다. 다음 칸으로 이월한다.

- **2-C** — 「지금 열림」을 실제 시각으로, 약국별로. 디버그 UI 제거와 `numOfRows` 확대를 같이.
- **제보 영속화** — `new Set()` → append-only 로그나 무료 Postgres. **이게 없으면 제품 판정은 되살릴 수 없다.**
- **B안(지역별 SSR 라우트 + 동적 sitemap + JSON-LD)** — 검색 유입을 진짜로 시험하려면 필요. 새 개념 4~5개라 세션당 ≤3을 깨므로 별도 칸으로.
- **에러 처리** — `app.get("/")`에 try/catch가 없고 `data.response.body.items.item`을 무조건 읽는다. 개발계정 1,000회/일 한도를 넘으면 `TypeError` → 500이고, Googlebot이 500을 만나면 색인이 미뤄진다. 09-19 전에 넣으면 좋지만 새 개념 수에 밀린다.

## 제품 판정을 되살리는 조건

내려놓는 것이지 버리는 것이 아니다. 아래 셋이 모이면 다시 연다.

1. 주말 전화 세기가 **2일 이상 누적**되고 합이 0이 아니다 (비용 0. 근무할 때마다 한 줄씩)
2. 2-C가 끝나 「지금 열림」이 실제로 계산된다
3. 제보가 프로세스 밖에 저장된다

## 숙제

**근무할 때마다 "오늘 문 열었나요" 전화 수를 한 줄씩 남긴다. 요일과 함께.**

`09-20 일 / 0통` 처럼. 이번에 0이 나온 것이 이 숙제의 가치를 증명했다 — **표본 하나가 8일짜리 계획을 뒤집었다.** 평일과 주말, 토요일과 일요일은 약국 개점률이 달라 뜻이 정반대이므로 요일을 같이 적는다. 세 번째 주말까지 누적되면 그때는 판단할 수 있다.

## 이번 세션에서 본 것

- *"이 게아니라 약국 맵으로 하고 있는데 무슨 갑자기 이게 나와"* — 내가 위키 문서 다섯 개를 읽고 세운 전제를 한 문장으로 깼다. 허브 문서(HSW)는 그 갈래가 멈춘 시점에 멈춰 있는데 나는 그걸 현재로 읽었다.
- *"근무 때 체크를 했는데 0이였어 쪼금 드문 케이스이기두 하고"* — 자기 제품에 불리한 관측을 먼저 꺼냈고, 묻지도 않았는데 해석까지 하향 수정했다. 이 문장 하나가 이 세션의 결론을 바꿨다.
- D5에서 내 추천을 버리고 검색 유입을 골랐다. 3일 뒤 판정을 통과하는 것보다 이 제품이 원래 어떻게 굴러가야 하는지를 위에 뒀다. 그 선택 때문에 판정 기준이 바뀌었지 제품 방향이 바뀌지 않았다.

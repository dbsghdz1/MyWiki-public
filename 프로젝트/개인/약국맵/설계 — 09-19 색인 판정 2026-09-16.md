# 설계 — 09-19 색인 판정과 최소 배포

`/gstack-office-hours` 세션 산출물 (2026-09-16). Status: DRAFT. Mode: Startup 진단.
대상 저장소: `(로컬 경로)` (커밋 7개, 원격 없음, 배포 없음)

## 문제

주말과 명절에 사람들이 "지금 문 연 약국 어디예요"를 **사람에게 묻는다.** 홍이 약국에서 주 2일 일하며 반복해서 받는다(2026-09-05 본인 확인). 카운터로 오기도 하고, 전화가 더 많다.

데이터가 없어서가 아니다. 휴일지킴이약국·E-gen이 이미 목록을 준다. **공식 안내문 자체가 "포털 지도만 보고 이동하지 말고 출발 직전에 약국으로 전화해 확인하라"고 쓴다.** 신고 기준 데이터라 실제 영업과 어긋난다는 것을 운영 주체가 인정한다. 그래서 사용자의 실제 흐름이 `검색 → 못 믿음 → 전화`다.

이건 정보가 없는 문제가 아니라 **확인된 정보가 없는 문제**다.

## 수요 근거

- **첫 인터뷰 1건 (2026-09-06)**: 주말 전화 4~5통. 공식 정보는 "보통 다르다". **확인하고도 전화한다.** 이미 네이버 영업시간을 수정해 본 적이 있다.
- 이 인터뷰가 **추석 스파이크 가정을 깼다.** 수요 축은 명절이 아니라 주말이다.
- 그 외: 인터뷰 0명, 제보 0건, 검색 수요 미측정.

게이트 기준으로는 수요 근거가 아직 얇다. 이번 판정은 수요가 아니라 유통 배관을 검증하는 것이다.

## 현재 상태

실습 1~8 완료. Vite+React+TS, TanStack Query, Fastify 프록시(서비스키 서버로 이동, 번들 내 노출 1 → 0), `renderToString` SSR(`curl` 응답의 «약국» 0 → 3), `hydrateRoot`(중복 요청 1줄 → 0줄), 서버 prefetch + HydrationBoundary, `memo`, 제보 버튼 낙관적 업데이트(`src/App.tsx:22-72`). 마지막 커밋 `f4de709`(09-13) 이후 3일 정지.

**미완료**: 원격 저장소 없음, 배포 없음, 도메인 없음, sitemap/robots 없음.

## 제약

- `launch_gate: exempt` — 비수익 학습 프로젝트다. 수익 트랙은 HSW에서 별도로 돈다. 이 문서는 매출을 판정하지 않는다.
- 실습 슬롯 **35분**, 화~토 아침. **세션당 새 개념 ≤3.** 코드는 홍이 전부 타이핑.
- 09-19까지 남은 슬롯은 **09-17(목)·09-18(금) 두 번** + 주말.
- 지도는 카카오맵(네이버 막힘). 전국 약국 API는 이용허락 제한 없음·자동승인·FullData 제공.
- Fastify SSR이므로 **정적 호스팅 불가.** Node 프로세스가 돌아야 한다.

## 전제

1. 09-18(금)까지 배포가 끝나야 09-19 판정이 성립한다.
2. 칸 10(HTTP)·11(DNS)은 배포 뒤로 민다. 로드맵 원칙이 "문제가 학습 순서를 정한다"이고, 배포가 그 문제를 던지는 쪽이다.
3. 10월 제보 1건은 **낯선 사람 1명**이다. 홍 본인·룸메·소마 동기는 세지 않는다.
4. 배포 자체는 병목이 아니다. Fastify 서버가 이미 있고 원격만 없다.

## 검토한 대안

- **A — 최소 배포 (채택)**: 지금 Fastify 서버 그대로 호스팅에 올리고 robots·sitemap만 붙인다. 새 개념 2개. 재사용: 실습 3-A~3-C의 서버, [[작업노트/도구/Vercel 배포]].
- **B — 검색 대응 구조까지 (기각)**: A + 지역별 SSR 라우트(`/관악구`) + 동적 sitemap + JSON-LD. 색인될 페이지가 1개가 아니라 수십 개가 된다. **기각 사유: 새 개념 4~5개로 세션당 ≤3 규칙을 깨고, 안 끝나면 09-19 판정이 통째로 날아간다.** MyCryptoDiary D4 회고의 "하루에 새 개념 10개 → 3x"와 같은 실패 모양이다. **10월 제보 판정 전에 별도 칸으로 올린다.**
- **C — 배포를 에이전트에게 넘기고 슬롯은 칸 10·11에 (기각)**: 마감 리스크 0. **기각 사유: 칸 12는 배포를 배우는 칸이다.** 그걸 넘기면 이번 주에 배울 것이 없어진다.

## 유통

검색. SSR은 이미 동작한다(`curl` 응답에 약국명 3개). 남은 것은 `robots.txt`, `sitemap.xml`, Google Search Console + 네이버 서치어드바이저 등록과 색인 요청.

## 열린 질문

1. **호스팅을 어디로 하나.** Fastify SSR이라 정적 호스팅은 불가. 후보는 Vercel(작업노트 경험 있음, 단 커스텀 Node 서버는 손이 감)·Render·Fly·Oracle 무료 티어. **Oracle은 이미 Hermes가 돌고 있어 자산 재사용이 되지만, 원격 파일 수정을 auto 모드가 막아서 명령을 홍이 직접 쳐야 한다**([[작업노트/도구/Hermes cron 운영]]).
2. **도메인.** `hswlab.com`은 09-15에 이름만 확정했고 **구매 전**이다(회사 이메일). 이번 주에 사서 서브도메인을 쓸지, 호스팅 기본 도메인으로 먼저 색인 판정만 할지. 칸 12의 완료 기준은 "남의 기기에서 열린다"이므로 기본 도메인으로도 칸은 닫힌다.
3. **색인 판정에 네이버를 포함하나.** 국내 검색 유입이 목표면 네이버가 더 중요한데 서치어드바이저는 구글보다 느리다. 09-19에는 구글만 보고 네이버는 10월 기준으로 두는 안.

## 숙제

**다음 약국 근무 때 "오늘 문 열었나요" 전화가 몇 통 오는지 정(正)자로 센다.**

만들기가 아니라 세기다. 이유가 셋이다. ① 첫 인터뷰의 "주말 4~5통"이 재현되는지가 이 제품의 유일한 수요 근거인데 표본이 1이다. ② 게이트가 요구하는 불만 20건을 채우는 가장 싼 경로다. 조사 비용 0이고 이미 그 자리에 서 있다. ③ 10월 제보 판정의 기준선이 된다. 전화가 주말에 5통 오는데 제보가 0이면 그건 데이터 모델 문제고, 전화도 0이면 문제 자체가 약했던 것이다. **지금은 둘을 구분할 방법이 없다.**

한 줄이면 된다. `09-20 토 / 정正 / 3통`.

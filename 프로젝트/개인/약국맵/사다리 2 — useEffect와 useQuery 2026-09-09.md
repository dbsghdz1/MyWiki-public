## 오늘의 진짜 발견 — cleanup 자리에 `fetch`를 넣었다

처음 쓴 코드가 이랬다.

```js
useEffect(() => {
  return () => {           // ← 여기는 "정리(cleanup)" 자리다
    fetch(apiUrl).then(...)
  };
}, []);
```

**그런데 화면에 데이터가 떴다.** 개발 모드의 `setup → cleanup → setup` 때문에 cleanup이 한 번 불렸기 때문이다.

- `[]` 있음 → **1줄** (cleanup 1회)
- `[]` 없음 → **2줄** (매 렌더마다 cleanup이 또 돈다. 3줄로 안 간 건 두 번째 응답이 첫 번째와 **똑같은 문자열**이라 React가 재렌더를 건너뛴 것뿐 — 응답에 시각이 하나만 섞여 있었으면 무한 루프였다)

**진짜 문제는 배포판에서 화면이 영영 빈다는 것.** StrictMode의 이중 실행은 개발 전용이라, 운영에서는 cleanup이 **사용자가 페이지를 떠날 때** 불린다. **개발에서만 동작하는 버그**를 우연히 만들었다.

그리고 [react.dev `useEffect`](https://ko.react.dev/reference/react/useEffect) Troubleshooting의 **「My cleanup logic runs even though my component didn't unmount」** 절에 이 코드가 `🔴 Avoid: Cleanup logic without corresponding setup logic`로 **그대로 실려 있다.**

## 어제와 같은 모양으로 두 번 걸렸다

```js
onClick={console.log("안녕")}          // 09-08
queryFn: fetch(apiUrl).then(...)       // 09-09
```

**둘 다 "함수를 달라"는 자리에 "실행한 결과"를 넣었다.** 라이브러리가 *"필요할 때 내가 부르겠다"*고 하면 넘길 것은 언제나 함수다 — 이번엔 홍이 설명을 듣고 바로 연결지었다.

## 계측 함정 — `Preserve log`

*"요청이 계속 쌓인다"*의 절반은 Network 탭의 **`Preserve log`가 켜져 있어서** 새로고침해도 줄이 안 지워진 것이었다. **줄 수를 세는 게 목적인 실험에서는 계측 도구 설정부터 확인해야 한다.**

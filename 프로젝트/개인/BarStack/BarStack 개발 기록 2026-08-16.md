# BarStack 개발 기록 — 2026-08-16

"아이콘을 숨기는 것까지밖에 안 되는 게 아쉽다 — 팝오버에서 뭐가 숨겨져 있는지 보고 싶다"에서 시작해, 7-22의 "권한 제로" 결정을 뒤집고 **숨긴 아이콘 목록**을 App Store 빌드에 넣은 기록이다. 실측은 MacBook Pro(macOS 26.5.1, 노치) + DELL 외장 듀얼.

배운 것: [[작업노트/Apple/macOS 메뉴바와 샌드박스|macOS 메뉴바와 샌드박스]]

## 결정

1. **"권한 제로" 포지셔닝 폐기** (사용자: "권한 제로?? 의미 없어"). 화면 기록 권한을 **옵트인**으로 요청한다 — 팝오버 카드에서 켤 때만, 거부해도 나머지 기능 그대로.
2. **AX 재검증 → 닫힘 확정.** 7-22 실측대로 샌드박스는 권한을 허용해도 AX를 통째로 막는다(0 vs 29). App Store 빌드에서 클릭 실행은 불가. DMG 전용 AX 복원(두 제품화)은 선택하지 않았다.
3. **v1 범위 = 앱 아이콘 + 이름 목록, 무료.** 실제 글리프 스냅샷은 2단계, 로드맵 원칙("수동으로 쓰는 건 무료")대로 무료.

## 밤 — 클릭 실행 시도, 목록 v2, 되돌림 (`1c88fbb` → `e8bdbe6`)

1. **클릭 실행 시도.** 칩 클릭 → Quick Reveal → 그 아이템 위치에 합성 클릭. 샌드박스에서도 손쉬운 사용 권한만 있으면 `CGEvent` 클릭이 나간다는 걸 프로브로 확인했는데, 앱에서는 계속 씹혔다. QA 자동화(좌표 클릭기·창 목록 진단·컨테이너 trace 파일)로 원인을 쫓은 결과: **번들 ID 이름 창은 macOS가 두 번째 디스플레이용으로 만든 복제본이고 합성 클릭을 무시**한다. 진짜 창(autosave 이름 `Item-0`)을 찍으면 100% 열림. 또 한 번의 이동 직후 down/up은 씹혀서 2단계 이동이 필요했다.
2. **단일 디스플레이 실측 → 낮 버전 결함 발견.** `CGConfigureDisplayMirrorOfDisplay`로 미러링해 메뉴바를 하나로 만들자 **번들 ID 이름이 하나도 없다** — 낮에 배포한 `fdff799`는 노치 맥북 단독에서 "숨겨진 아이콘 없음"을 보여줬을 것. 대신 진짜 창은 SCK로 글리프가 캡처된다(노치 아래 포함, 단 화면 밖으로 밀리면 실패).
3. **목록 v2.** 진짜 행을 우리 아이템의 autosave 이름(`BarStack.divider`)으로 찾고, 숨긴 아이템은 **캡처한 글리프**(투명 여백 trim, 밝기에 따라 칩 톤 반전)로 표시. 팝오버가 열린 동안과 **접히기 직전**(복원 접힘 포함)에 캡처해 캐시. 이름은 복제 행이 있고 같은 순위의 폭이 일치할 때만(툴팁·라벨). 단일 디스플레이 미러링 상태에서 검증.
4. **클릭 실행 되돌림.** 실제로 동작은 했지만(메뉴 열림 → 바깥 클릭 → 재접힘) 커서 점프와 펼침 연출이 어색하고, 14인치 노치 아래 아이템은 어차피 못 누른다는 사용자 판단으로 제거. 손쉬운 사용 권한도 같이 제거. **남은 과제: 노치에 가려지는 아이템** — 별도 방법 필요.

## 심야 — 사용자 QA 피드백 대응과 1.1.1 제출 (`9d29e0b` → `e62793c`)

사용자가 "UI가 계속 바뀌고 깨진다, 숨기지 않은 항목도 들어온다, 열고 닫을 때 부자연스럽고 `‹`가 남는다, 배경이 바뀐다"고 보고. 전부 재현·계측해서 고쳤다.

1. **목록 흔들림·오탐 (`9d29e0b`)** — 스캔 로그로 잡은 세 원인: ① 접기/펼치기 **애니메이션 중** 스캔이 과도기 좌표를 읽어 `‹` 오른쪽 항목(날씨·Zappy)까지 숨김으로 잡음 → 슬라이드 중·종료 후 0.4초 스캔/캡처 중단 + "메인 아이콘보다 왼쪽" 이중 조건 ② 앱 이름을 주는 복제 행이 디스플레이 사이를 오가며 순서도 달라져 **매초 이름이 붙었다 떨어짐** → 창 ID별로 이름 고정 ③ 진짜 행이 디스플레이를 옮기면 x순서가 바뀌어 칩 순서가 뒤바뀜 → 집합이 같으면 순서 유지. 추가로 반쯤 걸친 아이템 캡처(잘린 글리프) 방지, 재캡처는 빈 자리+15초 주기로.
2. **슬라이드 애니메이션 제거 (`167f0c1`)** — 35ms 프레임 캡처로 실측: 펼침은 애초에 한 프레임에 나타나고, 접힘은 중간 길이를 거치는 ~150ms 동안 macOS가 바 전체를 매 스텝 재배치해 **`‹`가 둘 떠다니고 항상 보여야 할 오른쪽 아이템까지 사라졌다 돌아옴**. 즉시 전환은 한 프레임에 깨끗. 길이 보간 코드와 "애니메이션" 설정 토글 삭제. 팝오버의 "로그인 시 실행" 카드는 제거(설정 › 일반에 있음).
3. **칩 톤·빈 칩 (`b173f88`)** — 글리프 밝기에 따라 칩을 검정/흰색으로 뒤집던 걸, **단색 글리프는 템플릿 이미지로 팝오버 글자색에 맞춰 그리고** 배경은 통일. 즉시 접힘 때문에 "접기 직전 캡처"가 끝나기 전 아이콘이 밀려나 빈 칩이 되던 회귀는, 캡처가 시작된 경우 최대 0.3초 기다렸다 밀어내는 것으로 해결.
4. **팝오버 배경 (`ac8945a`)** — `.ultraThinMaterial`이 뒤 창/배경화면 색을 그대로 받아 열 때마다 톤이 달랐음 → `.regularMaterial`.
5. **1.1.1 제출 준비 (`e0a413c`, `e62793c`)** — 사용자 결정: Pro IAP는 빼고 숨긴 아이콘만. `SidebarDestination.proSurfacesEnabled = false`로 Pro·트리거 탭 숨김, 1.1.1 (6). fastlane 레인(Zappy 것 복제)과 metadata 도입 — 스토어 설명이 1.0 시절 문구(프리셋·자동 그룹·트리거·손쉬운 사용 권한)로 남아 있어 실제 기능에 맞게 다시 씀. 심사 노트에 화면 기록 권한 용도 명시.

## 구현 (`fdff799`, 이후 `1c88fbb`에서 글리프 방식으로 교체)

- `Core/HiddenItems/HiddenItemsScanner.swift` — `CGWindowListCopyWindowInfo`로 status-level 창을 행(디스플레이)별로 묶고, **번들 ID가 가장 많은 행**에서 BarStack 자신의 두 창(이름 = 번들 ID) 중 왼쪽 것을 `‹` 핸들로 잡아 그 왼쪽 항목을 숨김으로 판정. 번들 ID → `NSRunningApplication`/`NSWorkspace` 아이콘·이름. 시스템 에이전트(`com.apple.TextInputMenuAgent` 등)는 친화 이름 매핑. 권한 상태 3단계: 미허용 / 허용됐지만 재실행 필요(실행 시점 권한을 기억해 판정) / 준비. `relaunchApp()`은 `NSWorkspace.openApplication(createsNewApplicationInstance)` 후 종료.
- `Features/Popover/HiddenIconsCard.swift` — 카드 UI(권한 안내 → 재실행 안내 → 아이콘 칩 목록 + 개수 배지). "나중에"로 숨김, 설정 > 일반 토글로 복귀.
- 컨트롤러는 팝오버가 열린 동안만 1초 폴링, 닫히면 자동 종료. 팝오버 높이 430→500. ko/ja/es 번역.

## 실측 함정 (상세는 공부 노트)

- 첫 구현은 "핸들 창이 있는 행"을 읽었는데 팝오버가 외장 디스플레이 쪽에서 열려 이름이 전부 `Item-0`(→ "시스템 항목")으로 나옴. 행 간 인덱스+폭 매칭으로 고쳤더니 Notion↔Macs Fan Control 순서가 디스플레이별로 달라 두 개가 어긋남 → 번들 ID 행만 읽는 방식으로 최종.
- 화면 기록 권한은 재실행해야 이름이 보임 → 카드에 "BarStack 다시 실행" 단계.
- 글리프 캡처(SCK 창 단위)는 노치 디스플레이 행에서 템플릿 아이콘이 투명 → v1 제외.

## 열린 것

- **노치 아래 아이템**: 14인치 맥북에서 펼쳐도 노치에 가려지는 앞쪽 아이템은 보이지도 눌리지도 않는다. 다른 접근이 필요(사용자 지적, 2026-08-16 밤).
- 클릭 실행은 기술적으로 가능함을 확인했으나(진짜 창 + 2단계 이동 + 클릭 카운트) UX 문제로 보류. 재개하려면 `1c88fbb`의 `CompactStatusBarController+ActivateHidden.swift`가 출발점.
- 심사: 화면 기록 권한 요청 이유를 심사 노트에 명시("메뉴바 항목 이름을 읽기 위한 것, 캡처 없음"). 개인정보 문구 갱신 필요.
- wiki 불일치: [[프로젝트/개인/BarStack/1.2 Pro 계획|1.2 Pro 계획]]은 "착수하지 않는다"(08-15 보류)로 적혀 있으나 코드에는 07-30에 IAP+트리거(`4ddaf61`, `7a8d48c`)가 이미 들어가 있고 **미제출** 상태다. 이번 기능과 1.2 코드가 같은 브랜치(`chore/notarized-release-ci`)에 쌓여 있어, 다음 제출 범위를 정할 때 함께 결정해야 한다.

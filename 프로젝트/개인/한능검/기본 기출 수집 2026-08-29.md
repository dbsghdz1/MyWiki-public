## 수집·데이터화

- **기본은 일부 회차만 시행된다** — 57·58·60·61·63·64·66·67·69·71·73·75·77·79 (59·62·65·68·70·72·74·76·78회는 기본 시험 없음). 문제지+답지 28개 PDF 전부 수신.
- 파이프라인 적응 둘: `build.py`에 **선지 수 인자**(기본은 4지선다 — `python3 build.py <문제지> <답지> <출력> 4`), `merge.py`에 **베이스 폴더·수준 인자**(`merge.py ../기본 기본`).
- 빌드 결과: 14회차 전부 50문항, **정답 답지 매칭 100%**. 분포 검증 통과 — 회차별 배점 합계 전부 100점, 정답 분포 ①175 ②167 ③180 ④178.

## 검수 — 페이지 168장, 에이전트 병렬

심화 때와 같은 방식(페이지 이미지가 정답, OCR 교정)을 **회차별 서브에이전트로 병렬화**했다.

1. 1차: Fable 에이전트 14개 → **사용량 한도 429로 전원 중단.** 단, 죽기 전까지 디스크에 **134/168페이지(564문항)**가 저장돼 있었고 전부 유효 JSON — 페이지 단위로 즉시 저장하는 설계 덕에 살았다
2. 2차: 잔여 34페이지를 **Sonnet 에이전트 4개**로 재개(한도 보호). 전량 완료
3. 병합: 700문항 전부 `verified`

**교정 오류 실측 1건 — 79회 50번.** 에이전트가 선지 ①②를 뒤바꿔 전사했다. 잡힌 경로가 중요하다: 에이전트 스스로 *"시대순으로는 ①인데 답지는 ②"*라고 **정답 불일치를 신호**로 남겼고, 페이지 이미지 재확인으로 전사 오류로 판정·교정했다(명학소 1176→진주 1862→암태도 1923 = 가-다-나 = ②, 답지가 맞았다). **나열형(순서 배열) 문항이 선지 스왑에 가장 취약하다** — 선지들이 서로 순열이라 문장 검증이 안 통한다.

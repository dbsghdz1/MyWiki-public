# 예상 모의고사 v2와 PDF

홍이 2,900원 전체 상품의 PDF, 구매자 PDF 받기, 문항 품질 개선(「최대한 실제문제와 비슷하게」)을 요청했고, 이어 「배포하고 1.2.3.4.5 를하자」로 기본 5회분 재작성, 요약 노트 오류 수정, 앱 반영, 유료 문항 비공개, 환불 문구를 맡겼다. 출처: Claude 대화, 2026-11-25. [한국사 정복](README.md)

## 결과

- 81회 대비 심화 5회분과 80회 기본 복습 5회분, 500문항을 모두 새로 썼다(v2). 판매 웹에 배포했고 iOS 2.3.6(19)에 넣어 심사에 제출했다. [문항 v2](#문항-v2) [심사 기록](App%20Store%20%EC%8B%AC%EC%82%AC%20%EC%9D%B4%EB%A0%A5.md#236-19-2026-11-25-제출-심사-대기)
- 판매 웹에 구매자 PDF 받기, 유료 2~5회 문항 비공개, 환불 정책의 PDF 열람 조항을 배포하고 운영에서 확인했다. [판매 웹](#판매-웹)
- 요약 노트 「조선 건국과 태조·태종」의 「태조가 과전법을 제정」을 고쳤다. 과전법은 1391년 고려 공양왕 때 제정됐다. 「전시과와 토지 제도」 요약의 「조선 초 과전법」도 「고려 말에 제정된 과전법」으로 바로잡았다. 노트 원본 `notes/batch_1.json`, `notes/batch_5.json`과 `data/notes.json`, 앱 데이터에 반영했다.
- 구매자에게 직접 보낼 전체 10회 PDF 두 개(문제와 해설, 문제지와 정답표)를 새 문항으로 만들었다. 이전 판 두 가지는 하위 폴더에 보관했다.

## 문항 v2

v1 진단(실제 기출과 같은 기준으로 비교):

- 81회 심화 v1: 250문항의 발문이 2종뿐이었고(2~5회 200문항이 이름 고르기), 오답이 시대가 동떨어지고 해설이 자료를 되풀이했다. 2~5회의 번호별 시대 배치도 실제와 달랐다.
- 80회 기본 v1: 가장 긴 선지가 정답인 문항이 44%였다(4지선다의 우연 25%, 실제 기본 19.5%). 「(가)에 들어갈 내용」형이 7.6%(실제 18.7%), 부정형 1문항, 연표형 0이었다. 시대 배치는 실제와 같았다.

만든 방법(두 수준 같은 틀):

1. 슬롯: 번호별 시대와 주제를 기출 통계로 정한다(심화 57~80회 24회차, 기본 57~79회 기본 14회차).
2. 발문 유형 할당량: 같은 번호대 기출의 유형 비율. 기본은 이름 고르기형도 기출 비율로 상한을 둔다.
3. 번호대별 작성 에이전트 6개. 재료는 요약 노트와 그 주제의 최근 기출. 검사기는 기출 문장 16자 이상 겹침, 가장 긴 선지가 정답인 비율 12~25%, 표시 금지어, 같은 주제의 정답 반복을 본다.
4. 작성과 분리된 에이전트가 선지를 섞은 블라인드 사본을 풀고, 같은 에이전트가 정답과 해설을 검토한다. 작성자가 고치고, 고친 문항만 새 에이전트가 다시 푼다.
5. 회차 단위 교차 검사: 한 문항의 정답이 같은 회차 다른 문항의 오답으로 나오는지 본다.
6. 기본은 「오답이 자료가 가리키는 대상에도 해당하는가」만 보는 점검을 한 번 더 했다.

| | 81회 심화 v2 | 80회 기본 v2 |
|---|---|---|
| 회당 서로 다른 발문 | 평균 38.6종 | 평균 35.8종 |
| 가장 긴 선지가 정답 | 약 20% | 20.1% |
| 블라인드 풀이 정답 일치 | 250/250 | 250/250 |
| 고친 문항 재풀이 | 62/62, 16/16 | 18/18, 14/14 |
| 반드시 고칠 것 | 검토 24건 | 검토 5건, 별도 점검 10건 |
| 재풀이를 거치지 않은 마지막 수정 | 3문항 | 2문항 |

- 검증은 모두 AI가 했다. 사람 전문가 검토와 실제 수험자의 난도 측정은 하지 않았고, 사이트 안내문에도 그렇게 적었다.
- 사이트 풀이 화면은 새 문항과 예전 답이 섞이지 않게 저장 키를 바꿨다(`심화:81v2`, `기본:v2`).
- 상세 기록은 프로젝트의 `data/predict-81/REVIEW-v2.md`, `data/predict-basic-v2/REVIEW-basic-v2.md`.

## 판매 웹

- PDF 받기: `predict-site/api/pdf.js`가 주문번호는 토스 결제 조회로, 코드는 목록 대조로 확인한 뒤에만 `private/pdf/`의 파일을 보낸다. 전체 구매는 수준별 묶음 4개, 1회 구매는 그 회차 2개다. PDF는 `scripts/make-pdf.py`로 미리 만들고 `vercel.json` includeFiles로 그 함수에만 싣는다. 함수 응답 한도 4.5MB 때문에 파일당 4MB 아래로 둔다. 검사는 `scripts/check-pdf.mjs`.
- 유료 문항 비공개: 그전에는 2~5회 JSON이 `/data/*.json`으로 결제 없이 받아졌다. 2~5회를 `private/data/`로 옮기고 `api/set.js`가 같은 확인(`api/_grant.js`)을 거친 뒤에만 보낸다. 무료 1회는 공개 그대로다. 토스 미니앱 번들은 빌드 때 `private/data`를 번들 안에 복사한다(`build:toss`). 검사는 `scripts/check-data.mjs`(결제 확인 18가지).
- 예전 코드 구매자는 기기에 코드가 저장돼 있지 않아 유료 회차를 처음 열 때 코드를 한 번 넣는다. 1회분 코드는 회차 기록이 없어 서버가 회차를 가리지 않는다.
- 환불 정책: PDF를 내려받으면 유료 문항을 열람한 것으로 본다는 문장을 환불 정책, 결제 화면, PDF 받기 화면에 넣었다.
- 운영 확인: 예전 유료 JSON 주소 404, 가짜 주문 403, 실제 코드로 문항과 PDF 200. 로컬 크롬 원격 디버깅으로 결제자, 코드 구매자, 비구매자 흐름 21가지를 확인했다.

## 남은 것

- iOS 2.3.6(19)의 심사 결과와 자동 출시 확인.
- Android 비공개 테스트: versionCode 20(2.3.6)으로 올렸고 서명 스크립트 `tools/android-sign-test.sh`(비밀번호를 화면에 안 보이게 입력)를 준비했다. 홍이 실행하고 Play Console에 올려야 한다.
- 토스 미니앱에는 예전 기본 문항이 남아 있다. 번들을 다시 만들어 검수를 받아야 바뀐다.
- 상품 이름 「80회 기본 복습」을 유지할지. 새 기본 문항은 기본 기출 14회차 형식으로 썼고 81회 기본 예상문제로 만든 것은 아니다.
- 사람 전문가 검토.

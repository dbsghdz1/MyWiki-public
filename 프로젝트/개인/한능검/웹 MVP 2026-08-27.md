# 웹 MVP — 무료 범위만으로 완결된 제품

데이터가 다 준비돼 화면만 남아 있었다. React + TypeScript + Vite로 만들고 빌드까지 통과했다.

## 왜 이걸 먼저 했나

리드타임이 강제한 순서다. **D-U-N-S가 최대 30일**인데 Google Play 조직 계정은 *도메인이 연결된 웹사이트*를 요구한다 → **웹 배포가 D-U-N-S보다 먼저**여야 한다.

그리고 무료 범위(기출 풀이 + 정답 + 강의 링크)만으로 이미 완결된 도구가 된다. [[프로젝트/개인/한능검/한능검 시장 조사 2026-08-26|시장 조사]] 3-1절에서 확인한 1위의 설계 그대로다 — *"무료로 제공을 많이 해주셔서 다른 어플들은 다 지웠네요"*.

## 화면 셋

| 화면 | 하는 일 |
|---|---|
| 홈 | 회차 23개 · 진행률 막대 · **이어풀기**(안 고른 첫 문항으로) |
| 풀이 | 문항 1개씩 · 선지 선택 즉시 채점 · **정답 후 강의 카드 노출** |
| 결과 | 정답률 · 문항 번호 격자(맞음/틀림/미풀이) · 눌러서 해당 문항으로 |

강의 카드는 접힌 상태로 두고 누르면 `youtube-nocookie.com/embed`로 연다. **자동 재생하지 않는다** — 데이터를 아끼고, 보려는 사람만 본다.

## 구현에서 지킨 것 셋

**① 로컬 우선 저장 — 계정도 서버도 없다**

경쟁 앱 1~3★의 상당수가 *"별표해둔 문제가 초기화됨"* 류인데 원인이 서버·계정 의존이다. 여기서는 `localStorage`에만 쓴다. 그리고 **저장 실패가 풀이를 막지 않게** 모든 접근을 `try/catch`로 감쌌다 — 사생활 보호 모드나 저장이 차단된 환경에서 앱이 죽으면 안 된다.

**② 첫 화면을 가볍게 — 1.5MB를 한 번에 받지 않는다**

계절성 시장이라 시험 직전 모바일 유입이 몰린다. `bank.json` 1.5MB를 통째로 주지 않고 쪼갰다.

| | |
|---|---|
| `index.json` (회차 목록) | **1.0KB** |
| 회차별 파일 | 평균 57KB (최대 62KB) |
| JS 번들 | 198KB → **gzip 62KB** |

**③ 강의가 없는 문항도 막다른 길이 아니다**

강의 링크가 없는 53문항(지역사·제도 비교 등 통합 구간)은 **키워드 유튜브 검색 링크**로 폴백한다. 영상이 삭제·비공개될 때를 대비한 것이기도 하다 — [[프로젝트/개인/한능검/차별점 검증 2026-08-26|차별점 검증]]에서 *"깨진 링크 감지와 대체 경로를 처음부터 넣어야 한다"*고 정해둔 항목이다.

## 검증

`tsc --noEmit` 통과, 빌드 통과. **WKWebView 스냅샷으로 실제 렌더링을 확인**했다 — 회차 목록, 문항 표시, 정답/오답 색 구분, 강의 카드 열림까지.

> [!note] 스냅샷이 처음엔 백지였다
> `document.fonts.ready` 직후에 찍었더니 React 마운트와 `fetch`가 안 끝나 빈 화면이 나왔다. **특정 셀렉터가 나타날 때까지 폴링**하도록 바꿔서 해결했다. [[공부/도구/HTML을 이미지로 렌더링|HTML을 이미지로 렌더링]]에 적어둔 "폰트 로드 후" 규칙만으로는 SPA에 부족하다.

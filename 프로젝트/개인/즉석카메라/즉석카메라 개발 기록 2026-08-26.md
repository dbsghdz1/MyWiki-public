# 즉석카메라 개발 기록 2026-08-26

카메라 화면을 **두 번** 갈아엎은 날. 그리고 폴라로이드 상표를 조사했다.

## 본체를 만들었다가 걷어냈다

전날 촬영 화면을 "카메라 본체"로 만들었다(사출 플라스틱 표면·파인 뷰파인더 창·슬롯·각인·기계식 카운터·빨간 셔터). 물성은 좋았는데 사용자 지적이 정확했다 — **"카메라 화면이 작아서 이상하다."**

뷰파인더가 262pt였다. **사진 앱에서 프레이밍은 타협할 대상이 아니다.** 본체를 버리고 아이폰 기본 카메라 구조로 갔고, 폴라로이드다움은 **인화되는 순간**으로 옮겼다.

> 버린 작업이 아깝지 않았다. 본체를 만들어 보지 않았으면 "프레이밍 vs 물성"이 실제로 충돌한다는 걸 몰랐을 것이고, 물성을 어디로 옮겨야 하는지도 안 나왔다.

## 찍으면 화면이 바뀐다

처음엔 인화지가 촬영 화면 안에서 조작부 위로 밀려 나왔다가 3.5초 뒤 사라졌다. 사용자 표현으로 **"어정쩡했다"** — 셔터를 반쯤 덮은 채 걸쳐 있고, 아무것도 안 했는데 혼자 빠져나간다.

`JustShotScreen`으로 분리했다. 검은 화면에 인화지가 위에서 내려와 자리를 잡고, 설명과 `[앨범][계속 찍기]`가 뜬다. **끝내는 건 사용자가 정한다.**

- 인화지는 **끝이 조금 걸친 채로 시작한다.** 완전히 화면 밖에서 시작하면 전환 직후 0.5초가 새까맣게 비어서 화면이 죽은 것처럼 보인다
- 첫 장 안내 카드(`FirstDevelopNote`)를 이 화면에 흡수했다. 카드가 정작 설명 대상인 인화지를 덮던 문제도 같이 사라졌다

## 요청 셋이 한 선택으로 풀렸다 ★

사용자: *"촬영음을 꺼달라(SNOW처럼). 카메라 화면이 아직도 작다. 필터가 안 먹히는 것 같다."*

`AVCapturePhotoOutput`을 버리고 **비디오 스트림에서 프레임을 뽑는 것**으로 셋이 동시에 해결됐다. 기법은 [[공부/Apple/카메라 캡처와 실시간 필터|카메라 캡처와 실시간 필터]]에 정리했다.

**"필터가 안 먹힌다"가 정확한 지적이었다.** 적용은 되고 있었지만 `AVCaptureVideoPreviewLayer`에 CoreImage를 못 끼워서 **현상이 끝난 10분 뒤에야** 결과에 나타났다. 고르는 순간 아무 일도 안 일어나니 고장으로 읽히는 게 당연했다.

미리보기를 안 넣기로 했던 전날 판단("찍어도 바로 보이지 않는다가 이 앱의 전제")은 **틀렸다.** 전제는 *결과 사진*에 대한 것이지 *필름 선택*에 대한 것이 아니다. 무엇을 고르는지 모르는 채로 고르게 하는 건 컨셉이 아니라 결함이다.

**남은 것: 실기기에서 잡히는 포맷 크기 확인.** 비디오 프레임이 곧 사진이라 `[camera] active format WxH`가 1440 미만이면 화질 손해다.

## 비율 선택 — 정사각은 법칙이 아니었다

사용자 질문 *"카메라 화면이 정사각형인 이유가 있는 거지?"*에서 나왔다. 근거는 Polaroid 600·i-Type의 사진 영역이 79×79mm 정사각이라는 것인데, **Instax mini는 46×62mm 세로 직사각이다.** 정사각은 어느 계열을 골랐느냐의 결과지 인스턴트 필름의 성질이 아니다.

`PaperFormat`을 만들고 **4:3 기본 / 1:1 선택**으로 갔다. 인화지·현상·내보내기·앨범에 박혀 있던 정사각 가정을 전부 걷어냈다.

- **테두리와 아래 여백 비율은 두 형태가 같은 값을 쓴다.** 실물 두 제조사 수치를 각각 흉내 내면 다른 물건 둘이 된다 — 여기서는 같은 제품의 다른 필름이어야 한다
- 형태는 **필름의 성질**이라 촬영 전에 정해지고 찍은 뒤에는 못 바꾼다
- `Photo.formatID`는 옵셔널이다 — 코드 리뷰가 지적한 마이그레이션 지뢰를 그대로 따랐다

## 잡은 버그

| 증상 | 원인 |
|---|---|
| 상세 화면이 통째로 카키색 사각형 | `GeometryReader` 첫 패스의 폭 0 → 1×1 썸네일. 완료 사진은 타이머를 멈추게 해서 그대로 굳었다 |
| 첫 장에 첫 장용 문구가 안 나옴 | `@AppStorage` 플래그를 세우는 순간 뷰가 다시 그려진다 |
| 필름 끝이 필름 선택줄을 덮음 | 4:3에서는 가이드 아래가 곧 조작부 자리. 작은 기기(17e)일수록 심하다 → `PreferenceKey`로 높이를 재서 클램프 |
| 마스크·가이드가 59pt 밀림 | 프리뷰만 `ignoresSafeArea`인데 좌표는 안전 영역 기준으로 계산 |
| 소리가 두 번 남 | 시스템 촬영음 + 우리 셔터음 |

## 상표 — 흰 테두리에는 이름이 있다

본체 시안에 OneStep의 무지개 띠를 넣으려다 확인이 필요해졌고, 조사하다 **흰 테두리 자체가 계류 중인 분쟁**이라는 걸 알게 됐다. Polaroid의 등록 상표 이름은 **classic border logo(CBL)**이고, 정의가 *"세로로 선 직사각형, 위와 좌우는 얇은 테두리, 아래는 두꺼운 테두리"* — **우리 인화지의 정의 그대로다.**

정리와 실행 규칙은 [[공부/AppStore/실물을 흉내 내는 앱의 상표 위험|실물을 흉내 내는 앱의 상표 위험]]에.

레포 전수 검사 결과 스토어 문구·앱 문자열에 상표 **0건** 확인(코드 주석은 배포물에 안 실린다).

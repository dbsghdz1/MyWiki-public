# MyCryptoDiary 실시간 데이터 UI 계획

## 왜 이걸 하는가

iOS → TypeScript·React 직무 전환의 **핵심 포트폴리오 서사**를 만들기 위해서다. 목표는 "코인 앱을 만들었다"가 아니라 **"초당 수십~수백 틱이 들어오는 실시간 데이터를 UI로 다루는 문제를 풀어봤다"**이다.

이 주제를 고른 이유(면접에서 그대로 쓸 수 있는 답):

- iOS에서 60fps 유지·메인스레드 블로킹 회피에 신경 쓰던 감각이 웹의 리렌더 최적화로 거의 그대로 번역된다. **"도구를 바꾼 것이지 관심사는 그대로"**가 전환 사유에 대한 가장 강한 대답이다.
- 실시간은 붙이면 끝나는 기능이 아니라 이 프로젝트에서 **가장 어려운 부분**이다. 어려워야 이야깃거리가 남는다.
- 지원 시점은 **2026년 12월**. 역산하면 8월 셋째 주 착수가 적정하다. → **2026-08-16 갱신: D-day가 `2026-11-14`로 당겨졌고, 08-15 모의투자 전환으로 이 문서의 WebSocket·리렌더 작업은 08-28 이후(로드맵 Phase 2)로 재배치됐다.**

## 현재 상태 (2026-08-14 기준)

- 스택: Next.js 16, React 19, Tailwind 4. 상태관리·데이터패칭 라이브러리 **없음**(순수 React). TS/TSX 16개 파일, 약 614줄.
- 마지막 커밋 2026-08-06. **실시간 관련 코드는 아직 0줄** — WebSocket·폴링·거래소 연동 모두 없음.
- `src/components/home/LiveMarketCard.tsx`가 "실시간 차트"라는 제목을 달고 있지만 실제로는 하드코딩 배열 5개(BTC·ETH·SOL·XRP·DOGE)다. 서버 컴포넌트다.
- ⚠️ **가격이 이미 포맷된 문자열로 저장돼 있다** (`price: '92,481,000원'`, `change: '+2.43%'`, `volume: '1.8조'`). 실시간 값을 넣으려면 이 모델부터 바꿔야 한다. 1주차 첫 작업인 이유.

## Phase 2 1주차 (08-28 이후 — 원래 2026-08-18 주 예정이었음) — 진짜 틱을 띄우고, 망가지는 걸 측정한다

이번 주의 목표는 **잘 만드는 게 아니라 못 만든 상태를 증거로 남기는 것**이다. before/after가 있어야 최적화가 이야기가 된다.

### 1. 데이터 모델을 숫자로 바꾼다

`LiveMarketCard.tsx`의 `Coin` 타입에서 표시용 문자열을 원시 숫자로 분리한다.

- `price: string` → `price: number` (92481000)
- `change: string` → `changeRate: number` (0.0243)
- `volume: string` → `accTradePrice24h: number`
- 포맷팅은 렌더 시점에 `Intl.NumberFormat('ko-KR')`으로. 상승/하락 색상도 문자열의 `-` 접두사 검사(`change.startsWith('-')`)가 아니라 숫자 부호로 판정한다.

이 단계가 없으면 실시간 값이 들어와도 화면에 꽂을 수 없다.

### 2. 업비트 WebSocket을 붙인다

- 엔드포인트: `wss://api.upbit.com/websocket/v1` — **인증 불필요**(공개 시세)
- 구독 요청은 JSON 배열을 보낸다: `[{ticket}, {type:"ticker", codes:["KRW-BTC","KRW-ETH","KRW-SOL","KRW-XRP","KRW-DOGE"]}, {format:"DEFAULT"}]`
- `format: "DEFAULT"`로 두면 필드명이 `code`, `trade_price`, `signed_change_rate`, `acc_trade_price_24h`라 읽기 쉽다. `SIMPLE`은 축약 필드명이라 트래픽은 줄지만 처음엔 불리하다.
- 🪤 **응답이 텍스트가 아니라 바이너리(Blob)로 온다.** `JSON.parse(event.data)`가 바로 실패한다. `await event.data.text()` 또는 `TextDecoder`로 디코딩해야 한다. 실제로 여기서 제일 많이 막힌다.
- `LiveMarketCard`를 `'use client'`로 전환해야 한다(현재 서버 컴포넌트).
- 하드코딩 배열은 **초기값(fallback)으로 남긴다.** 연결 전/실패 시 빈 화면이 되지 않도록.

### 3. 일부러 순진하게 구현한다

틱이 올 때마다 그대로 `setState`를 호출해서 전체 목록을 갱신한다. 5개 코인이면 초당 수십~수백 번 리렌더가 난다.

**이 상태를 반드시 커밋으로 남긴다** (예: `feat: naive websocket ticker (unoptimized)`). 최적화 커밋과 나란히 놓였을 때 그 자체가 포트폴리오 근거가 된다.

### 4. 측정한다 ← 1주차에서 가장 중요

- React DevTools Profiler로 **초당 렌더 횟수, 커밋당 소요 시간, 리렌더되는 컴포넌트 범위**를 기록한다.
- 스크린샷과 숫자를 이 폴더에 `실시간 UI 측정 기록 YYYY-MM-DD.md`로 남긴다.
- 체감("버벅인다")이 아니라 **수치**로 남겨야 한다. 신입 지원자 중 이걸 갖고 있는 사람이 드물다.

### 1주차 완료 기준

- [ ] 진짜 업비트 가격이 화면에서 실시간으로 움직인다
- [ ] 순진한 구현이 별도 커밋으로 남아 있다
- [ ] Profiler 측정치(before)가 문서로 남아 있다

## 이후 개괄 (11-14 역산)

| 시기 | 주제 | 남길 증거 |
|---|---|---|
| 2주차 | 외부 store + `useSyncExternalStore`로 구독 분리 — 값이 바뀐 행만 리렌더 | after 측정치, before/after 비교 |
| 3주차 | 배치·스로틀링(`requestAnimationFrame` 단위 합류), 차트 렌더링(캔버스 vs SVG 선택 근거) | 선택 근거 문서 |
| 4주차 | 연결 신뢰성 — 끊김 감지, 지수 백오프 재연결, 탭 백그라운드 시 구독 축소 | 장애 시나리오 재현 기록 |
| 이후 | 실거래 기록과 연결(일기 ↔ 시세), 배포, README·이력서화 | 배포 URL, 이력서 항목 |

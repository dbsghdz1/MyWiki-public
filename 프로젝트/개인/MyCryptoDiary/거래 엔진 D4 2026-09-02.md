# D4 — 거래 엔진 ① 매수 (진행 중)

브랜치 `feat/clerk-auth` 이어서. 계획서의 D4는 서버측 가격 재조회 → 잔고 검증 → 트랜잭션(현금↓·보유↑·주문기록)이고, 학습 포인트는 Server Actions·DB 트랜잭션·신뢰 경계·입력 검증이다.

## 결정

### 반올림 (2026-08-30)

README 「반올림 규칙」 절로 분리했다 — 유저가 내는 건 올림, 받는 건 내림. 최소 수수료 1원은 올림에서 자동으로 따라온다.

### 매수 입력은 **수량 기준**(A) (2026-09-02)

유저가 "0.001 BTC"처럼 **수량**을 입력하고 주문금액을 계산한다. 금액 기준(B, "10만원어치")도 실제로 쓰이지만 — 호가창·차트 거래 화면은 대개 수량 입력, 간편매수가 금액 입력 — 하나만 먼저 한다.

| | 수량 기준 (선택) | 금액 기준 |
|---|---|---|
| 계산 | 주문금액 = 가격 × 수량 | 수량 = 주문금액 ÷ 가격 |
| 정확한 쪽 | 받는 수량 | 내는 돈 |
| 자릿수 문제 | 소수 × 소수 → 자릿수 증가 | 나눗셈 결과를 8자리로 내림 |

### 가격은 **원화 정수만** 먼저 (2026-09-02)

`Coin.price`가 `number`(부동소수점)인 것을 `bigint`로 바꾼다. **D1 리뷰가 예고한 시점이 여기다** — *"`Coin.price`가 float인 것은 표시 전용이라 지금은 허용하되, D4에서 체결가로 넘기면 「float 절대 금지」 위반이 되므로 경계를 명시할 것"*. 화면에 그리는 데는 float이어도 되지만 잔고를 깎는 순간 안 된다.

업비트 원화 마켓은 BTC·ETH급이 정수 가격이고 **소수 가격은 저가 코인에만** 붙는다(도지코인 99.4원 등). 그래서 정수 가격 코인만 먼저 지원하고, 소수는 나중에 얹는다.

## 나중에 할 것 — 소수 가격 지원

**본인 결정(2026-09-02): 정수로 먼저 가고 소수는 나중에 추가한다. 좋은 경험이 될 작업이라 별도로 남긴다.**

소수 가격을 받으려면 **고정소수점 산술**이 필요하다. 실수를 "정수 + 정해진 배율"로 표현하는 방식이고, 금융 시스템이 float 대신 쓰는 표준 방법이다.

- 소수 문자열(`"99.4"`)을 배율 맞춘 정수로 파싱 (`994n`, scale 1 → 통일하려면 scale 8로 `9940000000n`)
- **곱셈은 배율이 곱해지고 나눗셈은 나뉜다** — 가격(scale 8) × 수량(scale 8) = 결과 scale 16. 원 단위로 되돌리려면 10^16으로 나누며 올림
- 파싱 엣지 케이스: 소수점 없음, 8자리 초과, 앞자리 0, 음수 거부
- 이때 `Coin.price`는 `bigint` 하나가 아니라 **값 + 배율** 쌍이거나, 전부 scale 8로 통일한 `bigint`가 된다

착수 시점: 매수·매도가 정수 가격으로 완주한 뒤. 저가 코인을 목록에 넣고 싶어지는 순간이 신호다.

## 결정

- **`proxy.ts`** — Next 16에서 `middleware.ts`가 개명됐다. matcher는 정적 확장자·`_next`를 부정 look-ahead로 빼고, `/(api|trpc)(.*)`와 `/__clerk/:path*`는 반대로 포함시킨다.
- **`ClerkProvider`는 `app/layout.tsx`**, 로그인 UI는 **`widgets/header`**. 헤더가 전 페이지에 나오므로 layout에 UI를 두지 않았다.
- **`app/sign-{in,up}/[[...]]/page.tsx`는 `_pages` 슬라이스를 만들지 않고 `app/`에만** 뒀다. 내용이 우리 것이 아니라 Clerk 컴포넌트 하나라 옮겨봐야 한 줄 파일만 늘어난다. D1의 라우트 스텁 6개와 같은 판단.
- **`entities/account`** — 계좌는 명사이고 DB(바깥 저장소)에서 가져오므로 `entities/<name>/api/`. `entities/coin`이 업비트에서 가져오는 구조와 같다.

## 밟은 지뢰

**Clerk v7(Core 3)에서 `SignedIn`/`SignedOut`/`Protect`가 제거됐다.** `removedControlComponents`에서 export되지만 쓰면 런타임 에러를 던진다 — 이름 자체가 안내판이다. 대체는 **`<Show when="signed-in" fallback={...}>`**. 조건이 맞으면 children, 틀리면 fallback.

> 중요한 점: 이 에러는 **`tsc`와 `npm run dev`를 통과하고 `npm run build`에서만** 났다. 타입은 살아 있고 런타임에만 던지기 때문이다.

**`matcher: []`는 미들웨어를 한 번도 실행시키지 않는다.** 파일이 있고 문법이 맞고 빌드가 통과하고 화면도 정상이라 "잘 된다"고 판단했지만 아무 일도 하지 않고 있었다. 확인법은 `npm run build` 출력의 **`ƒ Proxy (Middleware)`** 줄 — 비어 있으면 이 줄이 없다.

**`useAuth`(훅)와 `auth()`(서버 함수)의 갈림길.** `index.d.ts` 맨 아래 `export declare const auth: never`가 안내판이고, 주석에 `@clerk/nextjs/server`에서 가져오라고 diff까지 적혀 있다. 결정 기준은 단순하다 — `getDB()`가 `import 'server-only'`라 클라이언트 컴포넌트에 들어갈 수 없으므로 이 함수는 서버여야 하고, 서버에선 훅을 못 쓴다.

## 검증

- `tsc` / `eslint`(경고 0) / `steiger` 위반 0 / `next build` 통과

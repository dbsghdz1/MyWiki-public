## 2026-08-17~18 추가 — 업비트 API (블록 2~3)

PR #1·#2·#3 머지 완료(#2가 이미 머지된 브랜치로 들어가 main에 안 올라가서 #3으로 다시 올림). 이후 `feat/upbit-api` 브랜치에서:

- `shared/api/upbit/{types,client,index}.ts` — 커밋 `c761e7a`. `getTickers`(5s) / `getDayCandles`(60s) / `getMarkets`(3600s)
- `app/api/upbit/ticker/route.ts` — 커밋 `2551b96`. `curl "localhost:3000/api/upbit/ticker?markets=KRW-BTC"` → 실시세 JSON, 파라미터 없으면 400. **D1 DoD 항목 충족**

**결정**: 외부 응답 타입을 **1겹만** 만든다(`UpbitTicker` = 업비트가 준 snake_case 그대로). camelCase 우리 모델(2겹)과 변환 함수는 소비자가 생기는 홈 연결 단계에서 — "재사용이 실제로 생길 때" 원칙.
**결정**: public API는 `shared/api/upbit/index.ts` 하나. `shared/api/index.ts`에서 전부 모으면 나중에 db·clerk가 한 문으로 나와 `db`만 쓰려던 파일이 upbit까지 끌고 온다.

**개념 정리(사용자 요청으로 기록)**: `shared/api/upbit/client.ts`(함수)와 `app/api/upbit/*/route.ts`(URL)의 차이를 정리했다 — route는 client를 감싼 껍데기이고, **부르는 사람이 같은 기계 안이면 함수, 다른 기계면 HTTP**다. 브라우저가 `import`를 못 하는 건 그 파일이 유저 컴퓨터에 없기 때문. 함께 바로잡은 것: 이 프로젝트는 **모노리스**가 맞고, React는 프레임워크가 아니라 라이브러리이며, **Tailwind는 런타임에 호출되지 않고 빌드 때 CSS를 한 번 만들고 끝난다**(동적 클래스 조립 금지의 근거). 상세는 [[공부/JS/Next.js 서버와 캐싱|Next.js 서버와 캐싱]].

**남은 D1**: `candles`/`markets` route handler 2개 → 홈 실시세 연결(market-board 5종, watchlist BTC) → 필드 매핑 검증(`signed_change_rate` × 100). 스파크라인은 D6 이월.

**일정**: 2일 지연(D1을 8/15~18에 걸쳐 진행). 계획서의 "학습 모드 지연 → D12 버퍼 소진 전제"대로 **계획 유지, 버퍼 흡수**로 결정(2026-08-18). 3일 이상 밀리면 재배치.

**결정 (2026-08-20)**: 코인 한글이름·심볼·배지색 하드코딩을 버리고 업비트 `/market/all`에서 받는다. 직후 XRP가 "리플"이 아닌 **"엑스알피(리플)"**로 표시됨 — 하드코딩했으면 틀린 채 방치됐을 것. 배지색은 제거(디자인 변경), 심볼·쌍표기는 마켓 코드에서 파생(`symbolOf`/`pairOf`). 우리가 들고 있는 건 "어떤 코인을 보여줄지" 목록뿐.

**결정**: `getCoins`를 `entities/coin/api`로 내림. 두 위젯이 같은 로직을 쓰게 됐는데 FSD 규칙 2번(같은 계층 슬라이스끼리 import 금지) 때문. 첫 위젯 때 미리 내리지 않은 것은 의도 — 재사용이 실제로 생긴 시점에 내렸다.

**필드 매핑 검증**: 화면 5종을 업비트 원본과 대조. `trade_price`→현재가, `signed_change_rate`×100→등락률, `acc_trade_price_24h`→거래대금 전부 일치. 미세한 차이는 `revalidate: 5` 캐시가 동작한다는 증거.

**남긴 판단**: 도지코인 `99.4원` 소수점 표시 / 보합 시 `+0.00%` / `getCoins`가 마켓 831개에서 5개를 `find`(1시간 캐시라 네트워크는 없음).

### 실제 소요 — 계획 6.5h → 4 작업일 (8/15·16·18·19~20, 17일 휴무)

**일정 판단 (2026-08-20)**: 진짜 마감은 2주 계획이 아니라 **2026-12 지원**이고 8/20 기준 약 90 작업일이 남아 D1의 4배 페이스여도 여유가 두 배 이상이다. 따라서 "12일치를 12일에"라는 목표는 버리고 **"12일치를 순서대로"**로 바꾼다. 다만 [[프로젝트/개인/MyCryptoDiary/실시간 데이터 UI 계획 2026-08-14|실시간 데이터 UI 계획]]의 WebSocket 착수(원래 08-18)가 D12 이후로 밀리는 구조 — **이력서 1번 항목이 가장 늦게 만들어진다**는 점은 D12 전에 재검토할 것.

### PR #4 리뷰 결과 (2026-08-20)

Standards/Spec 두 축. **Spec: D1 요구사항 전부 충족** — DoD 3개 통과, 캐시 주기 정확, 필드 매핑 정확(`signed_change_rate`가 `formatPercent`에서 정확히 1회만 ×100).

**고칠 것 (A: 크래시·장애)**
1. 업비트 실패 시 위젯 단위 폴백 — 현재는 429 하나에 홈 렌더 전체가 500
2. `WatchlistCard`의 `const [coin] = ...` 뒤 가드 없음 (`LiveMarketCard`엔 있어 불일치)
3. candles `count` 무검증 — `?count=abc` → `NaN`이 업비트로 전송
4. 에러 메시지: ticker가 `'market is required'`인데 실제 파라미터는 `markets`, candles는 끝 공백 오타, 접두사 규칙 제각각

**고칠 것 (B: 이름·중복)**
5. **`Coin.tradeVolume24h` → `tradeValue24h`** — 담긴 값은 `acc_trade_price_24h`(거래**대금**)인데 Volume은 수량의 이름. 업비트에 `acc_trade_volume_24h`가 따로 있어 나중에 충돌한다
6. 등락 색 판정이 두 위젯에 다른 형태로 복제 → `entities/coin/model`에 `trendOf()`
7. `getCoins`의 순차 `await` → `Promise.all`
8. `symbolOf`·`toCoin` public API 노출 축소 (미사용/내부용)

**연기 (근거 있음)**: `Map` 인덱싱·라우트 로직 분리는 D6 폴링 때 / `format.ts` 엣지 케이스(`NaN`, `-0.00%`)는 **D5 테스트로 고정** / `Coin.price`가 float인 것은 표시 전용이라 지금은 허용하되 **D4에서 체결가로 넘기면 기술 스택 표의 "float 절대 금지" 위반**이 되므로 경계를 명시할 것.

**자체 지적**: 커밋 `4055068`(Prettier 재포맷)이 D1 범위 밖이었다. 작업 기록의 「남긴 것」에 "이번 커밋에 안 섞음"이라 적어둔 항목을 섞었다.

## 확립된 일일 워크플로

1. **수집**: 연합뉴스 스포츠 RSS(`https://www.yna.co.kr/rss/sports.xml`)에서 `[프로야구 ○○전적]`(구장별 박스스코어)과 `…(종합)` 기사를 찾는다. 전 경기 종료 신호는 `[프로야구 중간순위] N일` 기사 등장이다. RSS는 약 2~3일치만 보관하므로 놓친 날은 `yna.co.kr/sports/baseball/<페이지>` 목록에서 기사 ID를 스캔한다. `src/daily.py`의 자동 초안은 기사 본문이 그대로 들어가 매체명이 노출되므로 실발행에는 쓰지 않고, 종합 기사를 직접 읽고 수기 편집한다.
2. **편집**: `output/<발행일>/draft.json`에 roundup 1건(4장: cover → scoreboard → stat_grid(또는 scoreboard 2장) → takeaway)을 작성한다. 헤드라인은 그날의 서사 하나로 잡는다(예: "8연승과 8연패", "원정 4전 4승"). 렌더러가 글자 단위로 줄바꿈하므로 제목의 어절 분리는 `\n` 수동 줄바꿈으로 막는다.
3. **발행**: `render_posts.py --draft` → PNG 육안 검수 → `approve_posts.py` → `publish_articles.py --dry-run` → `--platform instagram`. 같은 날짜 폴더에 발행 완료 게시물이 있어도 `publish_articles.json` 기록 기준으로 자동 스킵되므로 하루 2건 발행이 안전하다(07-23, 07-28에 검증).
4. **캡션 규칙**: 승자 우선 점수 나열 + 한 줄 요약 + 원문 링크는 KBO 공식 스코어보드(매체명 비노출 규칙 준수) + 해시태그.

## 부수 산출물: AI 릴스 프로토타입 (2026-07-23)

카드 PNG 슬라이드쇼가 아닌 "AI 나레이션 + 키네틱 타이포" 방식의 릴스를 로컬 파이프라인만으로 시제작했다(`output/2026-07-23/kbo-20260722-reel.mp4`, 33.7초 1080×1920).

- 구성: macOS `say`(Yuna, -r 190)로 장면별 나레이션 생성 → wave 길이에 장면 길이 동기화 → Pillow로 프레임 렌더(디자인 시스템 색·폰트 재사용) → ffmpeg 인코딩.
- 인스타 발행은 미연동. 연동하려면 Graph API `media_type=REELS` + resumable upload(외부 영상 호스팅 불필요)로 게시기 확장이 필요하다.
- 제작 스크립트는 세션 스크래치에 있었으므로 재사용하려면 재작성이 필요하다(구조는 위 요약 참조).

## 환경 제약 (2026-07-22 기준)

시스템 `python3`(3.9)에는 Pillow가 없어 파이프라인이 실패한다. Homebrew Python 3.14.6으로 프로젝트 루트에 `.venv`를 만들어 사용한다(`.venv/bin/python src/...`). 렌더링의 raqm 텍스트 기능은 시스템 fribidi를 동적 로드하므로 `brew install fribidi`가 필요하다(설치 완료). ffmpeg도 Homebrew로 설치했다(릴스용).

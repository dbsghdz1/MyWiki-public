# 릴스 발행 시작 2026-09-23

홍: "인스타 계정 운영하는 게 있는데 야구 관련 여기서 릴스를 올리고 싶어." → 같은 날 첫 릴스를 발행하고, 매일 밤 그날 경기에서 한 장면을 골라 자동으로 올리는 파이프라인을 Mac에 설치했다. [[프로젝트/개인/인스타카드뉴스/README|인스타카드뉴스]] 현재 카드의 «AI 릴스 발행 연동 동결»은 이 요청으로 풀렸다.

## 형식 결정

- **경기 클립 릴스**(야구1열식): 세로 1080×1920, 가운데 중계 클립, 위에 노란 킥커 + 2줄 제목, 아래 스코어·기록 한 줄, 하단 `@yagu.3cut`. 07-23의 «AI 나레이션 + 키네틱 타이포» 프로토타입은 스크립트가 유실됐고, 08-01에 써 둔 `render_short.py`·`publish_reel.py`(미발행)가 이 형식이었다.
- **원천은 티빙스포츠 유튜브의 경기별 하이라이트.** 티빙·KBO 계약(2024~2026)은 40초 미만·비상업 2차 창작을 허용한다 — 렌더 39.8초·발행 40초·계획 36초 세 겹으로 막는다. 캡션 끝에 «영상 출처: TVING KBO 리그 중계 하이라이트 (40초 미만 2차 창작)»를 단다.
- **하루 1건.** 카드뉴스(서버 08:00·23:00)와 겹치지 않게 Mac에서 23:45에 올린다.

> 캡션에 «9회초 1사 만루»라고 썼지만 중계 스코어버그는 **2아웃**(빨간 점 두 개)이다. 기사에는 아웃카운트가 없어서 근거 없이 쓴 숫자였다. Instagram API는 게시된 캡션 수정을 지원하지 않으므로(`POST /{media-id}`는 `comment_enabled`만) **앱에서 «1사»를 «2사»로 손으로 고쳐야 한다.** 이 실수 때문에 자동 파이프라인에 사실 검증 단계를 넣었다(아래 5번).

## 자동 파이프라인

설치 위치는 `(로컬 경로)`(실행본)이고, launchd `com.instacardnews.reel`이 **23:45**와 **06:30**(재시도)에 돈다. 원본 코드는 `(로컬 경로)`이며 고친 뒤 `scripts/install_reel_runtime.sh`를 돌려야 반영된다.

1. `find_highlights.py` — 티빙스포츠 채널에서 그날 경기 하이라이트(4~5편)를 찾는다.
2. `pick_moment.py` — 경기마다 오디오·자동 자막만 받아 «홈런·만루·끝내기…» 키워드와 음량 피크로 후보 구간 2개를 낸다. 후보 구간만 480p로 받아 초 단위 콘택트시트를 만든다.
3. 연합뉴스 그날 기사(종합·전적) 본문을 모은다 — 문안의 사실 근거.
4. `claude -p`(Opus, 읽기 권한은 `output/`만)가 시트·자막·기사를 보고 장면 하나와 킥커·제목·푸터·캡션을 정한다. 약한 날은 건너뛴다.
5. **사실 검증**: 두 번째 `claude -p`가 문안의 주장을 기사와 하나씩 대조한다. 기사에 없거나 다른 주장은 빼거나 고치고, 고친 문안을 다시 검증해 통과하지 못하면 발행하지 않는다.
6. 형식 검사(구간·길이·글자 수, 매체명·URL·문의·광고 문구, 기사 문장 25자 이상 그대로 옮기기) → 1080p 구간 다운로드 → 장면 전환에 끝 맞춤 → 렌더 → litterbox 임시 호스팅 → 발행 → Slack `#10-콘텐츠-인스타` 알림.

**안전장치**:

- 어떤 단계가 실패해도 Slack에 «실패»를 알린다.
- 최근 7일 릴스가 하나라도 Instagram에서 사라지면 권리자 신고로 보고 `output/.reels-paused`를 만들어 자동 발행을 멈춘다. 홍이 파일을 지워야 재개한다.
- 2026-12-31 이후에는 «티빙 방침 재확인 필요»로 보류한다.
- 같은 날 같은 알림은 한 번만 보낸다.

## 검증

- 9/22로 발행 없이 끝까지 세 번 돌렸다. 자동 판단은 세 번 모두 손으로 고른 것과 같은 장면(833~866초)을 골랐다.
- Sonnet 5로 돌린 문안에는 기사와 다른 주장이 셋 있었다(아웃카운트, «2위와 격차를 벌렸다» — 기사는 «3.5게임 유지», #직관). 검증 단계가 셋 다 잡아 고쳤다. 그래서 두 단계 모두 Opus로 정했다(1회 약 0.4달러).
- launchd 환경에서 따로 점검했다: yt-dlp(Node 런타임), 구간 다운로드, Claude 로그인, Hermes Slack 전송 모두 동작한다. 발행된 날짜로 실행하면 «이미 발행됨»으로 멈춘다(exit 0).
- 테스트는 71개가 통과한다(기존 30 + 릴스 41).
- 코드 리뷰 워크플로(리뷰어 5명)가 24건을 냈다. 검증 에이전트는 모델 한도로 실패해서 직접 확인했고, 확인된 것은 모두 고쳤다. 대표적인 것은 영문 제목 `Match` 누락, 구간 파일 재사용 버그, 조사 «와»·기록 잡담 오탐, 제목과 영상 겹침, 실패 시 무알림이다.

## 막혔던 것

- **서버에선 유튜브를 못 받는다**(`Video unavailable`). 그래서 릴스만 Mac에서 돈다.
- **launchd는 `(로컬 경로)`을 못 읽는다**(`/bin/zsh: can't open input file`, exit 127). 옛 Mac 카드 발행 작업(`com.instacardnews.publish`)이 127로 죽어 있던 이유도 이것으로 보인다. 실행본을 `(로컬 경로)`로 옮겨 해결했다.
- **JS 런타임이 없으면 영상 서버가 403을 준다**(`ffmpeg exited with code 8`). yt-dlp에 `--js-runtimes node:<mise shim>`을 준다.
- **Instagram Login 토큰은 resumable 업로드를 거절**한다(400 «video_url is required»). 공개 URL 방식으로 바꿨다.
- Mac `.env` 토큰은 죽어 있었고(code 190) 서버 토큰만 살아 있었다. 서버 값을 복사했다.
- 워터마크가 옛 계정명이어서 카드 렌더러(Mac·서버)도 `@yagu.3cut`로 고쳤다.

## 남은 위험 (판단은 홍)

- **Instagram 원본성 정책.** 방송 화면에 자막만 얹은 릴스는 «취합 콘텐츠»로 분류돼 비팔로워 추천에서 빠질 수 있다. 09-30 판정에서 조회수로 확인한다.
- **Mac 의존.** 배터리일 때 1분 뒤 잠드는 설정이다. launchd는 놓친 실행을 깨어날 때 한 번 돌려주고, 18시 전이면 전날 경기를 잡는다. 그래도 Mac이 꺼져 있던 날은 빠진다.
- 원본 레포는 커밋하지 않았다. 레포에 원래 있던 미커밋 변경과 섞여 있어서 그대로 두었다.
